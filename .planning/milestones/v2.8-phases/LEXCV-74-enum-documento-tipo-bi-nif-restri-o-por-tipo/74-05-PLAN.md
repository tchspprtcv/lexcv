Close the sole remaining Phase 74 gap (74-VERIFICATION.md, Truth #10 / CLI-24): the backend
`ResourceController.updateCliente` still rejects a legacy `documento_tipo` value even when the
client resends it UNCHANGED, contradicting 74-CONTEXT.md line 26 ("pre-existing invalid
combinations are tolerated até serem editados; só submissões novas são validadas"). The frontend
half was already closed by 74-04; this plan closes the backend half only.

legado") true end-to-end, so a save of an untouched legacy value returns HTTP 200.
Output: A diff-against-stored-entity exemption in `updateCliente` that skips the per-tipo
membership check ONLY when the incoming `documentoTipo` and `documentoNumero` are byte-for-byte
identical to what is already persisted; genuinely new/changed submissions stay fully validated.
