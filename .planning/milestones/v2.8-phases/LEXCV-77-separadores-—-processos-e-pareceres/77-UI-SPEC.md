## Scope Note

This phase introduces **zero new visual patterns**. It fills in 2 of the 5 "Em breve" placeholder tabs added in Phase 76 (`web/src/app/(dashboard)/clientes/[id]/page.tsx`, tab keys `"processos"` and `"pareceres"`, currently rendering `<PlaceholderEmBreve />` at lines 1055–1058) with compact `Table` listings that replicate — verbatim in classNames and badge-color mapping — the tables already shipped in `web/src/app/(dashboard)/processos/page.tsx` and `web/src/app/(dashboard)/pareceres/page.tsx`. Per 77-CONTEXT.md: no new CTAs, no inline preview, no edit/create — row-click navigates to the existing detail routes (`/processos/[id]`, `/pareceres/[id]`).

Both source list pages were read in full and are the literal visual source of truth for this spec:
- `web/src/app/(dashboard)/processos/page.tsx` (412 lines) — `Table`/`TableHeader`/`TableBody`/`TableRow`/`TableCell` markup at lines 310–391; estado badge variant mapping at lines 323–335 (`ATIVO`→`green`, `SUSPENSO`→`amber`, `TRIAGEM`→`purple`, `CONCLUIDO`/`ENCERRADO`→`gray`, else→`secondary`); loading/error/empty states at lines 295–308.
- `web/src/app/(dashboard)/pareceres/page.tsx` (487 lines) — `statusVariant()` helper at lines 30–40 (`PENDENTE`→`gray`, `EM_ELABORACAO`→`blue`, `EM_REVISAO`→`amber`, `CONCLUIDO`→`green`, else→`secondary`); desktop `Table` markup at lines 437–479; loading/error/empty states at lines 376–404.
- `web/src/hooks/use-processos.ts` — `useProcessos(filters: ProcessosListFilters)` accepts `cliente_id` (snake_case); `enabled` is computed **internally** as `typeof window !== "undefined"` — the hook does **not** accept an external `enabled` override today.
- `web/src/hooks/use-pareceres.ts` — `usePareceres(filters: ParecerSolicitacoesListFilters)` accepts `clienteId` (camelCase); same internal-only `enabled` computation, no override param today.
- `web/src/app/(dashboard)/clientes/[id]/page.tsx` (post-Phase 76) — tab state machine (`TabKey`, `useState<TabKey>`), `PlaceholderEmBreve()` component (lines 1091–1102) to be replaced at the two call sites for `"processos"`/`"pareceres"`.

**No new component library additions, no new color/typography/spacing tokens, no new copy patterns beyond two short empty-state sentences.** This spec stays narrow and points at existing code as the literal visual source of truth rather than re-describing it, following the established Phase 74/75/76 precedent.

**Design System detected:** No `components.json` in `web/` — no shadcn CLI (unchanged since Phase 74/75/76). ## Typography

No new typography introduced. Reuses the exact declared set from `/processos` and `/pareceres` table markup — verified directly against both source files.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Table header (`TableHead`) | `text-[10px]` | `font-bold` (700) | existing `Table` component default |
| Primary cell value (Número/Título, links to detail) | `text-sm` (existing `Table`/`TableCell` default) | `font-bold` (700) — e.g. `font-bold text-slate-900 dark:text-white` on the processo número link | existing default |
| Secondary cell value (Área Jurídica plain text, Advogado Responsável) | `text-sm` | `font-medium` (500) — e.g. `text-slate-500 dark:text-slate-400 font-medium` | existing default |
| Sub-line under primary value (e.g. "Entrada: {data}") | `text-[11px]` | `font-medium` (500), `uppercase tracking-wider` for the processos precedent | existing default |
| Empty-state / loading / error text | `text-sm` | no weight class declared — inherits base/unstyled weight (existing `p-6 text-sm text-slate-500` / `text-red-600` pattern) | existing default |

Declared weights for this phase: **2** — `font-bold` (700, table headers + primary cell links) and `font-medium` (500, secondary/muted cell text). Matches the weight budget already established by the source pages; no third weight introduced. Note: this differs from Phase 75/76's declared pair (`font-semibold`/`font-medium`) because this phase reuses a **different existing surface** (the `/processos` and `/pareceres` table idiom, which uses `font-bold` for emphasis, not `font-semibold`) — both pairs are correct for their respective source pattern and this spec does not reconcile them, per the "replicate an established pattern, don't invent" directive in the task note.

## Interaction Contract (the actual new design surface)

This is the real scope of Phase 77's UI work. The checker/executor should validate against this section more than the boilerplate sections above.

### 1. Processos tab content

Replaces `tab === "processos" ? <PlaceholderEmBreve /> : ...` (currently line 1055–1056 of `clientes/[id]/page.tsx`) with:

- Data source: `useProcessos({ cliente_id: id })` — note the snake_case filter key (hook-level inconsistency vs. `usePareceres`, pre-existing, not in scope to fix per CONTEXT.md).
- **Lazy fetch requirement (CONTEXT.md):** the query must only run when the Processos tab is active — `enabled: tab === "processos"`. **Integration gap found in this research:** `useProcessos` in `web/src/hooks/use-processos.ts` computes `enabled` internally (`const enabled = typeof window !== "undefined"`) and does **not** currently accept an external `enabled` override parameter. The executor must either (a) extend `useProcessos`'s filters/options to accept and AND-combine an external `enabled` flag, or (b) gate the hook call itself so it is only invoked with real intent when the tab is active (e.g., only rendering/calling the hook inside the `tab === "processos"` branch is NOT sufficient by itself for lazy-fetch semantics if React still mounts the hook on every render of a component that's always in the tree — confirm the hook is called from a small sub-component that unmounts when the tab is inactive, OR add the `enabled` param). This is a required code-level decision for the plan/executor, not optional.
- Columns (exactly 4, per CONTEXT.md): **Número** · **Estado** (badge) · **Área Jurídica** (plain text) · **Data de Início**.
- No Tribunal column, no `legal_hold` indicator, no prazo-risco badge, no Ações column with `MoreVertical` — compact means fewer columns and no row-level menu (row click IS the action).
- Row click: entire row (or at minimum the Número cell) is a `Link` to `/processos/${encodeURIComponent(p.id)}` — reuse the exact link styling from `/processos/page.tsx` line 340–345.
- Sort: whatever `useProcessos` returns by default (`sortBy: "created_at", sortDir: "desc"` matches the hook's own default when no explicit sort filter is passed) — most-recent-first, per CONTEXT.md's Claude's Discretion note.
- States: loading → `A carregar...` (`p-6 text-sm text-slate-500`); error → `text-red-600` message per Copywriting Contract; empty → `Nenhum processo associado a este cliente.` (`p-6 text-sm text-slate-500`).
- Wrap the whole tab body in a bare `Table` (no page header, no filter bar, no KPI cards, no pagination footer) — none of the surrounding chrome from `/processos/page.tsx` (search bar, stat cards, pagination) is replicated here, only the `Table`/`TableHeader`/`TableBody`/`TableRow`/`TableCell` block itself, optionally wrapped in a single `Card`/`CardContent className="p-0"` for consistent border/background, matching how the table sits inside a `Card` in the source page.

### 2. Pareceres tab content

Replaces `tab === "pareceres" ? <PlaceholderEmBreve /> : ...` (currently line 1057–1058) with:

- Data source: `usePareceres({ clienteId: id })` — camelCase filter key (as the hook already expects).
- **Lazy fetch requirement (CONTEXT.md):** `enabled: tab === "pareceres"`. Same integration gap as above applies to `usePareceres` in `web/src/hooks/use-pareceres.ts` — it also computes `enabled` internally without an override param. Same two resolution options apply.
- Columns (exactly 4, per CONTEXT.md): **Número/Título** · **Estado** (badge) · **Advogado Responsável** · **Data de Criação**.
  - Note: `ParecerSolicitacao` (see `web/src/types/pareceres.ts`) has no `numero`/`titulo` field today — only `descricao`, `clienteId`, `advogadoId`, `prioridade`, `status`, `prazo`, `createdAt`. The existing `/pareceres/page.tsx` list uses **Cliente** as its primary link label (since that page lists across all clients); inside a single client's ficha, Cliente is redundant. The executor should use `descricao` (truncated if needed) as the "Número/Título" column's display value, since no dedicated numero/titulo field exists — this is a display-mapping decision, not a data-model change (out of scope, no backend touched this phase).
  - `Advogado Responsável` requires resolving `advogadoId` to a name — the existing `/pareceres/page.tsx` already does this via `useAdminUsers()` + `.filter(u => u.roles?.includes("ADVOGADO"))` + a lookup map (lines 78–86); reuse the same resolution pattern, do not invent a new one.
- No Prioridade column, no Prazo column, no Ações column — compact means fewer columns, replaced by Advogado Responsável per CONTEXT.md.
- Row click: entire primary cell is a `Link` to `/pareceres/${encodeURIComponent(s.id)}`, styled exactly like `/pareceres/page.tsx` lines 458–463 (`hover:text-blue-600 dark:hover:text-blue-400`).
- Sort: whatever `usePareceres` returns by default (no explicit sort param exists on this hook — it returns backend default order) — matches CONTEXT.md's "follow what the hooks already return by default" discretion grant.
- States: loading → `A carregar...`; error → `text-red-600` message; empty → `Nenhum parecer associado a este cliente.`.
- Same bare-`Table`-in-`Card` wrapping as Processos — no search bar, no advanced-pesquisa panel, no filter chips replicated from `/pareceres/page.tsx`.

### 3. No mobile card-view duplication required

Both source pages have a `md:hidden` stacked-card mobile view (Pareceres) or none at all (Processos, which has no mobile branch and just lets the table scroll). Per the "compact" framing and lack of any CONTEXT.md instruction to build a mobile card view, the executor may let the `Table` scroll horizontally on narrow viewports (existing app-wide table-responsiveness convention from Phase 54) rather than building a bespoke `md:hidden` card list for these two tabs — this keeps the phase narrow and consistent with "reuse, don't invent."
