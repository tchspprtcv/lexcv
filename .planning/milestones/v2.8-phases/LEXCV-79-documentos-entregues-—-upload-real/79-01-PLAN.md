<objective>
Add a new tenant-scoped REST endpoint `GET /clientes/{id}/documentos` that lists all `Documento` records associated with a given cliente. This is the only net-new backend work in Phase 79 and is the data source the frontend "Documentos Entregues" tab (Plan 02) will consume.

Purpose: The generic `GET /documentos` endpoint (`listDocumentos()`) ignores the `cliente_id`/`processo_id` query params server-side (it only does `findByTenantId`), so a cliente-scoped listing route is required for the tab to render only this client's documents.
Output: One new controller method `listClienteDocumentos`, mirroring the existing `listProcessoDocumentos` exactly, swapping Processo→Cliente. No repository, DTO, or config changes.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-79-01 | Information Disclosure | `listClienteDocumentos` | mitigate | Tenant-scope enforced twice: (a) `cliente.getTenantId().equals(getTenantId())` guard returns 404 before any document is read; (b) `findByTenantIdAndClienteId(getTenantId(), id)` filters the document query by the caller's tenant. A cross-tenant cliente id yields 404, never a foreign document list. This mirrors `listProcessoDocumentos` exactly. |
| T-79-02 | Elevation of Privilege | `listClienteDocumentos` | mitigate | `@PreAuthorize("hasAuthority('documentos:view')")` gates access; a caller without the `documentos:view` scope is rejected by method security before the method body runs. |
| T-79-03 | Spoofing / Repudiation | endpoint auth | accept | Auth is JWT-cookie based via `JwtAuthenticationFilter` (existing, unchanged); `getTenantId()` reads the verified `UserPrincipal`. No new auth surface introduced by this plan. |
