<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → API (upload/list/delete) | The tab issues authenticated requests to `/documentos/upload`, `/clientes/{id}/documentos`, `/documentos/{id}` DELETE, `/documentos/{id}/download`. All are cookie-authenticated (same-origin via Next rewrite) and already backend-gated. |
| UI RBAC vs backend RBAC | The frontend gates the Adicionar/delete affordances on `documentos:edit` and the tab view on `documentos:view`; the backend independently enforces the same scopes via `@PreAuthorize`. Both layers must agree. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-79-04 | Elevation of Privilege | tab affordance gating | mitigate | Upload/delete controls gated on `editable && permissions.can.edit("documentos")`; tab view gated on `permissions.can.view("documentos")` → `AccessDeniedState`. Backend `/documentos/upload`, `/documentos/{id}` DELETE, `/documentos/{id}/download`, and the new `/clientes/{id}/documentos` already enforce `documentos:edit`/`documentos:view` via `@PreAuthorize` — the UI gate is defense-in-depth, not the sole control. Deliberately `documentos:*`, not `clientes:*`, so the two layers agree (CONTEXT.md). |
| T-79-05 | Information Disclosure | `useDocumentos` cliente-scoped fetch | mitigate | The repointed queryFn calls the tenant-scoped `GET /clientes/{id}/documentos` (Plan 01), which returns 404 for cross-tenant cliente ids — the tab can never render another tenant's documents. |
| T-79-06 | Tampering (file upload) | `/documentos/upload` via FileDropZone | accept | Upload reuses the existing generic `/documentos/upload` endpoint and its existing server-side handling unchanged; the `accept` allowlist is a UX hint only (not a security control). No new upload surface is introduced by this plan; content-type/scanning hardening on the shared endpoint is a pre-existing, out-of-scope concern tracked elsewhere. |
| T-79-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages are installed in this phase — all hooks, `FileDropZone`, and UI primitives already exist. No package legitimacy checkpoint required. |
</threat_model>
