Create docker-compose.yml at the repository root with these four services:

SERVICE: postgres
- image: postgres:16-alpine
- container_name: lexcv_postgres
- environment (from compose env vars):
  POSTGRES_DB: ${POSTGRES_DB}
  POSTGRES_USER: ${POSTGRES_USER}
  POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
- volumes: lexcv_pgdata:/var/lib/postgresql/data
- healthcheck:
    test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
    interval: 10s
    timeout: 5s
    retries: 5
- networks: [lexcv_net]

SERVICE: backend
- build: context: ./backend, dockerfile: Dockerfile
- container_name: lexcv_backend
- depends_on:
    postgres:
      condition: service_healthy
- environment (pass all required backend env vars from compose .env):
  SERVER_PORT: 8080
  DB_HOST: postgres
  DB_PORT: 5432
  DB_NAME: ${POSTGRES_DB}
  DB_USER: ${POSTGRES_USER}
  DB_PASSWORD: ${POSTGRES_PASSWORD}
  JWT_SECRET: ${JWT_SECRET}
  JWT_ACCESS_EXPIRATION_MS: ${JWT_ACCESS_EXPIRATION_MS}
  JWT_REFRESH_EXPIRATION_MS: ${JWT_REFRESH_EXPIRATION_MS}
  CORS_ALLOWED_ORIGINS: ${CORS_ALLOWED_ORIGINS}
  SEED_ENABLED: ${SEED_ENABLED:-false}
- volumes: lexcv_uploads:/app/uploads
- networks: [lexcv_net]
- Note: backend is NOT exposed on a host port — Caddy proxies to it internally

SERVICE: frontend
- build: context: ./web, dockerfile: Dockerfile
- container_name: lexcv_frontend
- depends_on: [backend]
- environment:
  BACKEND_API_ORIGIN: http://backend:8080
  NEXT_PUBLIC_API_BASE_PATH: /api/v1
- networks: [lexcv_net]
- Note: frontend is NOT exposed on a host port — Caddy proxies to it internally

SERVICE: caddy
- image: caddy:2-alpine
- container_name: lexcv_caddy
- ports:
  - "80:80"
  - "443:443"
- volumes:
  - ./Caddyfile:/etc/caddy/Caddyfile:ro
  - caddy_data:/data
  - caddy_config:/config
- depends_on: [frontend, backend]
- networks: [lexcv_net]

Top-level volumes declaration:
  lexcv_pgdata:
  lexcv_uploads:
  caddy_data:
  caddy_config:

Top-level networks:
  lexcv_net:
    driver: bridge

Create Caddyfile at the repository root:

  :80 {
    handle /api/* {
      reverse_proxy backend:8080
    }
    handle {
      reverse_proxy frontend:3000
    }
  }

Create .env.example at the repository root documenting all variables compose needs:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Caddy | Only ports 80/443 exposed; backend and frontend have no direct host port exposure |
| Caddy → backend/frontend | Internal Docker network only; services not reachable from host |
| .env file → container env | Secrets live in .env on host; must not be committed to git |
| postgres service → data volume | Named volume; no bind mount to avoid host permission issues |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-04 | Information Disclosure | .env file at repo root | mitigate | .env added to .gitignore; only .env.example (no real values) committed |
| T-37-05 | Spoofing | Caddy routing | accept | Internal bridge network; backend/frontend not reachable without going through Caddy |
| T-37-06 | Denial of Service | backend/frontend container resource exhaustion | mitigate | docker-compose.prod.yml sets deploy.resources.limits (cpu + memory) |
| T-37-07 | Information Disclosure | Postgres port exposed to host | mitigate | postgres service has no ports: mapping in compose; only reachable from lexcv_net |
| T-37-08 | Tampering | Named volume data integrity | accept | Named volumes are managed by Docker daemon; no bind mount minimizes host path permission issues |
| T-37-SC | Tampering | caddy:2-alpine / postgres:16-alpine base images | accept | Official images; pinned to major.minor tags; reviewed before first use |
</threat_model>
