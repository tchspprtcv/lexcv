    **docker-compose.prod.yml** — add a volumes override to the caddy service so Caddyfile.prod is mounted instead of Caddyfile. The updated caddy block must be:

    ```yaml
    caddy:
      restart: unless-stopped
      volumes:
        - ./Caddyfile.prod:/etc/caddy/Caddyfile:ro
        - caddy_data:/data
        - caddy_config:/config
    ```

    caddy_data and caddy_config are already declared as named volumes in docker-compose.yml — do not redeclare them in docker-compose.prod.yml.

    Create DEPLOYMENT.md at repo root. The document is a precise operational runbook for deploying to a fresh Ubuntu/Debian VPS. Structure:

    **## Prerequisites**
    - VPS with Ubuntu 22.04+ or Debian 12+
    - Docker Engine 24+ and Docker Compose v2 installed (`apt install docker.io docker-compose-plugin`)
    - A domain name with an A record pointing to the VPS public IP (DNS must propagate before starting Caddy)

    **## Firewall**
    Open the required ports before starting the stack. Caddy's ACME HTTP-01 challenge requires port 80 to be reachable from the internet.
    ```
    ufw allow 22/tcp   # SSH
    ufw allow 80/tcp   # ACME challenge + HTTP redirect
    ufw allow 443/tcp  # HTTPS
    ufw enable
    ```

    **## Deploy Steps**
    1. Clone the repository on the VPS:
       `git clone https://github.com/your-org/lexcv.git && cd lexcv`
    2. Copy env example and fill in secrets:
       `cp .env.example .env`
       Edit `.env` — required changes:
       - `DOMAIN_NAME=your-actual-domain.com`
       - `POSTGRES_PASSWORD=<strong random password>`
       - `JWT_SECRET=<base64-encoded random secret, min 32 bytes>`
       - `CORS_ALLOWED_ORIGINS=https://your-actual-domain.com`
       - `SEED_ENABLED=true` (only on first run to seed admin user; set false after)
    3. Start the stack:
       `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d`
    4. Check logs:
       `docker compose logs -f caddy`
       Caddy will log certificate provisioning. First startup can take 30-60 seconds for Let's Encrypt.

    **## Verify**
    ```
    curl -I https://your-actual-domain.com/api/v1/setup/status
    ```
    Expected: HTTP 200 with JSON body.

    **## Image Registry (CI/CD)**
    Set `REGISTRY` and `IMAGE_TAG` in `.env` to pull pre-built images from GitHub Container Registry instead of building on the VPS. When both are set, the prod override uses pre-built images (`backend.image` and `frontend.image`).

    **## Updates**
    ```
    git pull
    docker compose -f docker-compose.yml -f docker-compose.prod.yml pull
    docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
    ```

    **## Certificate Renewal**
    Caddy renews Let's Encrypt certificates automatically. No cron job needed. Certificates are stored in the `caddy_data` Docker volume — do not delete it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Caddy (443/80) | Public traffic enters here; untrusted by definition |
| Caddy → backend:8080 | Internal Docker network; trusted after Caddy terminates TLS |
| Caddy → frontend:3000 | Internal Docker network; trusted |
| Operator → VPS shell | Operator sets env vars including secrets; must use secure channel (SSH) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-01 | Spoofing | Let's Encrypt ACME HTTP-01 challenge | mitigate | Port 80 must be open only during ACME; Caddy handles challenge automatically and securely without exposing app on HTTP |
| T-38-02 | Tampering | Caddyfile.prod mounted read-only | mitigate | `:ro` flag on bind mount in docker-compose.prod.yml prevents container from writing to Caddyfile.prod |
| T-38-03 | Information Disclosure | .env file with JWT_SECRET and DB password on VPS | mitigate | DEPLOYMENT.md instructs operator to set strong unique secrets; .env must not be committed (already in .gitignore) |
| T-38-04 | Denial of Service | Ports 80/443 exposed | accept | Low-value target for DDoS at this stage; Caddy handles connection limits by default; OS-level rate limiting out of scope |
| T-38-05 | Elevation of Privilege | CORS_ALLOWED_ORIGINS set to wrong value | mitigate | .env.example documents production value as `https://your-actual-domain.com`; DEPLOYMENT.md explicitly calls out updating this value |
| T-38-SC | Tampering | No new npm/pip/cargo installs in this plan | accept | Infrastructure/config only phase; no package manager invocations |
</threat_model>
