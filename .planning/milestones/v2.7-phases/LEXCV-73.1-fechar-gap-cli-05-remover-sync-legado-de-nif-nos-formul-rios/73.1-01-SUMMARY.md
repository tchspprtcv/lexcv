# Phase 73.1 Plan 01: Fechar gap CLI-05 (remover sync legado de NIF) Summary

**Removed the silent NIF-overwrite bug in both cliente forms and the backend controller, and added Jakarta Bean Validation (@NotBlank + @Pattern ^\d{9}$) with @Valid enforcement so NIF validity is a server-side guarantee, not a browser convention.**

## Performance

- **Duration:** 3 min (build/typecheck gates included)
- **Started:** 2026-07-02T10:05:00-01:00
- **Completed:** 2026-07-02T10:08:00-01:00
- **Tasks:** 3 (2 code tasks + 1 verification-only task)
- **Files modified:** 4

## Accomplishments
- Deleted the post-payload NIF-sync block (`Sincronizar NIF se tipo for NIF`) from both `novo/page.tsx` and `editar/page.tsx` — the dedicated Zod-validated `nif` field is now the sole source of `payload.nif` in both forms
- Added `@NotBlank` + `@Pattern(regexp = "^\\d{9}$")` to `Cliente.nif`, and `@Valid` to both `createCliente` and `updateCliente` `@RequestBody Cliente` parameters
- Removed the server-side NIF-sync twin in `createCliente` (`cliente.setNif(cliente.getDocumentoNumero())`) and rewrote `updateCliente`'s NIF assignment to be unconditional (`cliente.setNif(payload.getNif())`) instead of conditionally re-deriving from `documentoNumero`
- Verified both build gates green: `mvn -DskipTests clean package` = BUILD SUCCESS; `pnpm exec tsc --noEmit` = 0 errors
