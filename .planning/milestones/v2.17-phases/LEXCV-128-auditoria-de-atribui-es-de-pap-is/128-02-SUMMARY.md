# Phase 128 Plan 02: AuditoriaRbacService and RecusaTransacional Summary

## Accomplishments

- `AuditoriaRbacService` (`@Service`, `@RequiredArgsConstructor`, `@Slf4j`): five `registar*` write methods, each `@Transactional(propagation = Propagation.MANDATORY)`, plus `@Transactional(readOnly = true) listar`. Every write builds `detalhe` via a `LinkedHashMap` helper that omits null values and empty collections before Jackson serialization; a `JsonProcessingException` during serialization is rethrown as an unchecked `IllegalStateException` so the caller's MANDATORY transaction rolls back the change together with its missing event.
- `registarAtribuicoes` computes the assignment diff by `TenantRole.getId()` (never object identity — proven by a same-id/different-instance test), producing `papel_atribuir` for roles only in `depois` and `papel_retirar` for roles only in `antes`, both sorted by `(nome, id)` for deterministic output; zero saves when `antes` and `depois` resolve to the same id set.
- Actor privacy (revised Decision 2): every `detalhe` write reads only `UserPrincipal.getUserId()`/`getNome()` (never the email getter) and `User.getNome()` for the target — proven by a dedicated test that exercises all five write methods with a distinctive email fixture and asserts its absence from every captured `detalhe` string.
- `listar` never resolves names from `UserRepository` — names come only from the `detalhe` snapshot. Null or malformed `detalhe` JSON (`"{nao json"`) is caught and logged as a WARN carrying only the row id, returning a DTO with the structural fields (`id`/`timestamp`/`acao`/`categoria`/`alvoId`) populated and detail fields null, never throwing (T-128-12).
- `AuditoriaRbacEntradaDto` (`@Data @Builder @NoArgsConstructor @AllArgsConstructor`) with the exact field set from the plan's interfaces block; `categoria` is resolved server-side (`"papel"` for `papel_escritorio`, `"atribuicao"` for `atribuicao_papel`) so the frontend never parses `entidade_tipo`.
- `RecusaTransacional.recusar(ResponseEntity)` marks `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()`, catching `NoTransactionException` for direct (unproxied) calls, then returns the same `ResponseEntity` instance. Proven with a real `TransactionInterceptor` wired via `ProxyFactory` over a mocked `PlatformTransactionManager`: the `TransactionStatus` instance passed to `commit()` has `isRollbackOnly() == true` when `recusar()` ran inside the proxied method, and `false` on a normal return — the mechanism is proven honoured, not merely invoked.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test service field constructed before Mockito injected its `@Mock` dependency**
- **Found during:** Task 1, first test run
- **Issue:** `AuditoriaRbacServiceTest` originally built `service = new AuditoriaRbacService(auditLogRepository, objectMapper)` as an instance-field initializer. Field initializers run during JUnit's construction of the test instance, which happens *before* `MockitoExtension` injects `@Mock` fields (`postProcessTestInstance`) — so `auditLogRepository` was still `null` at that point, and every write method threw `NullPointerException` at `auditLogRepository.save(...)`.
- **Fix:** Moved service construction into a `@BeforeEach` method, which runs after mock injection.
- **Files modified:** `backend/src/test/java/com/lexcv/services/AuditoriaRbacServiceTest.java`
- **Commit:** `9b81ebe9` (fixed before this commit was made; no separate commit needed)

**2. [Rule 1 - Bug] Doc-comment self-tripped its own grep acceptance gate**
- **Found during:** Task 1, acceptance-criteria verification
- **Issue:** The privacy-rule doc-comment above the actor-name helper originally wrote `{@link UserPrincipal#getEmail()}` to document which getter must never be called. The plan's own acceptance criterion (`grep -F "getEmail" ... returns nothing`) is a literal string search over the whole file, so the comment itself made the gate fail — a comment explaining the forbidden call was indistinguishable, to grep, from the forbidden call.
- **Fix:** Reworded the comment to describe the rule without spelling the getter name, and added a note explaining why (see key-decisions).
- **Files modified:** `backend/src/main/java/com/lexcv/services/AuditoriaRbacService.java`
- **Commit:** `9b81ebe9` (fixed before this commit was made; no separate commit needed)
