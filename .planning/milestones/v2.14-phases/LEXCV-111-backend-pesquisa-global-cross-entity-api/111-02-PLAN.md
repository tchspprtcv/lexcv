<objective>
Build the API layer for cross-entity global search: a new dedicated `PesquisaController` at `GET /api/v1/pesquisa?q=<termo>` that resolves the caller's tenant, validates the term, and merges results from the four `pesquisarGlobal` queries (Plan 111-01) into one flat, `tipo`-discriminated `List<ResultadoPesquisaDto>` — querying each entity type ONLY behind its own `:view` scope check. Plus a Mockito RBAC-matrix test proving per-branch gating and the structural absence of any Honorario/financeiro data.

Purpose: This is the orchestration + authorization layer. Satisfies SRCH-01 (cross-entity discriminated results from the caller's tenant) and SRCH-06 (each type gated by its own scope, gate-before-fetch, never Honorario). Depends on 111-01's repository methods existing.

Output: `ResultadoPesquisaDto`, `PesquisaController`, `PesquisaControllerTest`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (browser) → PesquisaController | untrusted `q` query param crosses here — trimmed, min-length-gated, truncated to 200 chars before use |
| JWT/SecurityContext → per-branch authorization | caller's authorities decide which entity types are queried at all; must gate before fetch, never after |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-03 | Information Disclosure (cross-scope / financeiro leak) | PesquisaController per-branch gating + DTO shape | mitigate | **HIGH severity.** Gate-before-fetch: each entity branch runs only inside `if (hasAuthority(auth, "<scope>:view"))`; there is NO Honorario/financeiro branch and `ResultadoPesquisaDto` has no financial field, so financeiro data is structurally unreachable (SRCH-06). `PesquisaControllerTest` role matrix + partial-scope test prove omission-not-hiding and zero Honorario data. Directly answers PITFALLS.md Pitfall 2 |
| T-111-04 | Denial of Service (query fan-out abuse) | `q` param handling | mitigate | `q` trimmed; min length 2 enforced server-side (missing/empty/short → 200 + [], never a broad `ILIKE '%a%'` fan-out); truncated to 200 chars; each branch capped `LIMIT 5` (from 111-01) — every request's cost is bounded regardless of client input |
| T-111-07 | Spoofing (unauthenticated access) | endpoint auth | mitigate | SecurityConfig `.anyRequest().authenticated()` gates the filter chain + method-level `@PreAuthorize("isAuthenticated()")`; JWT httpOnly-cookie auth via the existing JwtAuthenticationFilter — no new auth surface, no bearer tokens |
| T-111-08 | Repudiation (unlogged access) | read-only search | accept | Search performs no state change; consistent with app-wide policy (only mutations are audited via AuditLog, reads are not) — no new repudiation risk introduced |
| T-111-SC | Tampering (supply chain) | package installs | accept (N/A) | Zero new dependencies added in this plan — no npm/pip/cargo/maven install; package-legitimacy gate does not apply |
