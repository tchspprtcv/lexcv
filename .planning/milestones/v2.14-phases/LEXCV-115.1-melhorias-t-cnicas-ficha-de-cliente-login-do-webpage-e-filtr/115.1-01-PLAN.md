<objective>
Área 1 — Permitir criar Processo/Parecer diretamente a partir da ficha de cliente.

Add two contextual "Novo Processo" / "Novo Parecer" buttons to the cliente ficha (Processos and Pareceres tabs), each navigating to the corresponding create form with `?clienteId={id}`. Buttons are gated on `processos:create` / `pareceres:create` — the same scopes already used by the standalone list-page "Novo" CTAs.

Purpose: Closes reported UX gap #1 — today a user must leave the cliente ficha, go to /processos or /pareceres, and re-pick the cliente from scratch to create an artifact for the cliente they are already viewing.
Output: 3 modified files (1 ficha page + 2 create forms), 2 new buttons, 2 locked-field states, 1 shared helper copy string.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next.js client app | Client-side RBAC gating (`canCreate*`) and the `?clienteId=` URL param are attacker-controllable; they are UX affordances, not the security boundary |
| Next.js app → backend API (`POST /api/v1/processos`, `/api/v1/pareceres`) | The real authorization + tenant-isolation boundary; enforced by `@PreAuthorize` + `getTenantId()` scoping (unchanged by this phase) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-115.1-01 | Elevation of Privilege | Client-side `canCreateProcessos`/`canCreatePareceres` button gating | mitigate | Hiding the button is UX/defense-in-depth only. Actual create authorization stays enforced server-side by the existing `@PreAuthorize("hasAuthority('processos:create')")` / `('pareceres:create')` on the create endpoints — this phase touches NO backend code and does not weaken them. A user who forges the URL still hits the server-side gate on submit. |
| T-115.1-02 | Tampering (IDOR / cross-tenant) | `?clienteId=` URL param seeding the locked Cliente field | mitigate | The param only pre-selects an `<option>` that must already exist in the tenant-scoped `useClientes()` list; a forged or cross-tenant id matches no option (field renders empty, submit fails validation). Final authority is the create endpoint, which derives tenant via `getTenantId()` and scopes/validates cliente ownership per-tenant. No backend change here — existing tenant isolation is the control. |
| T-115.1-SC | Tampering (supply chain) | npm/pnpm installs | accept | No packages installed this phase — all primitives (Button/Card/NativeSelect/Link/Plus) already present (UI-SPEC Registry Safety). No `pnpm add` / `shadcn add` task exists. N/A. |

No unmitigated high-severity threats — the IDOR/EoP vectors are both bounded by pre-existing, unchanged server-side controls. No blocking security checkpoint required.
</threat_model>
