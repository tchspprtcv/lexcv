# Phase 115.1 Plan 02: Redirect "Entrar" do Webpage → Login do Web Summary

**New no-throw `getLoginUrl()` helper resolves the webpage's 4 "Entrar" links to `{NEXT_PUBLIC_WEB_APP_URL}/login` when set (fixing the local-dev 404, since `webpage` runs isolated from `web`/Caddy in dev) and to relative `/login` otherwise, keeping production byte-identical — confirmed via inspection of the actual minified build output with the var set.**

## Accomplishments
- `webpage/src/lib/get-login-url.ts` created — single exported `getLoginUrl(): string`, reads `process.env.NEXT_PUBLIC_WEB_APP_URL` inside the function body (never module scope), trims trailing slashes, appends `/login`, and never throws (deliberate divergence from `getBackendOrigin()`, since an unset var is the expected production case).
- All 4 "Entrar" call sites (`site-header.tsx` desktop + mobile sheet, `hero-section.tsx`, `site-footer.tsx`) now import and call `getLoginUrl()` instead of hardcoding `href="/login"` — `git diff` confirms only the import line and the `href` line changed at each site; `Button` variants/classes/text, the mobile `onClick={() => setOpen(false)}`, and the footer's `ArrowRight` icon are all byte-identical to before.
- End-to-end build-time inlining verified two ways: (1) a standalone functional test of the trim/fallback logic against 5 input cases (unset, empty, bare origin, trailing slash, multiple trailing slashes) — all pass; (2) an actual `pnpm build` with `NEXT_PUBLIC_WEB_APP_URL=http://localhost:3000` set, then grepping the resulting minified `.next` chunks, which show the literal inlined value: `function cK(){return"http://localhost:3000".replace(/\/+$/,"")+"/login"}` (identifier minified, logic and value correct) across all 3 component files' bundled output.
