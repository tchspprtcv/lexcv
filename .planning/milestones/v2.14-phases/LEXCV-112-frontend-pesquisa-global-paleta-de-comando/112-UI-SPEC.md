# Phase 112 — UI Design Contract

> Visual and interaction contract for the global search command palette (Ctrl+K/⌘K). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Grounded in:** `112-CONTEXT.md` (16 locked decisions, smart-discuss), `.planning/research/ARCHITECTURE.md` + `SUMMARY.md`, `REQUIREMENTS.md` (SRCH-03/04/05/08/09/10/11), and direct reads of `command.tsx`, `combobox.tsx`, `dashboard-shell.tsx`, `notification-bell.tsx`, `empty.tsx`, `skeleton.tsx`, `badge.tsx`, `button.tsx`, `dialog.tsx`, `globals.css`, `components.json`/`npx shadcn info`. No open design questions remained after upstream artifacts were read — this document contains zero user Q&A; every field below is pre-populated or a clearly-marked researcher default.

**Non-goals for this phase (explicit, to prevent scope creep):**
- Does NOT redesign `command.tsx` / `combobox.tsx` / `empty.tsx` / `skeleton.tsx` — these are reused byte-for-byte.
- Does NOT touch `--radius` (that is Phase 114's job). Nothing in this phase may hardcode a corner radius in px/rem — only existing `rounded-*` utility classes tied to the theme's `--radius` token.
- Does NOT search Honorário/financeiro data, does NOT add a `search:view` scope, does NOT implement document full-text/OCR search, does NOT add a command-palette action launcher — all explicitly out of scope per `REQUIREMENTS.md`.

## Spacing Scale

Declared values (must be multiples of 4) — standard scale, already the app-wide convention:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside a result row (`gap-1`), skeleton row rhythm |
| sm | 8px | Compact spacing between elements (`gap-2`) — header icon clusters, `CommandItem` internal gap |
| md | 16px | Default padding (dialog `p-4`/`p-6` regions, `Empty` inner padding halves) |
| lg | 24px | Section padding, topbar `gap-6` |
| xl | 32px | Layout gaps (not heavily used by this compact feature) |
| 2xl | 48px | Major section breaks (not used by this phase) |
| 3xl | 64px | Page-level spacing (not used by this phase) |

**Exceptions:** None. Specifically — **do not** introduce a 44px icon-only touch target for the mobile search trigger. This codebase's own topbar precedent (`NotificationBell`, the hamburger menu button) already uses **36px** (`h-9 w-9`, Button's `size="icon"`) for every topbar icon action across all breakpoints, including mobile. The new mobile search trigger must match that exact existing convention, not invent a new size. (The 48px touch-target convention from Phase 55 applies to form controls inside mobile bottom-sheets/modals — a different UI class, not topbar icon buttons — and does not apply here.)

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | Regular 400 (default); **Semibold 600 reserved exclusively for the bold-highlighted matched substring** in result title/subtitle | Normal / Tailwind default ≈1.43 (unmodified — matches every other `text-sm` instance already in the app) |
| Label | 12px (`text-xs`) | Regular 400 (subtitles, kbd hint, error/no-results copy); Medium 500 is **inherited-only** (baked into the reused `CommandGroup` heading style, not newly authored) | Tailwind default ≈1.33 |
| Heading | 18px (`text-lg`) | Medium 500 — **inherited from the reused `EmptyTitle` primitive** (empty/no-results state title only); this phase does not author new heading-weight text | 1.2 (tight) |
| Display | Not used this phase | — | — |

**Weight budget for NEW text this phase authors: exactly 2 — Regular (400) and Semibold (600, bold-highlight only).** Medium (500) appears only where an already-installed, reused-not-redesigned shadcn primitive (`CommandGroup` group heading, `EmptyTitle`, `Badge`) already bakes it in — do not introduce any additional new medium-weight text beyond what these primitives already carry.

**Highlight rule (locked, `112-CONTEXT.md`):** matched-substring emphasis is **bold weight only** — never a background color, never an underline. Applies to both the result title and subtitle (the subtitle frequently contains the structured identifier the user typed, e.g. `numero_cliente`/NIF). Match case-insensitively against the literal typed query on the rendered `titulo`/`subtitulo` strings; if no literal substring match is found in the display text (e.g. the backend matched via `unaccent`-normalized diacritics), render the text plain with no bold segment rather than attempting accent-aware highlighting — an explicit, deliberately simple fallback for this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `#f8fafc` light / `#020617` dark; `--popover` `oklch(1 0 0)` light / `oklch(0.205 0 0)` dark | Page canvas behind the dialog overlay (`DialogOverlay`, `bg-black/50`, unmodified); the `CommandDialog`/`DialogContent` surface itself (`bg-popover`) |
| Secondary (30%) | `--muted` `oklch(0.97 0 0)` light / `oklch(0.269 0 0)` dark | Selected/hovered `CommandItem` row (`data-selected:bg-muted`, inherited — do not override to blue), skeleton fill (`bg-muted animate-pulse`), the existing dark sidebar (untouched by this phase) |
| Accent (10%) | `--primary` `#2563eb` light / `#3b82f6` dark | Reserved **exclusively** for: (1) the search trigger's focus-visible ring — reuse the exact existing class `focus-visible:ring-1 focus-visible:ring-blue-500/50` already on the `<Input>` this phase replaces; (2) the trigger's search-icon focus color — reuse the exact existing class `group-focus-within:text-blue-500`; (3) each group's "Ver todos os {Entidade}" link text/hover — `text-blue-600 dark:text-blue-400 hover:underline`, mirroring `NotificationBell`'s "Ver todas as notificações" link verbatim |
| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` light / `oklch(0.704 0.191 22.216)` dark | **Not used.** This phase introduces zero destructive actions (read-only search + navigate). |

**Accent reserved for:** trigger focus ring, trigger search-icon focus color, "Ver todos os {Entidade}" group links. **Explicitly never** for: the matched-substring highlight (bold weight only, per the locked decision above — no blue text, no colored background), or the selected/hovered `CommandItem` row background (stays neutral `bg-muted`, inherited from `command.tsx` — must not be overridden to blue, which would fight the primitive's own `data-selected` styling).

## Component Inventory & Interaction States

*(Supplementary to the template's required sections — the planner/executor consume this directly per the downstream-consumer contract; the checker maps it to Dimension 2 "Visuals".)*

**Primary focal point:** on dialog open, `CommandInput` is the sole focal point (auto-focused, nothing else competes for attention). Once results render, the secondary hierarchy cue is the bold-highlighted matched substring within each result's título/subtítulo — no other visual weight (color, size, icon emphasis) competes with it inside a result row.

| File | Change | Notes |
|------|--------|-------|
| `web/src/components/shared/global-search-dialog.tsx` | NEW | Self-contained shell — owns open-state + Ctrl+K/⌘K listener, same shape as `notification-bell.tsx` |
| `web/src/hooks/use-global-search.ts` | NEW | TanStack Query wrapper, `queryKey: ["search", debouncedQ]` |
| `web/src/lib/use-debounced-value.ts` (or equivalent) | NEW | ~10 lines; 300ms — matches both the locked decision and the existing inline precedent at `clientes/page.tsx:80-85` |
| `web/src/types/search.ts` | NEW | Mirrors backend `ResultadoPesquisaDto`: `{ tipo, id, titulo, subtitulo, rota }` |

### Trigger placement (researcher default, grounded in `dashboard-shell.tsx`'s actual current structure)

- **Desktop (`md:` and up):** the existing `hidden md:flex flex-1 max-w-md` slot (currently the decorative `<Input>`) becomes a `<button>` styled to visually match the current input exactly — same classes (`pl-9 bg-slate-100/50 dark:bg-slate-900/50 border-slate-200 dark:border-slate-800 rounded-full text-sm h-9 shadow-sm`), same left-aligned `Search` icon, placeholder-style "Pesquisar..." text in `text-slate-400`/muted-foreground, plus a new trailing kbd hint. Visually near-identical to today — only behavior changes (click/Enter opens the dialog instead of typing inline).
- **Mobile (below `md`):** a second, icon-only trigger (`Search`, `h-9 w-9`, `aria-label="Pesquisar"`) added to the existing `ml-auto flex items-center gap-3` action group (the group that already holds `ThemeToggle`/`NotificationBell`/`UserMenu` and is already visible at every breakpoint), wrapped in `md:hidden` so exactly one trigger is ever visible at a given width — mirroring the existing `md:hidden` pattern already used by the hamburger button in this same file. Placed immediately before `ThemeToggle`.
- Both triggers open the **same** `GlobalSearchDialog`/`CommandDialog` instance — single shared open-state, two entry points, exactly as `112-CONTEXT.md` requires ("ícone/botão sempre visível... Ctrl+K é um extra desktop").
- `rounded-full` on the desktop trigger is a fixed Tailwind utility (not tied to `--radius`) — its pill shape is unaffected by Phase 114's future radius change, unlike `command.tsx`'s own `rounded-xl!`/`rounded-lg!`, which **is** tied to `--radius` and will only visually round once Phase 114 lands. Do not hardcode a radius value anywhere in this phase's new code.

### Result item anatomy

```
[icon 16px]  Título (regular, bold on matched substring)
             Subtítulo (12px, muted-foreground, bold on matched substring)
```

- Icon: entity-type icon, reused verbatim from `dashboard-shell.tsx`'s `NAV` — `Users` (Cliente), `Scale` (Processo), `FileText` (Documento), `ScrollText` (Parecer). Auto-sized to 16px by `CommandItem`'s own `[&_svg:not([class*='size-'])]:size-4` rule — no extra sizing class needed.
- Group order (locked): Clientes → Processos → Documentos → Pareceres — same order as the sidebar `NAV`.
- Title/subtitle content itself (`titulo`/`subtitulo` strings) is fully computed server-side by Phase 111's `ResultadoPesquisaDto` — this phase only renders and highlights what the API returns, it does not construct the disambiguator format.
- "Ver todos os {Entidade}" renders as the **last `CommandItem`** in that group's list (keyboard-navigable, consistent with "navigation vem grátis do cmdk"), styled in the reserved accent color (see Color section), no icon — plain text link, matching `NotificationBell`'s "Ver todas as notificações" precedent exactly (no icon there either).

### States reference

| State | Trigger | Visual |
|-------|---------|--------|
| Pre-query, no recent items | Dialog just opened, `sessionStorage` recents empty, query empty | `Empty`/`EmptyTitle`/`EmptyDescription` — copy per Copywriting table |
| Pre-query, recent items exist | Dialog just opened, `sessionStorage` has ≥1 entry | Single flat group headed "Visitados recentemente", plain weight (no bold — nothing is "matched" yet), max 5 items, most-recent-first, deduplicated by `(tipo,id)` |
| Debounce window (0–300ms after a keystroke) | User typing, request not yet fired | **No loading indicator at all** — locked decision, `112-CONTEXT.md`: "Nenhum indicador durante os ~300ms de debounce" |
| Loading | Debounced query ≥2 chars, request in flight | Skeleton rows per group — `h-8 w-full rounded-md` (matches `Skeleton`'s own `bg-muted animate-pulse`), 3 rows/group, only for the entity groups the caller's **client-side-known** permissions (`hasScopedPermission(me.permissions, scope, "view")`, same check `NAV` already uses) indicate will appear — a display-only optimization to prevent layout shift once the real (server-side-RBAC-filtered) response lands; this is never the actual security boundary, which remains 100% server-side per Phase 111 |
| Results | Response returned, ≥1 result | Grouped `CommandGroup`s in the locked order, each capped at what the backend already returned (≤5/type, no further frontend truncation) |
| No results | Response returned, 0 results across all groups | `Empty`/`EmptyTitle`/`EmptyDescription` (not `CommandEmpty`) — matches `112-CONTEXT.md`'s locked decision verbatim ("reutiliza Empty/EmptyTitle/EmptyDescription com mensagem simples"); "Sem resultados" / "Não foram encontrados registos para..." copy, rendered inside `CommandList` in place of `CommandGroup`s |
| Error | Request rejected/network failure | Inline text inside the dialog (mirrors `NotificationBell`'s inline-error precedent, in addition to `apiFetch`'s automatic toast) |

### Keyboard & focus behavior

- Ctrl+K / ⌘K toggles the dialog (opens if closed, closes if open) — global listener mounted once in `dashboard-shell.tsx`, same shape as `NotificationBell`'s self-contained state.
- `event.preventDefault()` on the keydown so the browser's own address-bar/bookmark shortcuts don't fire underneath.
- Esc and click-outside close — free from `Dialog`/Radix, already relied on elsewhere in this codebase, no new code needed.
- Arrow keys + Enter navigate/select — free from `cmdk`, same as `combobox.tsx`. **`shouldFilter={false}` must be set explicitly** on the `Command` root, copying `combobox.tsx:107`'s exact precedent — otherwise cmdk's own fuzzy `command-score` scorer will re-sort or silently hide the backend's already-correctly-ranked results (a score of `0` hides an item entirely, not just deprioritizes it).
- Focus returns to whichever trigger opened the dialog on close — default Radix `Dialog` behavior, no special handling needed.
- Every result-group section must gate on `permissions.isFetched`, never `!permissions.isLoading` — a recurring bug class in this codebase (Phase 103/105/v2.13-audit).

### Recent items (`sessionStorage`, session-only per SRCH-10)

- Cap: 5 items, most-recent-first, deduplicated by `(tipo, id)` — revisiting a record moves it to the front rather than duplicating.
- All 4 types (`cliente`/`processo`/`documento`/`parecer`) are eligible — corrected per plan-checker finding: Documento does have a working detail route (`documentos/[id]/page.tsx`) and Phase 111's `PesquisaController` already returns it.
- Session-only storage (`sessionStorage`, not `localStorage`) — never persists across sessions, never sent to the server; this is the confidentiality-driven choice already locked in `112-CONTEXT.md` and `REQUIREMENTS.md` (SRCH-10) for a shared institutional workstation.
