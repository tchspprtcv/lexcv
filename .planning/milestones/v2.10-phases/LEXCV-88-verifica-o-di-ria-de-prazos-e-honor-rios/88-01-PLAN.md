## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Spring context startup → repository proxy generation | Derived-query method names are validated against the entity metamodel at context load; a name that does not map to real fields fails at startup, not compile. Both new method names were verified field-for-field against `Notificacao.java` / `Honorario.java` during planning. |
| `@EnableScheduling` activation → background scheduler thread | This config is the on-switch for the codebase's first non-request-driven execution thread. It carries no logic itself; all tenant-isolation and failure-isolation responsibility lives in the job (Plan 88-02). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-8801-01 | Tampering | `existsBy...Categoria` derived query | mitigate | Idempotency correctness depends on this predicate covering the full 5-tuple. Name derived exactly from confirmed `Notificacao` fields (tenantId, destinatarioId, entidadeTipo, entidadeId, categoria); a dropped segment would weaken dedup and is caught by Plan 88-02's idempotency tests which stub and assert against this exact signature. |
| T-8801-02 | Elevation of Privilege | `@EnableScheduling` in `SchedulingConfig` | accept | Activating scheduling only registers beans already annotated `@Scheduled`. The only such bean is `AlertasDiariosJob` (Plan 88-02). No pre-existing bean gains new capability. Isolated `@Configuration` keeps the blast radius to scheduling alone. |
| T-8801-03 | Information Disclosure | `findByProcessoIdIn` batch query | mitigate | The method takes an explicit `Collection<UUID>` of processo ids; the caller (job) only ever passes ids from that tenant's own `processoRepository.findByTenantId(tenantId)` result, so tenant scoping is preserved by the caller's input set. Honorario has no `tenant_id` column (transitive isolation via processo) — documented, and enforced upstream in Plan 88-02. |
| T-8801-SC | Tampering (supply chain) | Maven dependencies | accept | No new dependency added this phase. `@EnableScheduling`/`@Scheduled` are part of `spring-context`, already resolved via `spring-boot-starter-web` (confirmed in ARCHITECTURE.md sources: `pom.xml` has no Quartz/ShedLock). No `npm`/`pip`/`cargo`/new-Maven install to legitimacy-check. |
</threat_model>
