<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→API (same-origin, cookie JWT) | A página lê/marca só as notificações do próprio destinatário; scoping server-side (Phase 86) |
| linkUrl renderizado como href | Valor autoria-backend, contratualmente same-origin relativo; tratado como não-confiável |
| gate notificacoes:view | Gate de UX/defesa-em-profundidade; a fronteira de segurança real é server-side |
| query params de filtro (categoria/lida/page) | Input do utilizador enviado ao backend como filtros — não são parâmetros de autorização |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-89-03-01 | Tampering | `n.linkUrl` no título navegável | mitigate | Renderizar como `<Link>` APENAS quando `linkUrl` começa por "/" (relativo same-origin); caso contrário texto simples — bloqueia open-redirect/`javascript:` caso surja valor não-relativo. Null já cai em texto simples |
| T-89-03-02 | Elevation of Privilege | acesso à página | accept | O gate `notificacoes:view` é UX/defesa-em-profundidade; a autorização efetiva é server-side. O scope está seedado para os 4 perfis (Phase 86), pelo que o gate não bloqueia ninguém hoje — é o padrão de todas as páginas |
| T-89-03-03 | Information Disclosure | lista paginada filtrada | mitigate | Endpoints dual-scoped (tenant+destinatário) server-side (Phase 86); a página não envia parâmetro de destinatário; `categoria`/`lida`/`page` são apenas filtros, o backend deriva o destinatário do JWT |
| T-89-03-04 | Tampering | id em marcarLida.mutate (botão Check + clique no título) | mitigate | O id vem só da lista recebida pelo utilizador; o backend revalida posse (Phase 86); `encodeURIComponent` no hook (Plan 89-01) |
| T-89-03-SC | Tampering (supply chain) | dependências | accept | Sem novos packages; `Check`/`CheckCheck` do `lucide-react` já presente; `Card`/`Badge`/`Button`/`AccessDeniedState` já existentes; sem alteração de `pnpm-lock.yaml` |
</threat_model>
