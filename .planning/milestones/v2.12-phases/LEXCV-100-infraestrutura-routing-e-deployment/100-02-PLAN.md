The @webpage block is IDENTICAL across all Caddy sources (only indentation differs per file). It matches ONLY the exact root path `/` and the asset-prefix `/landing-static/*` — never a broad glob — so /api/*, /login, /dashboard, /setup all fall through unchanged. Use a plain `handle` (mutually exclusive), NOT `handle_path` (which would strip the prefix and 404 webpage's own assets — Next 15+ serves assets AT the assetPrefix without stripping).

TARGET Caddyfile (dev) — full file AFTER edit:
```caddyfile
:80 {
    handle /api/* {
        reverse_proxy backend:8080
    }

    @webpage {
        path / /landing-static/*
    }
    handle @webpage {
        reverse_proxy webpage:3000
    }

    handle {
        reverse_proxy frontend:3000
    }
}
```

TARGET Caddyfile.prod — full file AFTER edit (@webpage inserted between the /minio-console* block and the catch-all; native {$DOMAIN_NAME} templating is SAFE here — this is a real mounted file, NOT a Compose heredoc):
```caddyfile
{$DOMAIN_NAME}, www.{$DOMAIN_NAME} {
    handle /api/* {
        reverse_proxy backend:8080
    }
    handle_path /minio-console* {
        basicauth {
            {$CADDY_MINIO_USER} {$CADDY_MINIO_PASSWORD_HASH}
        }
        reverse_proxy minio:9001
    }

    @webpage {
        path / /landing-static/*
    }
    handle @webpage {
        reverse_proxy webpage:3000
    }

    handle {
        reverse_proxy frontend:3000
    }
}
```

TARGET docker-compose.yml — add this service block after the existing `frontend:` block (before `caddy:`):
```yaml
  webpage:
    build:
      context: ./webpage
      dockerfile: Dockerfile
    container_name: lexcv_webpage
    depends_on:
      - backend
    environment:
      BACKEND_API_ORIGIN: http://backend:8080
      NEXT_PUBLIC_API_BASE_PATH: /api/v1
    networks:
      - lexcv_net
    ports:
      - "3004:3000"
```
AND change the existing caddy service's `depends_on` in docker-compose.yml from `[frontend, backend]` to `[frontend, backend, webpage]` (add one `- webpage` line).

TARGET docker-compose.prod.yml — add this override block alongside the existing `frontend:` override (mirrors it exactly):
```yaml
  webpage:
    image: ${REGISTRY:-ghcr.io/lexcv}/webpage:${IMAGE_TAG:-latest}
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 256M
```
(No caddy change needed in the prod override — it inherits caddy's `depends_on: [..., webpage]` from the base docker-compose.yml edited above.)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet -> Caddy | All external HTTP enters at Caddy; the routing table decides which internal service (backend/webpage/frontend) each path reaches — a misrouted path can expose or misdirect traffic |
| Caddy -> internal services (lexcv_net) | Caddy reverse-proxies to backend:8080 / webpage:3000 / frontend:3000; a too-broad matcher could send API or dashboard traffic to the wrong container |

Acceptance criteria assert the exact matcher string is present and that no `path /*` or bare `path *` glob exists — so /api/*, /login, /dashboard, /setup can never be captured by the webpage branch. Runtime proof of correct isolation is the live route matrix in plan 100-04. |

Acceptance criteria assert `handle @webpage` (not `handle_path`) and Caddy `validate` passes. |
