CRITICAL FOOTGUN: Docker Compose interpolates $VAR / ${VAR} across the ENTIRE compose YAML — INCLUDING inside the caddy `entrypoint` heredoc — BEFORE Caddy ever sees the text. Commit 67e2120 had to hardcode `alcv.tech` (was `{$DOMAIN_NAME}`); commit 534fa92 had to DELETE the MinIO basicauth because the bcrypt hash's literal `$` chars got mangled and crashed Caddy on startup. Therefore every line added inside this heredoc MUST use only hardcoded literals and contain ZERO `$` characters. `webpage:3000` and `path / /landing-static/*` contain no `$` — that is why they are safe. (Caddyfile.prod, a real mounted file, is NOT subject to this — but it is out of scope for this plan; do not touch it.)

TARGET caddy `entrypoint` heredoc — full block AFTER edit (the @webpage block inserted between `handle /api/*` and the catch-all; NOTE: zero `$` anywhere in the echoed Caddyfile text, exactly as today):
```yaml
    entrypoint:
      - sh
      - -c
      - |
        echo 'alcv.tech, www.alcv.tech {
            handle /api/* {
                reverse_proxy backend:8080
            }
            @webpage {
                path / /landing-static/*
            }
            handle @webpage {
                reverse_proxy webpage:3000
            }
            handle {
                reverse_proxy frontend:3000
            }
        }' > /etc/caddy/Caddyfile && exec caddy run --config /etc/caddy/Caddyfile --adapter caddyfile
```

TARGET caddy `depends_on` — change from `[frontend, backend]` to `[frontend, backend, webpage]` (add one `- webpage` line).

TARGET new webpage service — add after the existing `frontend:` block (mirrors the frontend block: GHCR image, internal-only = NO `ports:`, resource limits, restart):
```yaml
  webpage:
    image: ghcr.io/tchspprtcv/lexcv/webpage:latest
    container_name: lexcv_webpage
    depends_on:
      - backend
    environment:
      BACKEND_API_ORIGIN: http://backend:8080
      NEXT_PUBLIC_API_BASE_PATH: /api/v1
    networks:
      - lexcv_net
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 256M
    restart: unless-stopped
```
Note: Hostinger exposes ONLY caddy's ports (80/443) — every other service is internal-only via lexcv_net. The webpage block therefore has NO `ports:` (unlike the dev docker-compose.yml block, which maps 3004:3000). The BACKEND_API_ORIGIN=http://backend:8080 is a Docker-internal service name (this is what makes the server-side fetch resolve over the internal network, not hairpin out through the public domain — verified live in 100-04).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker Compose interpolation -> Caddy heredoc | Compose expands $VAR/${VAR} across the whole YAML (including the entrypoint heredoc string) BEFORE Caddy parses it — any `$` inside the heredoc is a live footgun that can silently corrupt the Caddy config text |
| Public internet -> Caddy (production/Hostinger) | This heredoc IS the production routing table; a malformed config crashes Caddy on startup, taking the entire site (backend + frontend + webpage) offline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-100-02 | Denial of Service (availability) — the $-interpolation footgun | docker-compose.hostinger.yml caddy entrypoint heredoc | mitigate | This is the SPECIFIC failure mode from commits 67e2120 (domain `{$DOMAIN_NAME}` -> hardcoded) and 534fa92 (bcrypt `$2a$10$...` mangled -> basicauth removed): a `$` inside the heredoc gets interpolated by Compose before Caddy sees it, producing a malformed config that crashes Caddy at container startup and downs the whole site. Mitigation: added lines use ONLY hardcoded literals (`webpage:3000`, `path / /landing-static/*`) with ZERO `$`. The load-bearing acceptance gate is the scoped awk+grep that asserts `0` `$` characters in the heredoc range — plus a `docker compose config` render proving the @webpage text survives interpolation intact. The test passes BECAUSE this specific footgun was avoided, not merely because Caddy config looks plausible. |
| T-100-01 | Information Disclosure / Elevation of Privilege | @webpage matcher in the heredoc | mitigate | Matcher is exactly `path / /landing-static/*` (never a `/*` glob), inserted after `handle /api/*` and before the catch-all — /api/*, /login, /dashboard, /setup fall through to backend/frontend unchanged. Asserted by the narrow-matcher acceptance criterion. |

The file is edited and verified locally via `docker compose config` + the no-`$` gate; a real deploy is explicitly out of scope and requires separate user authorization (per 100-CONTEXT.md and ROADMAP). |
