ROUTING MATRIX — the primary content-agnostic discriminator is WHICH asset prefix the returned HTML references: webpage HTML references `/landing-static/`; web HTML references `/_next/` and never `/landing-static/`:
```
# / -> webpage landing (200, contains landing section ids + /landing-static/ assets)
curl -s http://localhost/ -o /tmp/root.html -w 'root=%{http_code}\n'
grep -c 'id="funcionalidades"' /tmp/root.html   # expect >=1 (webpage)
grep -c '/landing-static/' /tmp/root.html         # expect >=1 (webpage assetPrefix)

# /login -> web (200, NO /landing-static/)
curl -s http://localhost/login -o /tmp/login.html -w 'login=%{http_code}\n'
grep -c '/landing-static/' /tmp/login.html         # expect 0 (this is web, not webpage)

# /dashboard, /setup -> web (served or redirected by web; never webpage)
curl -s -L http://localhost/dashboard -o /tmp/dash.html -w 'dash=%{http_code}\n'
grep -c '/landing-static/' /tmp/dash.html           # expect 0
curl -s -L http://localhost/setup -o /tmp/setup.html -w 'setup=%{http_code}\n'
grep -c '/landing-static/' /tmp/setup.html          # expect 0

# /api/* -> backend (JSON)
curl -s http://localhost/api/v1/setup/status         # expect {"initialized":...}
```

ASSET NON-COLLISION (LP-13) — pull one real chunk URL from each app's HTML and confirm both resolve 200 through the SAME origin in DISTINCT namespaces:
```
WP_ASSET=$(grep -oE '/landing-static/_next/static/[^"]+\.js' /tmp/root.html | head -1)
curl -s -o /dev/null -w "wp_asset=%{http_code}\n" "http://localhost${WP_ASSET}"   # expect 200 (served by webpage)
WEB_ASSET=$(grep -oE '/_next/static/[^"]+\.js' /tmp/login.html | grep -v landing-static | head -1)
curl -s -o /dev/null -w "web_asset=%{http_code}\n" "http://localhost${WEB_ASSET}"  # expect 200 (served by web)
# The two prefixes (/landing-static/_next vs /_next) are structurally distinct -> no collision.
```

NO-HAIRPIN SMOKE TEST (criterion #5) — three converging proofs that webpage reaches backend over the INTERNAL network, not by hairpinning out through the public domain:
```
# (a) env is the Docker service name, not localhost/public domain
docker compose -f docker-compose.yml exec -T webpage env | grep BACKEND_API_ORIGIN   # expect http://backend:8080

# (b) backend:8080 actually resolves+responds from INSIDE the webpage container (busybox wget in node:22-alpine)
docker compose -f docker-compose.yml exec -T webpage sh -c "wget -qO- http://backend:8080/api/v1/setup/status"   # expect {"initialized":...}

# (c) positive end-to-end proof: the landing rendered the REAL tenant name (server-side fetch to backend:8080 succeeded).
#     'backend' is resolvable ONLY inside lexcv_net, so the real name in the HTML proves internal resolution, not a hairpin.
grep -c 'Escritorio Teste LexCV' /tmp/root.html    # expect >=1 (real branding, not the "LexCV" fail-open fallback)
docker compose -f docker-compose.yml logs webpage | grep -iE 'ECONNREFUSED|ENOTFOUND|fetch failed' | grep -vc '^$'   # expect 0 fetch errors
```

TEARDOWN (non-destructive — keep the user's dev volumes; do NOT use -v):
```
docker compose -f docker-compose.yml down
```
