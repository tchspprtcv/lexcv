TARGET webpage/Dockerfile (mirror of web/Dockerfile, TWO deliberate differences noted below):

```dockerfile
# Stage 1: Install dependencies
FROM node:22-alpine AS deps
WORKDIR /app
RUN corepack enable && corepack prepare pnpm@latest --activate
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile --ignore-scripts

# Stage 2: Build
FROM node:22-alpine AS builder
WORKDIR /app
RUN corepack enable && corepack prepare pnpm@latest --activate
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN pnpm build

# Stage 3: Runner
FROM node:22-alpine AS runner
WORKDIR /app
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
USER appuser
EXPOSE 3000
ENV PORT=3000
ENV HOSTNAME=0.0.0.0
ENTRYPOINT ["node", "server.js"]
```

Two deliberate differences vs web/Dockerfile:
1. NO `COPY --from=builder /app/public ./public` line — `webpage/public/` does not exist (confirmed), and building with that line would fail (`/app/public` not found). Favicon/OG/robots are out of scope per REQUIREMENTS.md and inherited from web/ via Caddy's catch-all.
2. NO `ARG/ENV NEXT_PUBLIC_API_BASE_PATH` / `ARG/ENV BACKEND_API_ORIGIN` lines — webpage/next.config.ts reads no env at build, and webpage/src/app/page.tsx is `export const dynamic = "force-dynamic"` (99-04-SUMMARY confirms `pnpm build` passes with the backend unreachable). They would be dead build-args here.

TARGET webpage/.dockerignore (byte-for-byte copy of web/.dockerignore):

```
node_modules/

.env
.env.*
.env.local
*.md
.git/
.gitignore
```

TARGET new step in .github/workflows/deploy.yml — insert immediately AFTER the existing "Build and push frontend image" step (currently the last step of the build-and-push job), same 6-space indentation:

```yaml
      - name: Build and push webpage image
        uses: docker/build-push-action@v6
        with:
          context: ./webpage
          platforms: linux/amd64
          push: ${{ github.ref == 'refs/heads/master' }}
          tags: |
            ${{ env.REGISTRY }}/webpage:latest
            ${{ env.REGISTRY }}/webpage:${{ env.IMAGE_TAG }}
          # No build-args: webpage is force-dynamic (page.tsx) and reads no env at build time,
          # unlike the frontend step. Server-side fetches resolve BACKEND_API_ORIGIN at request time.
          cache-from: type=gha,scope=webpage
          cache-to: type=gha,mode=max,scope=webpage
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> GHCR | CI builds an image and pushes it to the container registry; a compromised/incorrect build step could publish a malicious or wrong-namespace artifact |
| Host build context -> image layers | `COPY . .` pulls the build context into the image; without .dockerignore, host secrets (`.env.local`) or stale artifacts (`node_modules/`, `.next/`) could leak into or corrupt the image |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-100-SC | Tampering (supply chain) | new deploy.yml build-push step | mitigate | Reuse `docker/build-push-action@v6` (identical version to backend/frontend steps); push only to `${{ env.REGISTRY }}/webpage` (same GHCR namespace); reuse the existing "Log in to GHCR" step. Acceptance criteria assert `docker/build-push-action@v6` count == 3 and no other action version appears — no new third-party action is introduced. |
| T-100-SC2 | Tampering (base image / deps) | webpage/Dockerfile | mitigate | Base image `node:22-alpine` is identical to the already-trusted web/Dockerfile. `pnpm install --frozen-lockfile` pins to the Phase-99-vetted `webpage/pnpm-lock.yaml` — Phase 100 adds ZERO new dependencies, so no new package-legitimacy checkpoint is required (the lockfile is frozen and was audited when created in Phase 99). |
| T-100-I | Information Disclosure | image build context | mitigate | webpage/.dockerignore excludes `.env`, `.env.*`, `.env.local` so no runtime secrets are baked into image layers; excludes `node_modules/` and `.next/` so host artifacts can't corrupt the clean in-image build. |

No package-manager install of NEW packages occurs in this phase; the Package Legitimacy Gate is satisfied by the frozen, previously-audited lockfile.
