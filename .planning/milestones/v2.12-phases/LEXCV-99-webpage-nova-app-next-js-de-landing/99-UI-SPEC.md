## Spacing Scale

Declared values (must be multiples of 4) — these are Tailwind's own default tokens, already used project-wide with zero `@theme` overrides:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside nav links and trust-bullet icon rows |
| sm | 8px | Compact gaps (eyebrow tag internal padding, badge-style pills) |
| md | 16px | Default gap between a card's icon/title/body lines; header horizontal item gaps |
| lg | 24px | Card internal padding (`CardHeader`/`CardContent`'s own default `p-6`, inherited unmodified); gap between grid cards |
| xl | 32px | Gap between a section's eyebrow+heading block and its content grid |
| 2xl | 48px | Section vertical padding on mobile (`py-12`); gap between Hero title and subtitle block |
| 3xl | 64px | Section vertical padding on tablet (`md:py-16`) |

**Exceptions:** one extended token beyond the base 7 — **4xl = 96px** (`py-24`, Tailwind `space-24`, still a multiple of 4) for Hero and section-band vertical padding on desktop (`lg:py-24`). Full responsive step-down for every section band: `py-12` (mobile) → `md:py-16` (64px) → `lg:py-24` (96px). No other exceptions. No icon-only touch targets are introduced by this phase — `ThemeToggle` is reused exactly as-is at its existing 36px (`h-9 w-9`) size, matching the rest of the app; this phase does not invent a new 44px minimum since it would be inconsistent with the unmodified reused component.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 (regular) | 1.5 (`leading-6` equivalent) |
| Label | 14px (`text-sm`) | 600 (semibold) | 1.2 |
| Heading | 24px (`text-2xl`) | 600 (semibold) | 1.2 |
| Display | 48px (`text-5xl`) | 600 (semibold) | 1.15 |

Exactly 4 sizes, exactly 2 weights (400/600), declared flat (no responsive step-down for any role — see rationale below).

**Role assignment:**
- **Display (48px)** — Hero H1 only. Flat at all breakpoints, no responsive step-down. This is deliberately the largest size proven anywhere in this codebase today (`web/src/app/setup/page.tsx`'s H1 uses `sm:text-5xl` as its desktop ceiling) — reused verbatim as the landing's one and only Display value, applied unconditionally rather than only above a breakpoint, for a bolder flagship treatment. The locked hero title ("Gestão jurídica completa para a sua instituição") is short enough that 2–3 line wraps on narrow mobile viewports remain fully legible; this avoids introducing a 5th, mobile-only size.
- **Heading (24px)** — all section H2s ("Funcionalidades", "Confiança Institucional", "Contacto") and all card titles (6 module cards + 4 trust cards). Matches `CardTitle`'s own existing default (`text-2xl font-semibold leading-none tracking-tight`) exactly — zero override needed when reusing `CardTitle`.
- **Body (16px)** — Hero subtítulo, section intro paragraphs, module/trust card descriptions, footer copy. Flat everywhere (no `text-sm→text-base` responsive step, unlike `setup.tsx`'s subtitle) — kept simple since 16px already reads well at every viewport.
- **Label (14px)** — nav anchor links, eyebrow/kicker tags (uppercase + `tracking-[0.2em]`, matching the letter-spacing pattern already used in `setup/page.tsx`'s eyebrow tag and `dashboard-shell.tsx`'s "Sistema" group label — only the numeric size is standardized here into 14px instead of `setup.tsx`'s one-off 11px, to keep this phase's palette at exactly 4 declared sizes while preserving the visual *pattern*), footer fine print, CTA button labels (see exception below).

**Two documented, pre-existing exceptions (do not extend elsewhere on this page):**
1. `Button`/`Badge` ship an internal `font-medium` (500) baked into their own CVA base classes. Any text rendered through these unmodified, reused primitives (CTA labels, any badge chip) will render at weight 500, not 400/600. This is accepted because CONTEXT.md mandates reusing these components verbatim, not modifying them. All *new* landing-authored text (headings, body, nav, eyebrows) must use only 400/600.
2. `Button`'s `size="sm"` variant internally overrides to `text-xs` (12px) — **do not use `size="sm"` anywhere on this page** for exactly this reason. Use `size="default"` (36px height, inherits base `text-sm`/14px) + `variant="secondary"` to achieve the "small/secondary" header CTA that CONTEXT.md calls for, and `size="lg"` (40px height, also inherits `text-sm`/14px) + `variant="default"` for the "large/primary" footer CTA. Both resolve to the same declared Label size (14px); only height/padding/color variant differ, matching CONTEXT.md's own distinction ("apenas estilos diferentes").

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` → `#f8fafc` light / `#020617` dark | Page background for every section band (Hero, Funcionalidades, Confiança, Contacto, Footer) — identical CSS custom property already defined in `web/src/app/globals.css`, copied verbatim into `webpage/src/app/globals.css` |
| Secondary (30%) | White light / `#020617` dark, bordered `slate-200`/`dark:slate-800` | Module cards, trust cards, sticky header bar background — this is `Card`'s own existing default styling (`bg-white dark:bg-[#020617] border border-slate-200 dark:border-slate-800`) reused with **zero override**. Sticky header uses the same pair via `bg-white/80 dark:bg-[#020617]/80 backdrop-blur-md`, mirroring `dashboard-shell.tsx`'s header treatment exactly. |
| Accent (10%) | `blue-600` light / `blue-400` dark | Reserved for **exactly**: (1) the 6 module-card icons in the Funcionalidades grid, (2) in-page anchor-nav link hover/active state (`#funcionalidades` / `#confianca` / `#contacto`), (3) a single hairline accent rule above the Hero eyebrow tag. **Never** CTA button backgrounds, never body text, never card backgrounds/borders. |
| Destructive | `red-600` light / `red-400` dark | Not used in this phase — zero destructive actions exist on a static marketing page. Declared only for contract completeness, matching `web/`'s existing error-copy convention (`setup/page.tsx`'s `serverError` block uses the same `red-600`/`dark:red-300` family). |

Accent reserved for: **module-card icons, anchor-nav hover/active state, one Hero hairline accent — nothing else.**

**Rationale (grounded in existing code, not invented):** the codebase actually has two established registers. The authenticated dashboard shell (`dashboard-shell.tsx`) uses blue as a "wayfinding" accent — active nav indicator, avatar gradient, focused search ring — signaling *"you are inside the live product."* The one existing pre-auth, full-bleed page (`setup/page.tsx`) is deliberately monochrome — zero blue anywhere, sharp borders, black/white contrast CTA. Since the landing page is pre-auth and full-bleed like `/setup` (not dashboard chrome), it inherits the monochrome institutional register as its Dominant/Secondary/CTA treatment, and uses blue only as a small, deliberate "preview of the product" accent on the module icons and nav — never as the CTA color. This is a simplification of `dashboard-shell.tsx`'s own slightly inconsistent unconditional `blue-400`/`blue-500` mix (applied without light/dark prefixing in places) into a clean, conventional light/dark pairing.

**Neutral (gray) scale — resolves a real existing inconsistency:** `button.tsx`/`badge.tsx`/`input.tsx` hardcode `neutral-*`, while `card.tsx`/`dashboard-shell.tsx`/`setup/page.tsx` hardcode `slate-*`. For every *new* element authored in this phase (section wrappers, custom text, borders, dividers), use **`slate-*` only** — it is both the dominant existing precedent and the literal hex source of the `--background`/`--foreground` tokens. `Button`/`Badge`/`Input`'s internal `neutral-*` is a pre-existing, accepted exception scoped only to those reused, unmodified primitives — do not introduce new `neutral-*` classes anywhere else on this page.

**Border radius convention:** `rounded-none` across the entire page. Cards need no override (`Card`'s own default is already `rounded-none`). Buttons require an explicit `className="rounded-none"` at each call site on this page only (overriding `Button`'s own internal `rounded-md`) — do not modify `button.tsx` itself. This exactly matches the precedent set by `setup/page.tsx`, the closest existing full-bleed institutional page, which overrides its `Input`/submit `Button` to `rounded-none` for the same reason: a sharp-cornered, "official document" feel appropriate to a legal-sector product.

## Page Structure & Layout

*(Supplementary section — this phase builds an entire new page, not a single component, so the structural/layout contract below is as load-bearing as the token tables above.)*

Single-page layout (per CONTEXT.md — no multi-route nav), top to bottom:

1. **Sticky header** — `h-16` (64px, matches `dashboard-shell.tsx`'s own header height convention), `bg-white/80 dark:bg-[#020617]/80 backdrop-blur-md`, border-bottom `slate-200`/`dark:slate-800`, `sticky top-0 z-10`. Contents: brand mark (left) · anchor nav (center/right, hidden `<md:`) · `ThemeToggle` · "Entrar" CTA (small/secondary).
2. **Hero** — full-width band, Dominant background, no card wrapper, no decorative gradients/blobs/mesh (the existing codebase has zero precedent for decorative backgrounds beyond the 36px avatar gradient — keep the Hero flat, consistent with `setup/page.tsx`'s equally undecorated top block). Vertical padding per the 4xl/3xl/2xl step (96/64/48). Centered or left-aligned single column, max-width constrained (match `setup/page.tsx`'s `max-w-7xl`/`max-w-3xl` container pattern).
3. **Funcionalidades/Módulos** — eyebrow + H2 + 6-card grid (`Card` component, unmodified styling).
4. **Confiança Institucional** — eyebrow + H2 + 4-card/bullet grid.
5. **Contacto** — eyebrow + H2 + body + single `mailto:` CTA, no form.
6. **Footer** — brand mark (small) + "Entrar" CTA (large/primary) + fine print line.

**Breakpoints:** `md:` (768px) is the established mobile/desktop breakpoint project-wide (PROJECT.md Key Decision: *"`md:` (768px) como breakpoint mobile/desktop... Consistência com shadcn/ui defaults e Tailwind breakpoints"*); `lg:` (1024px, Tailwind default) is the secondary breakpoint for 3- and 4-column grids. No custom breakpoints introduced.

**Responsive grid summary:**
| Section | Mobile (base) | Tablet (`md:`) | Desktop (`lg:`) |
|---|---|---|---|
| Funcionalidades (6 cards) | 1 col | 2 col | 3 col |
| Confiança (4 cards) | 1 col | 2 col (`sm:`) | 4 col (single row) |
| Header nav links | hidden | visible | visible |

**Dark/Light:** full parity in both themes via the ported `next-themes` provider (`attribute="class"`, `defaultTheme="system"`) — every color pairing declared above already has both a light and dark value; no section should be light/dark-mode-only.
