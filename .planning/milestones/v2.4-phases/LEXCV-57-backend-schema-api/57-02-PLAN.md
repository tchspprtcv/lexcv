## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request body → createCliente | Client-supplied JSON must not contain numero_cliente or numeroSequencial (server generates these) |
| Tenant context → MAX+1 query | Generation must be scoped per tenant; global MAX would leak sequence across tenants |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-04 | Tampering | createCliente numero_cliente generation | mitigate | Server always overwrites any client-supplied numeroCliente/numeroSequencial by setting them explicitly after the MAX+1 calculation. Client cannot inject a sequence number. |
| T-57-05 | Information Disclosure | GET /clientes cross-tenant | mitigate | listClientes calls clienteRepository.findByTenantId(tenantId) then filters stream by tenantId; getCliente checks cliente.getTenantId().equals(getTenantId()) before returning. Both paths enforce tenant isolation. |
| T-57-06 | Elevation of Privilege | synchronized(ClienteRepository.class) | accept | Lock is JVM-level only — does not protect against multi-instance deploys. For single-instance deployment (current), this prevents duplicate sequence within one JVM. Acceptable per Claude's Discretion guidance in CONTEXT.md. |
| T-57-SC | Tampering | npm/pip/cargo installs | accept | No new package manager installs in this plan — pure Java source edits only. |
</threat_model>
