## Milestone Summary

**Key Decisions:**
- Backend runtime usa eclipse-temurin:23-jre-alpine (JRE only) para imagem mínima
- Frontend usa output: standalone — imagem final sem node_modules
- Secrets injetados em runtime via Docker Compose; zero secrets em ENV de imagem
- Ambas as imagens correm como non-root appuser
- Caddy auto-provisiona Let's Encrypt sem bloco TLS explícito quando hostname configurado
- DOMAIN_NAME parametrizado via env var `{$DOMAIN_NAME}` no Caddyfile.prod
- GHCR usado como registry (gratuito, integrado no GitHub Actions)
- deploy job usa `if: github.ref == 'refs/heads/main'` para evitar deploys acidentais de PRs
- IMAGE_TAG=latest na VPS (não SHA) — :latest é sempre atualizado pelo push step
- Sem --force-recreate no compose up para minimizar downtime

**Issues Resolved:**
- REGISTRY default em .env.example estava errado (ghcr.io/lexcv) → corrigido para ghcr.io/tchspprtcv/lexcv (durante audit)
- Username hardcoded tchspprtcv no deploy.yml → substituído por ${{ github.repository_owner }} (durante audit)

**Issues Deferred:**
- Runtime tests (docker compose up, HTTPS ao vivo, CI/CD end-to-end) — aguardam VPS configurada com domínio real

**Technical Debt Incurred:**
- TD-01 a TD-05: verificações runtime para VPS (docker up, Caddy routing, volume persistence, HTTPS, CI/CD trigger)
- TD-06: NEXT_PUBLIC_API_BASE_PATH baked at build time — não configurável em runtime via .env
