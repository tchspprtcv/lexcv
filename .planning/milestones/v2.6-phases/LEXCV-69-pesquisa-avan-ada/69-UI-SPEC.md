## Spacing Scale

Declared values (must be multiples of 4), identical to Phases 65/66/67/68 — reused verbatim, same module:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact element spacing (label-to-input gaps, filter-row internal gaps) |
| md | 16px | Default element spacing (card padding, filter-grid cell gaps) |
| lg | 24px | Section padding (root wrapper `space-y-6`, card-to-card gaps) |
| xl | 32px | Layout gaps (between major page sections) |
| 2xl | 48px | Major section breaks (rare) |
| 3xl | 64px | Page-level spacing (not needed at this scale) |

Exceptions: the advanced-filters panel (revealed by the toggle) uses a responsive grid (`grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4`) for its fields (texto, cliente, advogado, status, dataInicio, dataFim) — `gap-4` (16px) matches the `md` token, no new spacing value introduced. Date-range pair (`dataInicio`/`dataFim`) sits in a single grid cell as a two-column sub-grid with `gap-2` (8px, `sm` token) between the two native date inputs, consistent with the existing `agenda/page.tsx` date-range pattern.

## Color

Matches Phases 65–68's neutral/slate palette and the 60/30/10 split verbatim — same module. No new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / `dark:bg-neutral-950`-equivalent | Page background, card surfaces |
| Secondary (30%) | `slate-50`/`neutral-100` (light) — `slate-900`/`neutral-800` (dark) | Cards, filter-panel background, "sem resultados" empty-state card surface |
| Accent (10%) | `blue-600` (`hover:bg-blue-700`) | Reserved for: **the "Pesquisar" submit button only** (this phase's one primary CTA). Never applied to the toggle button, the date inputs, or the empty-state icon/copy. |
| Destructive | `red-600` | Not used this phase — no destructive action exists in pesquisa avançada (read-only feature) |

**Explicit re-declaration of the accent-reservation rule (per module convention, now closed as of Phase 68):** Accent blue is reserved exclusively for the single primary CTA per view. On this page that is the "Pesquisar" submit button. The toggle button ("Pesquisa Avançada" / "Ocultar Filtros") is a **secondary affordance** — style it as a plain/outline/ghost button (`variant="outline"` or `variant="ghost"`, matching existing secondary-button usage elsewhere in the module), never `blue-600`. This explicitly prevents a new accent leak on the one new interactive element this phase introduces.

- Timeline dot markers: unchanged from Phase 68's fix (`bg-slate-400 dark:bg-slate-500`) — not touched this phase, no version timeline in scope.
- `FileDropZone` accent-text leak: unchanged, still open per Phase 68's acknowledgment — no file upload UI exists in this phase, so it remains out of scope here as well.

## Interaction Contract (phase-specific addition)

Since this phase's primary UI-SPEC novelty is an interaction pattern rather than new visual tokens, the toggle/expand behavior is specified explicitly here for planner/executor precision:

- **Toggle mechanism:** a single button (`"Pesquisa Avançada"` / `"Ocultar Filtros"`) reveals/hides an inline panel of advanced fields (texto, cliente, advogado, status, dataInicio, dataFim) below the existing simple filter bar on `/pareceres`. This is an inline expand/collapse, not a modal, not a separate route, and not a tab — per CONTEXT.md's explicit resolution to keep this additive to the existing list page.
- **Submission model:** explicit "Pesquisar" submit button — **not** debounced live-search-on-keystroke — per CONTEXT.md's discretion resolution favoring the codebase's established draft-state + committed-filters convention (Phase 65/66 precedent). The texto/cliente/advogado/status/dataInicio/dataFim fields are all draft state until "Pesquisar" is clicked.
- **Result rendering:** when advanced search is active and has been submitted at least once, results from `usePesquisarPareceres` replace the simple list's rendering in the same table/card dual-view component — reusing Phase 65's row/card JSX, status badges, and cliente-name resolution verbatim (no duplicated rendering logic, no new visual variant for "search result row" vs "list row").
- **Clearing/reverting:** "Limpar Filtros" resets the advanced fields and returns the page to the simple list view (Phase 65's `useParecerSolicitacoes` rendering), not to a blank/empty search-results state.
- **Focal point:** the "Pesquisar" submit button is the primary visual anchor on this page once the advanced panel is expanded — it is the only accent-colored (`blue-600`) element in the panel, matching the Color section's accent-reservation rule.
