## Cross-Phase Integration Gaps (found by gsd-integration-checker)

### Gap 1 — PROC-15/16: Termo de Honorários resolves the wrong Honorário in multi-processo tenants

`web/src/app/(dashboard)/processos/[id]/termo-honorarios/page.tsx` calls `useHonorarios({ processoId: id })` → `GET /honorarios?processo_id={id}`. `ResourceController.listHonorarios()` (`backend/.../ResourceController.java:2559`) takes zero `@RequestParam` and unconditionally returns every `Honorario` for every `Processo` in the tenant. The page takes `honorarios.data?.[0]` — an arbitrary record, not necessarily this processo's.

**Impact:** any tenant with more than one formalized processo (the normal production case, since Phase 82 auto-creates one Honorário per formalização) will see the Termo de Honorários page display, block/unblock printing, and route the "edit valorTotal" link based on the wrong client's financial record.

### Gap 2 — PROC-13: Documentos tab shows every document in the tenant

`ProcessoDocumentosTab` (`web/src/app/(dashboard)/processos/[id]/page.tsx`) calls `useDocumentos({ processo_id: processoId })` → `GET /documentos?processo_id={id}`. `ResourceController.listDocumentos()` (`:2461`) takes zero parameters and returns `documentoRepository.findByTenantId(getTenantId())` — every document for the whole tenant. A correctly-scoped `GET /processos/{id}/documentos` (`listProcessoDocumentos`, `:2467`, already tenant+processo validated) exists and was built specifically for this feature, but no frontend code calls it.

**Impact:** every processo's "Documentos" tab shows every document uploaded anywhere in the tenant, including other clients' files; a user with `documentos:edit` can delete a document that visually appears scoped to this processo but belongs elsewhere.

## Resolution — Closed Same Session

Both gaps were narrow, well-understood, low-risk fixes (add a query-param filter to two existing backend endpoints; route one frontend hook through an endpoint that already existed for exactly this purpose). Rather than inserting a full gap-closure phase, they were fixed inline immediately following this audit:

- **Gap 1 fix:** `listHonorarios` gained an optional `processo_id` `@RequestParam`, with the same tenant+processo ownership check pattern already used by `listProcessoDocumentos`/`listClienteDocumentos`. When absent, behavior is unchanged (backward compatible with the existing `/financeiro` list page).
- **Gap 2 fix:** `useDocumentos` now routes to `GET /processos/{id}/documentos` when `processo_id` is provided, mirroring the exact existing branch for `cliente_id` → `GET /clientes/{id}/documentos`.

See commits following this audit for the exact diffs, and the milestone's git history for verification evidence.
