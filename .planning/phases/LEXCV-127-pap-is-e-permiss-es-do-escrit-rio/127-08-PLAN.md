<objective>
Finish the phase: make the user form assign the office's own roles by id (PAPEL-06, the frontend half
of Decisão 6 — the backend half without this ships broken user management), and rewrite the
`verify:bloqueio-rbac` gate so it proves the guarantee this phase delivers instead of the one it
retired.

That gate has 12 assertions written to prove a tenant ADMIN **cannot** save the RBAC matrix. This
phase ships the opposite. 127-CONTEXT.md Decisão 2b is explicit: it must be **rewritten to prove the
new guarantee** — not deleted, and not left failing. 127-PATTERNS.md §9 gives a per-assertion verdict,
which this plan follows:
  `A02` (Rules-of-Hooks ordering) and `A09` (the tab-visibility non-regression) survive;
  `A06`, `A07`, `A08` (the badge/tooltip apparatus) are deleted, since the apparatus is gone;
  `A03`, `A04`, `A05`, `A10`, `A11`, `A12` are inverted or retargeted.
`A02`'s predicate names `useMe()`, and the rewritten tab may no longer call it. The protection it
provides is ordering, not that specific hook, so it is generalised: **every** hook call in the block
must precede the first early return. That is strictly stronger than the original predicate and
cannot be satisfied by accident — which is what Decisão 2b is protecting.

Purpose: PAPEL-06 end to end, and an executable gate that fails if any of this phase's structural
guarantees is undone later.
Output: a converted role picker, a renamed and rewritten gate script, and a live human check.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser user form → `POST/PUT /api/v1/admin/users` | the client submits which roles another user will hold; the backend re-resolves every id within the caller's tenant |
| source tree → structural gate | the gate is the regression boundary for guarantees that have no runtime assertion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-127-39 | Elevation of Privilege | picker offering a role from outside the tenant | mitigate | the list comes from `useOfficeRbac()`, which is already tenant-scoped server-side; plan 05 re-resolves every submitted id within the caller's tenant regardless of what the client sends |
| T-127-40 | Denial of Service (self-lockout) | leaving a user, or oneself, with zero roles | mitigate | the at-least-one guard is preserved and generalised to ids; the backend refuses an empty selection with 400 (plan 05); live step 9 checks the administrator's own path end to end |
| T-127-41 | Tampering (regression) | a later edit reintroducing the literal `"ADMIN"` lock or the read-only branch | mitigate | `matriz-bloqueio-por-proveniencia` and `matriz-sem-branch-readonly`, plus the acceptance criterion that requires the gate to be observed FAILING when the lock is broken |
| T-127-42 | Repudiation | losing the Rules-of-Hooks protection during the rewrite | mitigate | `A02` is generalised to all hooks rather than dropped; the predicate is stricter than the original |
| T-127-43 | Information Disclosure | a stale client sending `roles` and silently assigning nothing | mitigate | the picker sends `tenantRoleIds`; the backend refuses `roles` with an explicit 400 rather than ignoring it |
| T-127-SC | Tampering | npm installs | mitigate | no dependency added; acceptance criteria assert an empty diff on `web/package.json` dependencies and on `pnpm-lock.yaml`. The only `package.json` edit permitted in this plan is the `scripts` rename |
