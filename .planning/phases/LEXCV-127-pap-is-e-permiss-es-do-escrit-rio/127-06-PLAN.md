<objective>
Land the frontend contract layer the rewritten screen will consume, before the screen itself — types,
Zod schema, the id-keyed unsaved-edit merge, and the query/mutation hooks — so the component work in
plan 07 is assembly rather than exploration.

Two things in here are load-bearing rather than plumbing.

First, the merge. Phase 125 already solved "do not silently discard an operator's unsaved checkbox
edits when an unrelated mutation invalidates the list query" in `merge-local-permissoes.ts`, keyed on
a numeric molde id. This screen has three mutations instead of one, and **rename is the new failure
mode**: it changes the one field a careless implementation might key the map on. The merge must stay
keyed on the role id; if anyone "simplifies" it to key on `nome`, renaming a role while another
role's checkboxes are unsaved silently loses the edits. That is the specific thing the unit test in
this plan exists to prevent.

Second, `use-admin.ts` still types itself against `@/server/mock-db`, which `CLAUDE.md` marks as
superseded pre-backend mock code. Every type in it is wrong now — `MockRole` is a closed union of
four literals, and office roles are an unbounded renameable list. Carrying that forward into the new
screen would bake the old model into the new one.

Purpose: a contract the component can be written against without reading backend Java.
Output: two type modules, one schema, one merge helper with a unit test, and a rewritten hook module
with no mock imports.
</objective>
