# Phase 33 — UI Design Contract

> Visual and interaction contract for Phase 33: Processos - Workflow, Gates e Prazos.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn / tailwind v4 |
| Preset | Anti-Safe Harbor (sharp edges, bold colors, no rounded corners) |
| Component library | radix-ui |
| Icon library | lucide-react |
| Font | var(--font-geist-sans) (Geist Sans) |

Source: inherited from Phase 32 UI-SPEC (approved). Confirmed by inspection of `web/src/components/ui/badge.tsx`, `button.tsx`, `card.tsx`, and `processos/page.tsx`.

No new shadcn components need to be added. Dialog is not currently present in `web/src/components/ui/` — it must be added via `npx shadcn add dialog` before implementation of the justification gate. ## Spacing Scale

Declared values (multiples of 4) — identical to Phase 32, inherited:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, icon-to-label gap in transition buttons |
| sm | 8px | Form item spacing inside Dialog, gap between action buttons in workflow card |
| md | 16px | Card inner padding (CardContent), input internal padding |
| lg | 24px | Card padding (CardContent `p-6`), workflow card section spacing |
| xl | 32px | Page-level section gaps between workflow card and prazos card |
| 2xl | 48px | Not used in this phase |

Exceptions:
- Transition action buttons (e.g. "Ativar Processo", "Suspender") must have minimum 44px height for touch accessibility.
- Prazo list rows: `py-3 px-4` (12px vertical / 16px horizontal) to keep the list dense without feeling cramped.

Source: Phase 32 UI-SPEC (spacing scale). Confirmed in `processos/page.tsx` (`p-5`, `p-6`, `space-y-6`).

## Color

Identical to Phase 32 — inherited:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #f8fafc (Light) / #020617 (Dark) | Page background, table body, dialog body, form fields |
| Secondary (30%) | #ffffff (Light) / #0f172a (Dark) | Cards (`Card`), sidebar, filter bar bg, dialog background |
| Accent (10%) | blue-600 (#2563eb) | Normal (edit-level) transition action buttons ("Ativar Processo"), active pagination dot, focus ring on inputs (`focus-visible:ring-blue-500`), "Novo Prazo" primary CTA |
| Destructive | red-600 (#dc2626) | Validation errors (RHF field messages), gate-blocked reason text |

Accent reserved for: primary action CTA buttons requiring only `processos:edit` permission, input focus rings, active pagination control. Not used for critical/manage-level transitions or for informational text.

### Workflow State Badge Color Mapping

Reuses existing badge variants from `web/src/components/ui/badge.tsx`. No new variants required.

| Estado | Badge Variant | Visual Signal |
|--------|---------------|---------------|
| `TRIAGEM` | `purple` | Em triagem (intake pending) — inherited from Phase 32 |
| `ATIVO` | `green` | Active process — primary working state |
| `SUSPENSO` | `amber` | Suspended — reversible, caution |
| `ENCERRADO` | `gray` | Closed — terminal |

Source: existing `estadoVariant` mapping in `processos/page.tsx`. No changes needed to this mapping.

### Prazo Risk Badge Color Mapping

Three risk levels derived by the backend. Helper function `prazosRiscoToVariant` and `prazosRiscoToLabel` go into `web/src/lib/prazos.ts` — analogous to `lib/conflict-check.ts`.

| Risco Level | Badge Variant | Visual Signal |
|-------------|---------------|---------------|
| `ok` | `green` | Deadline comfortably in the future |
| `proximo` | `amber` | Deadline approaching — action recommended |
| `vencido` | `red` | Deadline passed — action required immediately |

### Transition Action Button Distinction

| Transition Type | Required Permission | Button Appearance |
|-----------------|--------------------|--------------------|
| Normal (e.g. ativar, atualizar responsável) | `processos:edit` | `bg-blue-600 hover:bg-blue-700 text-white rounded-none font-bold` (primary fill) |
| Critical (suspender, encerrar, reabrir) | `processos:manage` | `variant="outline" border-slate-300 dark:border-slate-700 rounded-none font-bold text-slate-700 dark:text-slate-300` (outline, neutral — avoids alarm when not yet pressed) |
| Any transition — insufficient permission | — | `disabled opacity-50 cursor-not-allowed` + tooltip (14px, slate-500): "Sem permissão: requer processos:edit/manage" |

## Layout: Processo Detail Page — New Sections

Two new sections are added to `/processos/{id}/page.tsx`, inserted between the existing "Dados" card and the tab panel (Partes / Fases / Movimentações).

### Section 1: Workflow Card

**Card header:** "Workflow" (CardTitle, left-aligned) + current estado badge (right-aligned, same variant mapping as listing).

**Card body** (`CardContent`, `space-y-4`):

**Row 1 — Estado + Responsável (dl grid, `grid-cols-3 gap-x-4 gap-y-3 text-sm`):**

| Field | Value |
|-------|-------|
| Estado | Current estado badge |
| Responsável | User display name (or "Não atribuído" in `text-slate-400` italic if null) |
| Próximo passo | Free-text string returned by backend (derivado do mapa de estado) or "—" |

**Row 2 — Transições disponíveis** (rendered immediately below the dl grid, `pt-4 border-t border-slate-200 dark:border-slate-800`):

Section label: `text-[11px] font-bold tracking-wider uppercase text-slate-500 dark:text-slate-400` → "AÇÕES DE TRANSIÇÃO"

Transitions are rendered as a horizontal flex row (`flex flex-wrap gap-2`). Each transition is a Button:

- Normal transitions (edit-level): primary filled blue button.
- Critical transitions (manage-level): outline neutral button.
- Disabled when user lacks required permission: `disabled opacity-50 cursor-not-allowed` with a `title` attribute as tooltip (no Tooltip component needed).
- No transitions available (terminal state or all blocked): render `text-sm text-slate-500 dark:text-slate-400` "Nenhuma transição disponível neste estado."

**Justification Dialog** (opens when a critical transition button is clicked):

Uses a Dialog (to be added via `npx shadcn add dialog`). Layout:

- `DialogHeader`: `DialogTitle` = transition label (e.g. "Suspender Processo")
- `DialogDescription` = "Esta ação requer justificativa e regista uma movimentação no processo."
- `DialogContent` body:
  - `Label` + `Textarea` (`min-h-[100px]`, `rounded-none`, `border-slate-300 dark:border-slate-700`), id="justificativa", required.
  - RHF field: `justificativa` — Zod: `z.string().trim().min(10, "Justificativa deve ter pelo menos 10 caracteres")`.
  - Below textarea: `text-sm text-red-600` RHF error message if validation fails.
- `DialogFooter`:
  - `Confirmar` button (primary, `rounded-none font-bold bg-blue-600 hover:bg-blue-700`), submits the transition.
  - `Cancelar` button (ghost, `rounded-none`), closes Dialog without action.
  - During submission: Confirmar shows `disabled opacity-50` + in-button text "A processar...".

**Loading state (whole workflow card):** Replace card body with `text-sm text-slate-500 dark:text-slate-400` "A carregar workflow...".

**Error state (whole workflow card):** `text-sm text-red-600` "Erro ao carregar o workflow. Tente novamente."

### Section 2: Prazos Card

**Card header:** "Prazos" (CardTitle, left-aligned) + "Novo Prazo" Button (right-aligned, primary blue, `rounded-none font-bold`, `Plus` icon — visible only when `processos:edit` permission present).

**Card body** (`CardContent p-0`):

When prazos exist: a flat list (`divide-y divide-slate-100 dark:divide-slate-800`). Each prazo row:

```
px-4 py-3 flex items-center justify-between gap-4 hover:bg-slate-50/50 dark:hover:bg-slate-800/20 transition-colors
```

Row layout:

- **Left:** descricao (`font-medium text-sm text-slate-900 dark:text-white`) stacked over data_limite (`text-xs text-slate-500 dark:text-slate-400`, formatted as `pt-CV` locale date).
- **Center/meta:** prioridade tag (`text-[11px] font-bold tracking-wider uppercase text-slate-500 dark:text-slate-400` — values: ALTA / MÉDIA / BAIXA) + responsável name (`text-xs text-slate-500`) side by side with `gap-2`.
- **Right:** Risco badge (green/amber/red from `prazosRiscoToVariant`) + escalonado indicator (if `escalonado === true`: `AlertCircle` icon 14px `text-amber-600 dark:text-amber-400` with `title="Prazo escalado"`) + concluido checkbox (a `Check` circle icon, `text-emerald-600` when true, `text-slate-300` when false, toggling concluido state via mutation — visible only when `processos:edit`).

Ordered by `data_limite` ascending (soonest first, vencido items at top due to past dates).

**Empty state:** `p-6 text-sm text-slate-500 dark:text-slate-400` "Nenhum prazo registado para este processo."

**"Novo Prazo" inline form (Dialog):**

- `DialogTitle`: "Novo Prazo"
- Fields (`space-y-4`):
  - `Descrição` — Input, required (`z.string().trim().min(1, "A descrição é obrigatória")`).
  - `Data limite` — `<input type="date">` styled to match project select className (`h-10 w-full bg-white dark:bg-[#020617] rounded-none border border-slate-300 dark:border-slate-700 px-3 text-sm focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-blue-500`), required.
  - `Prioridade` — `<select>` with options: `ALTA`, `MEDIA`, `BAIXA`. Default: `MEDIA`.
  - `Responsável` — `<select>` populated from user list. Optional.
- `DialogFooter`: "Guardar Prazo" (primary) + "Cancelar" (ghost).

## Processos Listing: New Columns / Signals

The existing processos listing table at `/processos/page.tsx` receives three new signals. These are added as additional content within or alongside existing cells — **no new table columns** to preserve horizontal space on narrower viewports.

| Signal | Placement | Rendering |
|--------|-----------|-----------|
| Responsável | Below the "Entrada: …" date sub-line in the NÚMERO column cell | `text-[11px] font-medium text-slate-400 dark:text-slate-500` prefix "Resp.:" + user display name, or "—" if unset |
| Prazo risk | Below the estado Badge in the ESTADO cell | Risco badge (`rounded-none font-bold tracking-wide text-[11px]`) — only when `riscoMaisCritico` is `proximo` or `vencido` (hidden when `ok` or no prazos). If `vencido`: red badge "PRAZO VENCIDO". If `proximo`: amber badge "PRAZO PRÓXIMO". |
| Escalado flag | Inline next to the risco badge | `AlertCircle` icon 12px `text-amber-500` when `escalonado === true` |

Source for placement pattern: existing sub-line in `processos/page.tsx` (line ~330: `text-[11px] font-medium tracking-wider uppercase text-slate-500`).
