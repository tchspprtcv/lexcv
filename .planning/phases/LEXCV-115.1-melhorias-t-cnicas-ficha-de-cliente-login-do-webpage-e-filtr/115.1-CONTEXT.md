<decisions>
## Implementation Decisions

### Área 1: Criar Processo/Parecer a partir da Ficha de Cliente
- Botão "Novo Processo" no cabeçalho de `ClienteProcessosTab` (mesmo padrão visual do botão "Adicionar" de `ClienteDocumentosEntreguesTab`), navega para `/processos/novo?clienteId={id}`
- Botão "Novo Parecer" no cabeçalho de `ClienteParecerTab`, navega para `/pareceres/nova?clienteId={id}` — mesmo padrão, por simetria
- Ambos os formulários de criação passam a ler `clienteId` via `useSearchParams`, pré-selecionam o NativeSelect de Cliente correspondente, e bloqueiam esse campo para edição (evita troca acidental de cliente)
- RBAC: `processos:create` / `pareceres:create` respetivamente — mesmo scope já usado nos botões "Novo" das páginas de listagem

### Área 2: Redirect "Entrar" do Webpage → Login do Web
- Diagnóstico aceite: o link já aponta para `/login` relativo nos 4 pontos, e tanto `Caddyfile` como `Caddyfile.prod` já fazem proxy correto para a app `web` em produção — o gap reportado é consistente com dev local (webpage a correr isolado, sem Caddy à frente, sem rota `/login` própria)
- Corrigir para funcionar corretamente em dev local, preservando o comportamento já correto em produção
- Mecanismo: nova env var pública `NEXT_PUBLIC_WEB_APP_URL` em `webpage/`, com fallback para `/login` relativo quando não definida (produção não precisa de a definir)
- Extrair a lógica para um helper partilhado (ex. `getLoginUrl()`) em vez de repetir em `site-header.tsx` (×2), `hero-section.tsx`, `site-footer.tsx`
- Documentar a nova variável em `webpage/.env.example`

### Área 3: Alinhamento Visual dos Filtros de Pareceres
- Painel "Filtros": trocar `Select`/`SelectItem` por `NativeSelect`, replicando o padrão já usado em Processos/Clientes
- Painel "Pesquisa Avançada": substituir `<input>`/`<label>` em bruto pelos primitivos `Input`/`Label` (sem alterar comportamento)
- Botões Aplicar/Limpar **mantêm-se com texto** — NÃO tornar ícone-only. Decisão já bloqueada na Phase 115 (`115-CONTEXT.md`): "não expandir a Pareceres/Notificações mesmo que tenham padrões semelhantes, mantendo o âmbito literal do requisito"
- Estrutura de contentor (Card > CardContent p-4 > form flex flex-wrap) já é idêntica à de Processos — nenhuma mudança necessária aí
- O toggle duplo "Filtros"/"Pesquisa Avançada" (que Processos/Clientes não têm) é uma funcionalidade legítima e existente desde a Phase 69 — não remover

### Claude's Discretion
- Nome exato do helper de Área 2 (`getLoginUrl()` ou equivalente) e a sua localização (`webpage/src/lib/`)
- Detalhe visual fino do botão "Novo Processo"/"Novo Parecer" (variant/tamanho) desde que siga o padrão já usado em Documentos Entregues

## Existing Code Insights

### Reusable Assets
- `ClienteDocumentosEntreguesTab` (`web/src/app/(dashboard)/clientes/[id]/page.tsx`, linha ~1264+) — único separador da ficha que já tem um botão "Adicionar" (linhas 1337-1340, abre `Dialog`); referência visual para os novos botões, embora Processo/Parecer usem navegação em vez de modal
- `webpage/src/lib/backend-origin.ts` / `setup.ts` / `branding.ts` — padrão já estabelecido de resolver origem via env var absoluta para chamadas server-to-server; `NEXT_PUBLIC_WEB_APP_URL` deve seguir o mesmo espírito (mas é client-side/`NEXT_PUBLIC_`, não server-to-server)
- `NativeSelect`/`Input`/`Label` primitivos shadcn já usados consistentemente em Processos/Clientes — cópia direta para Pareceres
