<objective>
Área 2 — Corrigir o redirect da ação "Entrar" do webpage público para o login da app web.

Today the 4 "Entrar" call sites in `webpage/` hard-link to the relative `/login`. In production this is correct (Caddy proxies `/login` to the `web` app), but in local dev the `webpage` runs isolated (no Caddy, no own `/login` route) so the link 404s. Introduce a new public env var `NEXT_PUBLIC_WEB_APP_URL` and a shared client-safe helper `getLoginUrl()` that returns `{NEXT_PUBLIC_WEB_APP_URL}/login` when set and falls back to the relative `/login` when unset — so production behavior is byte-identical and local dev can point at the running `web` app.

Purpose: Closes reported gap #2 (broken "Entrar" in local dev) without changing the already-correct production routing.
Output: 1 new helper file, 1 documented env var, 4 call sites rewired across 3 component files. Zero visual change.
</objective>
