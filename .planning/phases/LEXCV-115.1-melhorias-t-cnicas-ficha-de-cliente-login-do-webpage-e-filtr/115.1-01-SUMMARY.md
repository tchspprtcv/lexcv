# Phase 115.1 Plan 01: Criar Processo/Parecer a partir da Ficha de Cliente Summary

**Two RBAC-gated "Novo Processo"/"Novo Parecer" buttons in the cliente ficha's Processos/Pareceres tabs, each deep-linking to the corresponding create form with the cliente pre-selected and its field locked via a new `?clienteId=` query param read through `useSearchParams`.**

## Accomplishments
- `ClienteProcessosTab`/`ClienteParecerTab` (`clientes/[id]/page.tsx`) each gained a right-aligned, RBAC-gated (`processos:create`/`pareceres:create`) header button above their existing `Card`, visually matching `ClienteDocumentosEntreguesTab`'s "Adicionar" (`variant="outline"`, `size="sm"`, `Plus` icon) — not the bolder list-page CTA style
- Both buttons navigate to `/processos/novo?clienteId={id}` / `/pareceres/nova?clienteId={id}` with `encodeURIComponent(clienteId)`
- `/processos/novo` and `/pareceres/nova` both now read `clienteId` via `useSearchParams`, seed their respective form's Cliente default (`cliente_id` snake_case mapping for Processos, direct `clienteId` match for Pareceres), disable the Cliente `NativeSelect` when the param is present, and show an identical muted helper hint
- Pareceres' "Processo (opcional)" dropdown auto-populates once `clienteId` is pre-filled, with zero additional wiring (confirmed pre-existing reactive dependency: `useProcessos(clienteIdValue ? { cliente_id: clienteIdValue } : {})`)
- Both forms remain byte-behavior-identical to before when opened without the query param (field enabled, empty default, no helper text)
- Whole-app `pnpm build` (Turbopack) compiles and typechecks cleanly, all 24 routes generate successfully
- Project-wide `pnpm lint` confirms zero NEW errors/warnings on any of the 3 modified files (all pre-existing findings independently verified via `git diff` and logged, not fixed, per Scope Boundary)
