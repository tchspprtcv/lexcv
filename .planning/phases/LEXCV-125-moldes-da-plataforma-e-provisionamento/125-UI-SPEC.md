# Phase 125 — UI Design Contract

> Visual and interaction contract for `/plataforma/moldes`, the internal console where `PLATAFORMA_ADMIN` manages role moldes and sees their non-propagation guarantees. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Recap (from CONTEXT.md / ROADMAP.md / REQUIREMENTS.md)

- Audience: `PLATAFORMA_ADMIN` only — same gate already enforced by every screen under `/plataforma` (page-level UX mirror of the backend `hasRole('PLATAFORMA_ADMIN')` class-level `@PreAuthorize`). This is an internal operator tool, not a customer surface: optimize for "cannot be misread," not for polish.
- Must support: list moldes (MOLD-02), edit a molde's permission set as a permission×molde matrix reusing `RbacTab`'s shape (MOLD-02, MOLD-03), create a new molde inline following `criar-tenant-panel.tsx` (MOLD-04).
- `PLATAFORMA_ADMIN` is never a molde — never listed, never a matrix column, never a creatable name.
- The single most important element: the non-propagation warning at save time, with a per-molde count of already-instantiated offices, in both directions (offices affected = 0 is reassuring, not alarming; offices affected > 0 is the moment the operator must not misread as "these update too").
- Entry point: a button in `/plataforma`'s `CardHeader`, next to "Ver Relatório" and "Criar Tenant", exactly as "Ver Relatório" already works.

## Screen Structure

### 1. Entry point — `/plataforma` (`PlataformaPageContent`, `CardHeader` action row)

Add a third button to the existing action row (`web/src/app/(dashboard)/plataforma/page.tsx:168-182`), ordered by read-before-create precedent already established:

```
[ Gerir Moldes ]  [ Ver Relatório ]  [ Criar Tenant ]
  outline, icon: LayoutTemplate        outline, icon: FileChartColumn      solid blue, icon: Plus
```

- `Gerir Moldes` is `variant="outline"`, same sizing/classes as the existing "Ver Relatório" `Button asChild` + `Link href="/plataforma/moldes"`, icon `LayoutTemplate` (lucide-react) at `h-4 w-4`, label "Gerir Moldes".
- Placed **before** "Ver Relatório" — both are outline/secondary reads relative to the primary blue "Criar Tenant" — but moldes management is the more structurally significant of the two read/manage surfaces, so it leads.

### 2. `/plataforma/moldes` — page shell

Structural parent: `relatorio/page.tsx` (back-arrow breadcrumb header), because this is a sub-route of `/plataforma`, not a peer console — same as the relatório page.

```
[ ← ]  Moldes de Papel da Plataforma
       Defina os conjuntos de permissões que cada escritório novo recebe
       automaticamente ao ser provisionado.
```

- `ArrowLeft` button linking back to `/plataforma`, identical markup to `relatorio/page.tsx:70-78`.
- `h1` at `text-3xl font-semibold tracking-tight` (matches `relatorio`'s heading weight — note `relatorio` uses `font-semibold` not `font-bold`, unlike the parent `/plataforma` page's `font-bold`; **follow `relatorio`'s weight since this is its structural sibling**).
- Subtitle `text-sm text-slate-500 dark:text-slate-400`.
- Same page guard as `relatorio/page.tsx` and `/plataforma/page.tsx`: `if (!me.isFetched) return null;` then `AccessDeniedState` if `PLATAFORMA_ADMIN` is absent, using description `"Não tem permissão para aceder à gestão de moldes de papel."` and `backHref="/dashboard"`. This is a UX mirror only — the authority boundary is the backend's class-level `@PreAuthorize` on `PlatformAdminController`.

### 3. Main card — matrix view (default state)

One `Card` (`border-slate-200 dark:border-slate-800 bg-white/50 dark:bg-slate-900/50 backdrop-blur-sm rounded-xl`), structured like `RbacTab`, not like the tenant `DataTable`:

```
CardHeader (flex-row, justify-between)
  ├─ CardTitle "Matriz de Moldes"
  ├─ CardDescription "Permissões atribuídas a cada molde. Escritórios já
  │   provisionados não são afetados por alterações feitas aqui."
  └─ [ Criar Molde ]  [ Guardar Alterações ]
       outline, Plus     solid blue, Save — disabled until the matrix has
                          unsaved local edits (dirty-check against fetched
                          state, same pattern as RbacTab's
                          localRolePermissions vs. fetched rolePermissions)

CardContent
  ├─ Non-propagation banner (persistent, always visible — see below)
  └─ Permission × molde matrix table (see below)
```

Why a matrix, not per-row edit dialogs: CONTEXT.md locks this explicitly ("A edição de um molde é uma matriz de checkboxes permissão × molde, reaproveitando a forma já validada do RbacTab"). This is a deliberate deviation from the tenant `DataTable` + `Dialog` pattern used elsewhere in `/plataforma` — do not "fix" it toward that pattern.

**Loading / error states** (identical recipe to `RbacTab`, lines 774-803):
- Loading: centered `Loader2` spinner, `h-48` container.
- Error: centered `AlertCircle` (red) + `"Não foi possível carregar os moldes de papel."` + outline "Tentar novamente" button calling `refetch()`.
- Empty (defensive — realistically never hit since 4 moldes are always seeded, but declared per contract): centered `Empty`/`EmptyHeader`/`EmptyTitle`/`EmptyDescription` primitives (`components/ui/empty.tsx`, already in the project) — title "Nenhum molde definido", description "Crie o primeiro molde para que os próximos escritórios provisionados nasçam com papéis prontos a atribuir.", with a "Criar Molde" button inside `EmptyContent`.

### 4. Non-propagation banner (the single most important element)

Persistent, **always visible** above the matrix — not something that only appears on save. Ambient awareness first, explicit confirmation second (defense in depth against the default wrong assumption).

```tsx
<div className="p-4 bg-amber-50 dark:bg-amber-500/10 text-slate-700 dark:text-slate-300 text-xs border border-amber-200 dark:border-amber-500/30 rounded-md flex items-start gap-2.5">
  <TriangleAlert className="h-4 w-4 mt-0.5 text-amber-600 dark:text-amber-400 flex-shrink-0" />
  <div>
    <strong>Alterar um molde não atualiza escritórios já criados.</strong>{" "}
    Cada escritório recebe, no momento em que é provisionado, uma cópia
    própria e independente de cada molde (snapshot) — editar o molde depois
    disso não muda essa cópia. Só os escritórios provisionados a partir de
    agora recebem o conjunto de permissões que gravar aqui.
  </div>
</div>
```

Icon: `TriangleAlert` (lucide-react) — deliberately distinct from `ShieldAlert`, which `RbacTab` already uses for its blue/neutral "Nota Importante" box, so the two informational registers (neutral note vs. amber caution) stay visually distinguishable across the app.

### 5. Matrix table

Structurally identical to `RbacTab` (`settings/page.tsx:919-990`): `<table>` with `overflow-x-auto` wrapper, module-grouped rows, one column per molde. The differences from `RbacTab`:

- **Columns are dynamic**, not the hardcoded `["ADMIN", "TECNICO", "ADVOGADO", "ASSISTENTE"]` array — they come from the fetched moldes list (`GET /platform/moldes`), because MOLD-04 requires newly created moldes to appear here too. `PLATAFORMA_ADMIN` is never in this list (backend guarantee per CONTEXT.md); the UI does not need its own filter, but if the API ever regressed and returned it, that row/column must never render (defense in depth — filter it out client-side too, mirroring the `RbacTab` precedent of defending in the UI even when the backend already blocks something).
- **No row is immutable/pre-checked-and-locked.** `RbacTab` special-cases the `ADMIN` global role as always-on because it's the platform's fixed superuser row. Moldes have no such row — every molde's permission set is fully editable by `PLATAFORMA_ADMIN` (including a molde literally named "ADMIN", which is just an office's default administrator template, not the platform role). Do not port the `isAdminRow` lock-in logic.
- **No read-only branch.** `RbacTab` renders a disabled matrix + "Gerido pela Plataforma" badge for non-`PLATAFORMA_ADMIN` viewers, because that tab is shared with tenant admins. This page is reached only by `PLATAFORMA_ADMIN` (page-level guard above), so that branch does not exist here — every viewer of this page can edit.
- **Column header carries the instantiation count**, ambient and always visible (this is what lets the operator "see the scope of what is NOT being changed" without opening the save dialog):

```tsx
<th key={molde.id} className="p-3 font-bold text-center text-slate-700 dark:text-slate-300 text-xs tracking-wider">
  <div className="flex flex-col items-center gap-1">
    <span>{molde.nome}</span>
    <Badge variant={molde.escritoriosInstanciados > 0 ? "amber" : "gray"} className="text-[10px] font-semibold">
      {molde.escritoriosInstanciados > 0
        ? `${molde.escritoriosInstanciados} escritório${molde.escritoriosInstanciados === 1 ? "" : "s"}`
        : "0 escritórios"}
    </Badge>
  </div>
</th>
```

Data contract assumption this UI-SPEC imposes on the API: the moldes list payload must carry a per-molde instantiated-office count (e.g. `escritoriosInstanciados: number`, derived from `t_tenant_role` rows whose `molde_id` points at this molde). This is the load-bearing number for the entire "impossible to misread" requirement — flag it to the planner as a required field, not an optional nicety.

- Checkbox cells: identical markup/classes to `RbacTab` (`h-4 w-4 text-blue-600 ... rounded`), minus the `isDisabled`/`isAdminRow` branching described above.

### 6. Save flow — confirmation is mandatory, not optional

Clicking "Guardar Alterações" (blue, in `CardHeader`) does **not** call the mutation directly. It opens an `AlertDialog` that must be explicitly confirmed. This is the acknowledgement gate — the moment identified in the design brief as the one that must be impossible to miss.

The dialog content is **dynamic**, built from a diff between the locally edited matrix and the last-fetched matrix (same `localRolePermissions` vs. fetched-state diffing pattern as `RbacTab`, generalized to a `Record<moldeId, Set<permissionKey>>`). Only **changed** moldes are listed — an operator who only touched `ADVOGADO` should not have to read about `ASSISTENTE`.

```
AlertDialogHeader
  Title: "Confirmar alterações aos moldes"
  Description: "Vai gravar alterações de permissões nos moldes abaixo. Esta
                gravação não altera nenhum papel já copiado para um
                escritório existente — só afeta escritórios provisionados a
                partir de agora."

<ul> (outside AlertDialogDescription, one row per changed molde)
  For each changed molde, one row:
    - escritoriosInstanciados > 0:
      "{NOME} — {N} escritório(s) já têm uma cópia própria deste molde.
       Nenhum deles é alterado por esta gravação."
    - escritoriosInstanciados === 0:
      "{NOME} — 0 escritórios instanciaram este molde ainda. Esta alteração
       não tem impacto em nenhum escritório existente."
  (rendered with a small TriangleAlert or a plain bullet — amber text for
   the >0 case, slate/neutral text for the 0 case, so the friendlier case
   reads visibly calmer, not just semantically calmer)

AlertDialogFooter
  [ Cancelar ]  (outline, AlertDialogCancel)
  [ Confirmar e Gravar ]  (bg-amber-600 hover:bg-amber-700 text-white,
                            AlertDialogAction — amber, not blue: this is the
                            exact decision point the warning exists for, so
                            the confirm button itself carries the caution
                            color, not the routine blue used everywhere else
                            in the app for "Guardar")
```

On success: `toast.success("Moldes atualizados com sucesso.")`, close dialog, invalidate the moldes query (same `queryClient.invalidateQueries` pattern as `use-platform-admin.ts`).

On failure: the shared `apiFetch` wrapper already surfaces the backend's error message as a toast — **keep the `AlertDialog` open** (do not close it on error), matching the established convention in `plataforma/page.tsx`'s tenant-status `AlertDialog` ("mantemos o AlertDialog aberto"), so the operator can retry without re-diffing the matrix.

The "Guardar Alterações" trigger button itself is **disabled when there is no local diff** — an operator cannot open a consequential confirmation dialog over a no-op save.

### 7. Create molde — inline panel

Structural parent: `criar-tenant-panel.tsx`, per CONTEXT.md. Replaces the matrix `Card` in-place when "Criar Molde" is clicked (`isFormOpen` boolean state on the page, exact same pattern as `PlataformaPageContent`'s `isFormOpen`/`CriarTenantPanel` swap) — **not a `Dialog`**, matching the precedent's own reasoning (this panel needs width for a grouped permission checklist, same as the tenant panel needed width for the logo upload).

```
Card
  CardHeader (flex-row, justify-between)
    ├─ CardTitle "Criar Molde"
    ├─ CardDescription "Registe um novo molde de papel disponível para
    │   escritórios provisionados a partir de agora."
    └─ [ X ]  (ghost, rounded-full, aria-label "Fechar" — identical to
               criar-tenant-panel.tsx's close button)

  CardContent (space-y-6)
    ├─ Label "Nome do Molde"
    │  Input placeholder "Ex.: SUPERVISOR"
    │  helper text: "Maiúsculas, sem espaços — como os moldes existentes
    │   (ADMIN, ADVOGADO, TECNICO, ASSISTENTE)."
    │  Zod validation: non-empty, trimmed, transformed to uppercase on
    │  submit (mirrors criar-tenant-panel's `adminEmail.toLowerCase()`
    │  transform-on-submit convention), and explicitly rejects the literal
    │  value "PLATAFORMA_ADMIN" (case-insensitive) with the error message
    │  "Este nome está reservado à plataforma e não pode ser usado como
    │  molde." — a UX mirror of the backend's non-instantiable guard, not
    │  the authority boundary itself.
    │
    └─ Label "Permissões Iniciais"
       Grouped-by-module checkbox list, one column (this molde only) —
       same visual grouping as the matrix's module-separator rows, but
       rendered as a single scrollable list (`max-h-72 overflow-y-auto`),
       matching the existing single-column permission checklist already
       shipped in `settings/page.tsx:697-724` (the "Permissões
       Customizadas" picker), not the matrix's multi-column table — there
       is only one molde being defined here.

  CardFooter (border-t, justify-end, gap-3)
    [ Cancelar ]  (outline)
    [ Criar Molde ]  (solid blue, disabled while isSubmitting, label
                       "A criar..." while pending — same convention as
                       "A criar..." in criar-tenant-panel.tsx)
```

No non-propagation warning is needed on this panel — a molde that does not exist yet has, by definition, zero instantiated offices. The warning is specific to *editing an existing* molde; creation is uncomplicated and should not be burdened with a caveat that does not apply to it.

On success: `toast.success('Molde "{NOME}" criado com sucesso. Fica disponível para escritórios provisionados a partir de agora.')`, close the panel, invalidate the moldes query. On failure (e.g. duplicate name): the shared `apiFetch` toast fires and the panel stays open with the operator's input intact — same recovery convention as `CriarTenantPanel`'s own submit handler in `page.tsx`.

## Open Discretion Notes (Claude's Discretion, recorded per `<design_contract_questions>`)

These were not answered by CONTEXT.md/REQUIREMENTS.md and were decided here, consistent with the existing console:

1. **Entry button placement and icon** — chosen "Gerir Moldes" with `LayoutTemplate`, positioned before "Ver Relatório". Reason: read/manage actions precede the primary create action in the existing header, and moldes management is a configuration surface, closer in weight to reporting than to tenant creation.
2. **Confirm-button color (amber, not blue or red)** — reasoned above: not destructive (red), not routine (blue) — a third, deliberately distinct "caution" semantic, reusing the amber recipe already established elsewhere in this codebase (`processos/novo/page.tsx`) rather than inventing a new hex.
3. **New-molde name casing convention (forced uppercase)** — inferred from the four existing seeded molde names all being uppercase; enforced via a submit-time transform (same technique as the existing `adminEmail.toLowerCase()` convention), not by disabling lowercase input, to keep the field feeling ordinary to type into.
4. **Per-molde instantiation count is ambient (column header), not just inside the confirmation dialog** — the design brief asks the operator to "see the scope of what is NOT being changed"; putting it only inside a modal that appears at save time would mean the operator only learns the scope *after* deciding to change something. Showing it ambiently, on every view of the matrix, lets the number inform the decision, not just the confirmation of an already-made decision.
5. **No search/filter input on this page** — unlike `/plataforma` and `/plataforma/relatorio`, which search a tenant list that can grow unboundedly, the moldes list is small and grows slowly (a handful of moldes per platform lifetime). A search box would be visual noise with no reuse case yet.
