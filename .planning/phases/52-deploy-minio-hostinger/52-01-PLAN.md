Modificar docker-compose.yml com duas alterações:

1. Adicionar serviço `minio` após o serviço `postgres` e antes do `backend`:

```
  minio:
    image: minio/minio:latest
    container_name: lexcv_minio
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
    volumes:
      - lexcv_minio_data:/data
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:9000/minio/health/live || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - lexcv_net
    restart: unless-stopped
```

Não expor portas — o acesso ao S3 API (9000) é interno à rede lexcv_net; o acesso à consola (9001) é via Caddy.

a) Adicionar `minio` à secção `depends_on` do backend (junto ao postgres já existente):
```
    depends_on:

        condition: service_healthy
      minio:
        condition: service_healthy
```

**docker-compose.prod.yml** — adicionar overlay para o serviço minio com resource limits e restart (seguindo o padrão dos outros serviços no ficheiro):

```yaml
  minio:
    restart: unless-stopped

      resources:
        limits:
          cpus: '0.5'
          memory: 512M
```

Não adicionar `image:` — minio usa a imagem pública diretamente do base compose (não é built pelo GHCR).

---

**Caddyfile.prod** — adicionar rota para a consola MinIO com basicauth, inserida ANTES do handle catch-all existente (handle { reverse_proxy frontend:3000 }). O bloco handle /minio-console* deve ser colocado entre o bloco /api/* e o catch-all:

```
    handle /minio-console* {
        basicauth {
            {$CADDY_MINIO_USER} {$CADDY_MINIO_PASSWORD_HASH}
        }
        reverse_proxy minio:9001
    }
```

O resultado final do Caddyfile.prod deve ter a ordem: handle /api/* → handle /minio-console* → handle (catch-all).

`CADDY_MINIO_USER` é o username em texto simples; `CADDY_MINIO_PASSWORD_HASH` é o hash bcrypt gerado com `caddy hash-password`. Ambos injetados via env vars do VPS — nenhum valor hardcoded (per MIN-10).

```yaml
  deploy:
    runs-on: ubuntu-latest
    needs: build-and-push
    if: github.ref == 'refs/heads/master'

    steps:
      - name: Deploy to VPS
        uses: appleboy/ssh-action@v1

```

O job só corre em push para master (`if: github.ref == 'refs/heads/master'`) — não corre em PRs. O `needs: build-and-push` garante sequência: imagens construídas e publicadas antes do deploy.
