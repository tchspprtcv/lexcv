## Spacing Scale

Declared values (must be multiples of 4), identical to Phase 65/66 — confirmed already in use across `documentos/novo/page.tsx` and `processos`/`clientes` pages:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (label-to-input gap `space-y-2`, progress label row) |
| md | 16px | Default element spacing (form field gaps `space-y-4`) |
| lg | 24px | Section padding (root wrapper `space-y-6`, card-to-card gap between timeline and new-version form) |
| xl | 32px | Layout gaps (between major page sections) |
| 2xl | 48px | Major section breaks (rare) |
| 3xl | 64px | Page-level spacing (not needed at this scale) |

Exceptions: none. The "Nova Versão" card uses `space-y-4` internally (matches `documentos/novo/page.tsx`'s form spacing exactly) and sits below the version timeline with the page root's standard `space-y-6` gap.

## Typography

Matches Phase 65's contract verbatim — same module, same page (`pareceres/[id]/page.tsx`), must stay visually consistent. Only two weights: 400 (regular) and 700 (bold).

**Correction from Phase 66's aspirational claim:** the base `CardTitle` component (`web/src/components/ui/card.tsx:28-34`) renders `font-semibold` (600) with no explicit size — Tailwind's `h3` default. Phase 66's UI-REVIEW confirmed this override was never actually applied in shipped code, despite the spec claiming otherwise. This phase declares the override as **mandatory and executor-checked**: every `<CardTitle>` in the new "Nova Versão" section MUST carry an explicit `className="text-lg font-bold"`. This is not optional discretion — it is the fix for Phase 66's Top-3 finding #3, applied here so the same gap is not repeated.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / Label | 14px (text-sm) / 12px (text-xs) | 400 (regular) | 1.5 (body) / 1.4 (label) |
| Heading (page H1) | 30px (text-3xl, list) / 24px (text-2xl, sub-pages) | 700 (bold) | 1.2 |
| Section title (CardTitle: "Nova Versão", "Histórico de Versões") | 18px (`text-lg`, **explicit class required**) | 700 (bold, **explicit `font-bold` class required**) | 1.3 |
| Progress label ("A enviar... / N%") | 12px (text-xs) | 400 (regular) | 1.4 |

Weights used: 400 and 700 only. Do not introduce a third weight anywhere in this phase's new code.

## Color

Matches Phase 65/66's neutral/slate palette and the 60/30/10 split verbatim — same module. No new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / `dark:bg-neutral-950`-equivalent | Page background, card surfaces |
| Secondary (30%) | `slate-50`/`neutral-100` (light) — `slate-900`/`neutral-800` (dark) | Cards, section backgrounds |
| Accent (10%) | `blue-600` (`hover:bg-blue-700`) | Reserved for: **primary "Submeter Versão" button only**, and the **progress-bar fill** (`bg-blue-600`, matching `documentos/novo/page.tsx:177` exactly) |
| Destructive | `red-600` | Reserved for: **validation error text** (missing anexo, conteudo too short) and **submit-failure banner/toast only** |

Accent reserved for: the "Submeter Versão" primary button and the upload progress-bar fill. Never applied to labels, static text, drag-zone borders at rest, or decorative elements.

### Focus ring — corrected from Phase 66's mismatch

**Ground truth (verified directly in source, not assumed):** `web/src/components/ui/input.tsx` and `textarea.tsx` both declare `focus-visible:ring-2 focus-visible:ring-neutral-950` (light) / `dark:focus-visible:ring-neutral-300` (dark) — **not blue at all**. Phase 66's UI-REVIEW flagged a "blue-500 vs blue-600/700" mismatch because its own spec incorrectly asserted the ring should be blue; the actual shared `Input`/`Textarea` components have never used a blue ring. This phase declares the **correct, verified value**:

| Element | Focus-visible ring |
|---------|---------------------|
| `Textarea` (`conteudo` field) | `ring-neutral-950` (light) / `ring-neutral-300` (dark) — inherited from the shared component, do not override |
| `FileDropZone`'s internal "Clique para selecionar" trigger button | no custom focus ring; browser default outline is acceptable (component is unstyled for this state, unchanged from existing Documentos usage) |
| Drag-active state (dragging a file over the zone) | `border-blue-500 bg-blue-50` (light) / `dark:bg-blue-950` — this is the **drag-hover accent**, not a focus ring; verified in `file-drop-zone.tsx:54` and reused unmodified |

Do not introduce a blue focus ring anywhere in this phase's new code — match what `Input`/`Textarea` actually render.

### Focal points

- **Nova Versão form:** the "Submeter Versão" button is the primary CTA and sole `blue-600` interactive element when the form is enabled. The upload progress bar (when active) is the secondary visual anchor during submission — same `bg-blue-600` fill color reused for continuity, on a `bg-neutral-200`/`dark:bg-neutral-700` track, exactly matching `documentos/novo/page.tsx:169-181`.
- **Read-only ("CONCLUIDO") state:** when the solicitação's status is `CONCLUIDO`, the entire "Nova Versão" card is replaced by a neutral, non-interactive banner (see Copywriting Contract) — no accent color present at all in this state, reinforcing that no action is available.

## Copywriting Contract

Portuguese, direct tone, sentence case, no exclamation marks — consistent with Phase 65/66.

| Element | Copy |
|---------|------|
| Primary CTA | "Submeter Versão" (button label); pending state: "A submeter..." |
| Section title (form card) | "Nova Versão" |
| Textarea label | "Resumo da versão" |
| Textarea placeholder | "Descreva resumidamente o conteúdo desta versão (o parecer completo é submetido como anexo)." |
| Textarea helper text (below field, always visible) | "Este campo é um resumo — o documento completo deve ser enviado como anexo." |
| File upload label | "Anexo (obrigatório)" |
| File upload helper (below `FileDropZone`, when no error) | "Formatos aceites: PDF, Word, imagens." |
| Validation error — missing anexo | "É necessário anexar um ficheiro para submeter esta versão." |
| Validation error — conteudo too short | "O resumo deve ter pelo menos 10 caracteres." (mirrors Phase 66's exact 10-character threshold convention) |
| Progress label (during upload) | "A enviar... {N}%" (verbatim reuse of `documentos/novo/page.tsx:172-173` pattern) |
| Submit success toast | "Nova versão submetida com sucesso." |
| Submit error (inline banner + toast, dual-channel per Phase 66 pattern) | "Não foi possível submeter a versão. Verifique a ligação e tente novamente." |
| Read-only banner (status === CONCLUIDO, form hidden) | Heading: "Parecer já entregue" / Body: "Não é possível submeter novas versões após a entrega final." |
| Read-only banner (user is not advogado responsável nor ADMIN) | "Apenas o advogado responsável ou um administrador pode submeter novas versões." (form/card hidden entirely for this case — no button rendered, per CONTEXT.md's instance-check decision; this copy is optional and only needed if the team decides to show a passive explanation rather than omitting the section — default behavior is to omit the section silently, matching Phase 66's "no dead buttons" principle) |
| Timeline immutability (no change from Phase 65) | No edit/delete affordance copy needed — versions remain display-only, exactly as Phase 65 already established |

Destructive confirmation: not applicable this phase — version creation is additive, not destructive (no delete/edit of existing versions exists or is being added).
