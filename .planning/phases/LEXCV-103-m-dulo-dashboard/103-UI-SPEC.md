# Phase 103 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note (read first)

Phase 103 covers exactly one file: `web/src/app/(dashboard)/dashboard/page.tsx` (the main institutional Dashboard — not `processos/dashboard/page.tsx`, which is a different route and out of this phase's scope, see below). Requirements: **DASH-01** (Skeleton loading states) and **DASH-02** (Empty zero-data states).

**Verified-against-source correction to 103-CONTEXT.md's `code_context`:** CONTEXT.md's own text says the page has "texto 'A carregar...' bare em pelo menos 2 locais (KPI cards, Atividade Recente)." Direct read of the current `dashboard/page.tsx` shows this is **not accurate today** — there is no literal "A carregar..." string anywhere in this file (that string only exists in the *different*, out-of-scope `processos/dashboard/page.tsx`, which shows `<div className="p-8 text-slate-500">A carregar dashboard...</div>` while `isLoading`). The actual current state of `dashboard/page.tsx`:

- **KPI cards** (`DashboardKpis` component): calls `useDashboardKpis()` but never reads `.isLoading` — every number falls back to a bare `"—"` em-dash via `kpis.data?.total_clientes ?? "—"`, indistinguishable from a genuine zero or an error. This *is* a real gap DASH-01 closes, just not via literal "A carregar..." text — via a **missing** loading state, not present ad hoc text.
- **"Atividade Recente" card**: is **100% hardcoded static JSX** — three fixed entries ("Documento Submetido", "Novo Cliente", "Processo Concluído") with fake relative timestamps. It is not wired to any query, hook, or backend endpoint (confirmed: no `atividade`/`recent` hook exists in `web/src/hooks/`, and `DashboardKpis` type has no activity-feed field). This is a genuine, real limitation — flag it, don't silently fix it with invented backend/hook work (out of scope for a visual-only phase, matching the v2 deferred pattern already set by `DASH-V2-01`/`DASH-V2-02`).
- **"Prazos Urgentes" card**: real data (`useEventos({ concluido: false })`), and **already has** an ad hoc empty-state string today: `<div className="text-sm text-slate-500 dark:text-slate-400 italic">Sem urgências.</div>`. This is the cleanest, most concrete DASH-02 target — a real ad hoc message on real data, ready to become `Empty`.
- **"Processos Recentes" table** (`RecentProcessosCard`): real data (`useProcessos()`/`useClientes()`), but has **no empty-state markup at all** today — an empty `recentProcessos` array today just renders a `<TableBody>` with zero `<TableRow>`s (a blank table, not an ad hoc message, but still "no data with no proper Empty treatment").
- **"Status dos Processos"** card: a fully static, decorative chart-placeholder (`<div className="h-[260px] ... bg-[url('/grid.svg')]">`) with hardcoded legend — not data-bound at all (this is the Recharts/`DASH-V2-01` deferred item's future home). **Out of scope** for both Skeleton and Empty this phase — do not touch.

This correction does not change CONTEXT.md's locked decisions (Skeleton shape, no fade animation, Empty icon/copy tone) — it only corrects *where* those decisions apply in the real file, so planning/execution isn't blocked hunting for text that doesn't exist.

## Loading & Empty State Contract

This is the section that governs the actual implementation work this phase does (analogous to how `102-UI-SPEC.md`'s Color section governed its reconciliation work).

### Loading (DASH-01) — Skeleton, exactly 2 sections

| Section | Trigger | Skeleton composition (CONTEXT.md: "bloco retangular a imitar a forma real", not a generic bar) |
|---------|---------|----------------------------------------------------------------------------------------------|
| KPI cards (`DashboardKpis`) | `useDashboardKpis().isLoading` (already-called hook — read the `isLoading` field that today is discarded) | Per card, inside the same `Card`/`CardContent` shell (do not skeleton the Card chrome itself): row 1 = `<Skeleton className="h-10 w-10" />` (icon slot) + `<Skeleton className="h-5 w-14 rounded-full" />` (badge slot), right-aligned exactly like the real `flex items-start justify-between` row; row 2 (`mt-5`) = `<Skeleton className="h-3 w-24" />` (label line); row 3 (`mt-1`) = `<Skeleton className="h-8 w-16" />` (big number line). Render one skeleton card per *visible* KPI (respect the same RBAC `canView*` gates already used to decide which cards exist — do not skeleton a card the user isn't permitted to see). |
| "Atividade Recente" | Same `useDashboardKpis().isLoading` boolean — this is the **only** async signal that exists anywhere on this page today; reusing it (either by passing `isLoading` down as a prop from the parent, or calling `useDashboardKpis()` again in-place) gives a real, non-fabricated loading window. Calling the hook a second time is safe and free: TanStack Query shares cache/loading state by `queryKey: ["dashboard", "kpis"]`, so this is not a duplicate network request. | Exactly **3 rows** (matches the 3 real hardcoded entries below it, avoids layout shift on reveal — CONTEXT.md said "3-4," this spec fixes it at 3 for zero-shift parity with the real content). Each row mirrors the real `flex gap-4` shape: `<Skeleton className="h-10 w-10" />` (icon-chip slot) + a `min-w-0 pt-1` column with `<Skeleton className="h-4 w-40" />` (title line) and, below it (`mt-1.5`), `<Skeleton className="h-3 w-24" />` (timestamp line). |

**Explicitly out of Skeleton scope this phase** (per the literal ROADMAP/REQUIREMENTS text — "KPI cards e a secção 'Atividade Recente'," nothing else): "Prazos Urgentes," "Processos Recentes," and "Status dos Processos" do **not** get a Skeleton loading state this phase. Do not add one — that would be unrequested scope expansion of a deliberately narrow phase.

**No custom fade transition** (CONTEXT.md, explicit decision): swap Skeleton → real content on the same render React already produces when `isLoading` flips to `false`; do not add `transition`/`animate-in` wrapper classes around the swap.

### Empty (DASH-02) — broader than just Atividade Recente; applies to any section genuinely capable of holding zero items

| Section | Current state | Target | Copy (pt-PT/pt-CV) | Icon (`lucide-react`, `EmptyMedia variant="icon"` — neutral, no color override) |
|---------|---------------|--------|----|------|
