## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-03 | Elevation of Privilege | createVersao authorization | mitigate | Two-layer gate: `@PreAuthorize('pareceres:edit')` plus in-body check that caller is the assigned advogadoId or ADMIN (principal.getRoles().contains("ADMIN")); otherwise 403. Mirrors Phase 61 validateAdvogado pattern. |
| T-62-04 | Information Disclosure | cross-tenant version access | mitigate | Every endpoint loads the parent ParecerSolicitacao and rejects (404) when its tenantId != getTenantId(); version detail/download additionally assert version.solicitacaoId == path solicitacaoId. Entity also carries its own tenant_id (62-01) for defense-in-depth. |
| T-62-05 | Tampering | client-forged numeroVersao / criadoPorId / tenantId | mitigate | These fields are never bound from the request; numeroVersao is computed server-side under `synchronized(ParecerVersaoRepository.class)` (MAX+1), criadoPorId = principal.getUserId(), tenantId = getTenantId(). |
| T-62-06 | Tampering / path traversal | uploaded filename → object key | mitigate | StorageService.upload sanitises filename (`[/\\]` → `_`, T-50-01) before composing the object key; controller passes the raw filename through unchanged, relying on that existing mitigation. |
| T-62-07 | Denial of Service | storage outage during upload/download | accept | StorageUnavailableException is caught and surfaced as 503 (not a 500 stack leak); request fails cleanly. Upload size limits governed by existing Spring multipart config — unchanged this phase. |
</threat_model>
