# Phase 136 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope (4 small surfaces, NO new visual language: every token, class, badge variant, notice block, error pattern, dialog pattern and idempotency/inline-error convention is inherited verbatim from `134-UI-SPEC.md` and `135-UI-SPEC.md`, including their "Checker clarifications"):

1. Communication-state badge on the documents list (`web/src/app/(dashboard)/financeiro/documentos-fiscais/page.tsx` + `columns.tsx`) and on the document detail header (`.../documentos-fiscais/[id]/page.tsx`).
2. Detail page: new Card "Comunicação fiscal" (IUD as text + test-environment mark, last attempt/error summary, attempts count, "Reprocessar comunicação" button + confirm dialog).
3. Permanent "Modo simulado" banner on the fiscal pages while the backend reports `EFATURA_MODE=SIMULADO`.
4. In-app notification for persistent communication failure (new category) in the existing bell (`components/shared/notification-bell.tsx`) and `/notificacoes`.

Hooks: extend `web/src/hooks/use-faturacao.ts` with `useReprocessarComunicacao(documentoId)` (mutation, POST). Types in the existing faturacao types file: `EstadoComunicacao = "PENDENTE" | "ACEITE_SIMULADO" | "REJEITADO" | "ERRO"`, and on the document DTO a `comunicacao` object `{ estado, ambiente, iud, tentativas, ultimaTentativaEm, ultimoErro, proximaTentativaEm }`. Fiscal mode comes from a backend field (e.g. on the faturação/documents config response), never from a `NEXT_PUBLIC_` variable. Notification category: add `COMUNICACAO_FISCAL_FALHOU` to `NotificacaoCategoria` in `web/src/types/notificacoes.ts` and to the exhaustive `Record`s in `web/src/lib/notificacao-categoria.ts`. Sources: 136-CONTEXT.md (locked), 134-UI-SPEC.md, 135-UI-SPEC.md, REQUIREMENTS DFE-01..07.

Principle ("frontend burro", unchanged): the frontend NEVER derives communication state, IUD, attempts or the simulation mode. It renders values returned by the backend. Allowed client logic: formatting (Intl pt-CV, `dd/MM/yyyy HH:mm`), mapping `estado` -> label/variant through ONE module-level `Record<EstadoComunicacao, ...>`, and the exact-permission gate. The UI has no representation of "AUTORIZADO" at all (no label, no variant, no branch): if the backend ever returned an unknown estado, render the neutral fallback badge "Estado desconhecido" (outline), never a success style.

## Color

No new tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` #f8fafc / #020617 | Page background |
| Secondary (30%) | `--card`; slate-100/800 borders; `bg-slate-50 dark:bg-slate-900` for read-only blocks | Cards, table, dialog, IUD block, "Modo simulado" banner |
| Accent (10%) | `--primary` #2563eb / #3b82f6 | reserved list below |
| Destructive | `--destructive`, `text-red-600` / `dark:text-red-400` | Inline errors in the reprocess dialog banner only |

Accent reserved for:
1. The single filled primary button in the reprocess confirm dialog: "Reprocessar comunicação" (confirm). The page-level "Reprocessar comunicação" trigger is `variant="outline"` (NOT accent: operational recovery action on a read-only page that has no other filled button).
2. Links (same style as 134/135): the notification link target, "Ver documento fiscal".
3. Focus rings (`focus-visible:ring-blue-500`).

Never accent: ANY communication-state badge, the "Modo simulado" banner, the IUD block and its test-environment mark, the last-error summary, the Card "Comunicação fiscal", the "Cancelar/Fechar" buttons. Never green for "Aceite (simulação)" (a green would read as authorised) and never amber/red for "Rejeitado"/"Erro" badges: severity is conveyed by the label text, not by colour.

Badges (all neutral, none accent; Badge primitive, lucide icon 12px + `gap-1`, icon `aria-hidden`):

| Estado | Label | Variant | Icon |
|--------|-------|---------|------|
| `PENDENTE` | Pendente | `outline` | `Clock` |
| `ACEITE_SIMULADO` | Aceite (simulação) | `outline` | `Info` |
| `REJEITADO` | Rejeitado | `secondary` | `CircleSlash` |
| `ERRO` | Erro | `secondary` | `TriangleAlert` |
| unknown (fallback) | Estado desconhecido | `outline` | `Info` |

Rationale: `outline` for non-terminal/simulated outcomes, `secondary` (filled neutral) for the two states that need attention, so they are scannable without colour. Each badge has `title` equal to its long description (see Copywriting) and the label is always visible text (never icon-only).

## Surface 1 — Communication-state badge (list and detail)

### Documents list
- New column "Comunicação" after "Tipo" and before "Total": `ComunicacaoEstadoBadge`. Not sortable. Header label "Comunicação".
- New filter "Comunicação" (`native-select`, same pattern as the 134 Tipo filter, URL param persisted, page resets to 1): options "Todas", "Pendente", "Aceite (simulação)", "Rejeitado", "Erro". Only rendered if the backend list endpoint supports the filter (planner confirms; if not supported the column ships without the filter).
- Column "Tipo" and the 134/135 simulation badge treatment are unchanged. The list header description gains one sentence: "Faturas-recibo e notas de crédito emitidas pelo escritório. Os documentos são simulados e não têm validade fiscal. O estado de comunicação é atualizado em segundo plano."
- Empty/filtered-empty/error/loading states: unchanged. Filtered-empty reuses "Nenhum documento encontrado".

### Detail header
- The existing "Pendente" estado badge from 134/135 (and its helper "Comunicação à administração fiscal ainda não efetuada.") is REPLACED by `ComunicacaoEstadoBadge` driven by `comunicacao.estado`. The `text-xs text-slate-500` helper under the badges follows the estado (copy table below, "Header helper by estado"); there is exactly one estado badge in the header.
- Badges order: Tipo, Comunicação, "Simulação — sem validade fiscal" (unchanged mark, `outline` + `Info`).

### Short-lived updates
The state is updated in background by the backend. Detail page and list refetch the document/list queries with `refetchInterval: 15000` ONLY while the visible estado is `PENDENTE` (stops on any other estado, and when the tab is hidden: `refetchIntervalInBackground: false`). No spinner, no toast on automatic changes. After a successful reprocess, invalidate the document, the list and the notifications unread count.

## Surface 2 — Detail page Card "Comunicação fiscal"

Placed after "Valores" and before "Ligações" (after "Notas de crédito" on a FR). Rendered for every FR and NC. Card header row: CardTitle "Comunicação fiscal" (left) + (right-aligned, wraps below on mobile) the reprocess trigger when allowed.

Content (`dl`, `grid grid-cols-[1fr_auto] gap-2`, labels 400 left, values right; on screens < 640px stack `grid-cols-1`):

| Row | Value | Notes |
|-----|-------|-------|
| "Estado" | `ComunicacaoEstadoBadge` | long description line below, `text-xs text-slate-500` (see copy table) |
| "Ambiente" | "Teste (simulado)" | plain text, from `comunicacao.ambiente` (`SIMULADO`); never "Produção" in this build |
| "IUD" | IUD 45 chars in `font-mono text-sm break-all select-all` | block `bg-slate-50 dark:bg-slate-900 rounded-md p-4`; directly under it, `text-xs text-slate-500`: "Ambiente de teste — sem validade fiscal" with lucide `Info` 12px, never amber/red/accent |
| "Tentativas" | `{n}` | `tabular-nums`; helper `text-xs text-slate-500` "A comunicação é retentada automaticamente até 8 vezes." Value is the backend count; the "8" is part of the static copy only |
| "Última tentativa" | `dd/MM/yyyy HH:mm` (pt-CV) or "Ainda sem tentativas" | `text-xs`-size timestamp not needed: shown at 14px as value |
| "Próxima tentativa" | `dd/MM/yyyy HH:mm` | only when estado = PENDENTE and the backend returns it |

IUD absent (still being generated, `iud` null): row shows `text-sm text-slate-500` "A gerar..." and no mark. IUD is text only: NO QR code, NO barcode, NO "copy" button, NO link (QR/PDF is Phase 137).

Last error summary (only when `ultimoErro` is present and estado is `REJEITADO`/`ERRO`): a block with neutral notice classes (`rounded-md border border-slate-200 bg-slate-50 p-4 text-sm text-slate-700 dark:border-slate-800 dark:bg-slate-900 dark:text-slate-300`, `role="status"`), lead "Última falha" (600) followed by the backend summary text, truncated by the backend to a short, already-sanitised summary; the UI renders it as plain text with `break-words` and `whitespace-pre-line`, max 3 lines with a `line-clamp-3`, never as HTML, never a stack trace. Not red (red is reserved for inline form errors).

Loading: `Skeleton` for the Card. Error loading the document: unchanged page-level error. If `comunicacao` is missing in the DTO, the Card shows `text-sm text-slate-500` "A comunicação deste documento ainda não foi registada." (no badge in the header either, and no reprocess button).

### Reprocess button visibility (exact permission, both layers)
Trigger rendered only when ALL hold: `hasScopedPermission(perms, "financeiro", "edit")` is exactly true (exact `edit`, not a higher-implies-lower reading beyond the project helper's own chain; backend `@PreAuthorize("hasAuthority('financeiro:edit')")` must agree) AND `comunicacao.estado` is `ERRO` or `REJEITADO` AND mode is SIMULADO as reported by the backend. Otherwise it is NOT rendered (no disabled button, no tooltip, no hint). Users with only `financeiro:view` see the Card without the button and without any message about it. For `PENDENTE` and `ACEITE_SIMULADO` the button never appears.

Trigger: `Button variant="outline"` with lucide `RefreshCw` 16px (icon `aria-hidden`), label "Reprocessar comunicação".

### Reprocess confirm dialog (`Dialog`, same pattern as 134/135 confirmations; single step)
- Title: "Reprocessar comunicação". Description (`text-sm text-slate-500`): "A comunicação deste documento será reposta como pendente e voltará a ser tentada em segundo plano. O documento não é alterado."
- Content `space-y-4`: context block (`bg-slate-50`): "Documento" número (`font-mono`), "Estado atual" badge, "Tentativas" count. Helper `text-xs text-slate-500`: "O contador de tentativas volta a zero." and for REJEITADO an extra helper `text-xs text-slate-500`: "Se o documento foi rejeitado por um problema nos dados, o resultado pode ser o mesmo."
- Banner area (`role="alert"`, `text-sm text-red-600 dark:text-red-400`) for inline errors.
- Footer: "Fechar sem reprocessar" (outline, contextual dismiss; becomes "Fechar" after a definitive inline error) + "Reprocessar comunicação" (primary, not destructive). Pending: confirm shows "A reprocessar..." and both buttons disabled; Escape/overlay close blocked while pending. Close "X" `sr-only`: "Fechar reprocessamento da comunicação".
- On open, focus goes to the dialog title (confirm is not auto-focused, avoid accidental Enter).
- Success: dialog closes, document + list + notifications queries invalidated, toast "Comunicação reposta como pendente." and focus returns to the Card heading (the trigger disappears because estado becomes PENDENTE).
- No idempotency key needed: the operation is naturally idempotent (resetting to PENDENTE). Double-click safety: confirm disabled on first click.

### Inline errors (dialog banner; mapping via `ApiError {message, code, campo}` and `semToastParaStatus` as in 134/135: 409/422/503 inline without toast; 401/403 keep `apiFetch` behaviour)

| Code / status | Behavior | Copy |
|---------------|----------|------|
| 409/422 `COMUNICACAO_ESTADO_INVALIDO` (estado no longer ERRO/REJEITADO, e.g. already reprocessed elsewhere) | banner; "Fechar sem reprocessar" becomes "Fechar"; document query refreshed | "Este documento já não está em erro ou rejeitado. Atualizámos o estado; verifique antes de tentar de novo." |
| 409/422 `MODO_NAO_SUPORTADO` / unrecognised fiscal-mode code | banner; becomes "Fechar" | "O reprocessamento não está disponível neste ambiente." |
| 403 | existing `apiFetch` access-denied behaviour (no toast duplication); dialog closes | existing copy |
| 404 | dialog closes; page shows the existing not-found Empty state | "Documento fiscal não encontrado" (reuse 134) |
| 503 | banner; dialog stays open; retry allowed | "O serviço está temporariamente indisponível. Aguarde um momento e tente novamente." |
| Network failure / other 5xx | banner; dialog stays open; retry allowed | "Não foi possível reprocessar a comunicação. Verifique a ligação e tente novamente." |

## Surface 3 — "Modo simulado" banner

Component `ModoSimuladoBanner`, rendered at the top of the content area of ALL fiscal pages: documents list, document detail, and the honorário detail `financeiro/[id]/page.tsx` where fiscal documents/emission appear. Rendered whenever the backend reports mode `SIMULADO` (in this build always, so it is effectively permanent). Not dismissible (no close button, no persistence, no `localStorage`). If the backend reports any other mode value the banner is not rendered by this component (the app would not have started in this build; there is no "REAL" UI).

Markup: neutral notice classes (`rounded-md border border-slate-200 bg-slate-50 p-4 text-sm text-slate-700 dark:border-slate-800 dark:bg-slate-900 dark:text-slate-300`), `role="status"`, lucide `Info` 16px `aria-hidden` + `gap-2`, lead "Modo simulado" (600) then body copy (400). Never amber/red/accent; never sticky/overlay (it scrolls with the page); one banner per page, no duplicates in nested Cards.

Copy: "**Modo simulado.** Os documentos são comunicados a um serviço de simulação, não à administração fiscal (DNRE). Não têm validade fiscal. Continue a emitir os seus documentos válidos no software de faturação homologado."

(The per-document notices from 134/135 remain; the banner is the page-level statement, the per-document notice remains the document-level statement.)

## Accessibility and Responsive

- State is conveyed by visible text label plus icon, never colour alone; badges have `title`; the live region for estado changes is NOT announced automatically (background polling must not spam assistive tech); the banner and the error-summary block use `role="status"`, the dialog error banner `role="alert"`.
- Dialog is Radix (focus trap, Esc closes unless pending, focus returns as specified); confirm not auto-focused.
- IUD wraps (`break-all`) and is selectable; contrast >= 4.5:1 for `text-xs` helpers (`text-slate-500` on card/`bg-slate-50` already used in 134/135; use `text-slate-600 dark:text-slate-400` if the checker flags contrast on `bg-slate-50`).
- Touch targets >= 40px; table in `overflow-x-auto`; Card header row wraps below 640px with the button below the title; `dl` stacks below 640px.
- Dark mode: all classes paired with `dark:` variants.

## Decisions Made Without CONTEXT.md (defaults, consistent with codebase and 134/135)

- Neutral badge variants: `outline` for Pendente/Aceite (simulação), `secondary` for Rejeitado/Erro; labels carry the meaning, no colour semantics.
- Reprocess trigger is outline; the filled accent is reserved for the in-dialog confirm.
- Reprocess uses a confirm dialog (not a bare click) because it resets the attempts counter and triggers a new communication; no idempotency key (naturally idempotent).
- Polling only while PENDENTE (15 s), paused in background tabs; no websockets.
- Banner not dismissible and not sticky; shown on list, detail and honorário detail only.
- Notification category badge is `red` (existing notification system convention) and the category is silenciável; the neutral rule applies to communication-state badges, not to notification category badges.
- Comunicação filter on the list is conditional on backend support.
- "Ambiente" row text "Teste (simulado)"; no production wording exists in this build.
- The error summary is backend-sanitised; UI renders plain text, clamped to 3 lines.
