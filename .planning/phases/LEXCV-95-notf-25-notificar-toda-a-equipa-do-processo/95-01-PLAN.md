<objective>
Expand the team-fan-out logic inside `NotificacaoService` so process events reach the whole
client team, without building any parallel creation path.

This plan delivers the service-layer half of NOTF-25:
1. A single tenant-scoped team-resolution helper (`resolverEquipaCliente`) that both this plan and
   the ResourceController wiring plan (95-02) reuse — one implementation, closing Pitfall 3.
2. An 11-arg overload of the existing Phase 94 `criarComFanOutAdmin` helper that adds a
   "secondary recipients" tier (team members who get the informative 3rd-person message, exactly
   like the ADMIN fan-out already does), so PROCESSO_ATRIBUIDO can differentiate the new
   responsavel (2nd person) from the rest of the team (3rd person).
3. Team-expanded `notificarFaseEntrada` and `notificarProcessoAtribuido` (both gain a `clienteId`
   parameter) that feed the expanded recipient set into the SAME `criarComFanOutAdmin` helper.

Purpose: NOTF-25 success criteria 1, 2 (write side) and the 2nd/3rd-person split of criterion 2.
Output: modified `NotificacaoService.java` + extended `NotificacaoServiceTest.java`, green suite.
</objective>

| NotificacaoService → junction tables | Team-resolution reads tenant-scoped `t_cliente_advogado` / `t_cliente_administrativo` rows; a wrong scope would leak recipients across tenants |
| notificar* → criar() choke point | The only write path; widening the recipient set must not create duplicate rows that violate `uk_notificacao_dedup` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-95-01 | Information Disclosure | resolverEquipaCliente | mitigate | Query both junction repos via `findByClienteIdAndTenantId(clienteId, tenantId)` — the tenant_id filter on the junction row is the ownership check; never query by clienteId alone (Pitfall 10). Asserted by `resolverEquipaCliente_*` test verifying the (clienteId, TENANT_ID) argument pair |
| T-95-02 | Tampering | Widened recipient set vs uk_notificacao_dedup | mitigate | All recipients merged into one LinkedHashSet before the write loop; criar() uses the Phase 94 atomic `inserirSeNaoDuplicado` (ON CONFLICT DO NOTHING) — a team member who is also ADMIN is written once. Asserted by the reused Phase 94 collision tests under the new signatures |
| T-95-03 | Denial of Service | fan-out loop size | accept | Team size is bounded by a single cliente's advogados+administrativos (small, human-scale); dedup Set caps iterations; no user-supplied unbounded input |
| T-95-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase (Java source-only edits); Package Legitimacy Gate not applicable |
