## Spacing Scale

Declared values (must be multiples of 4), confirmed as already in use across `processos`/`clientes` pages via Tailwind utility classes:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact element spacing (filter chip gaps, table cell inline gaps) |
| md | 16px | Default element spacing (card padding, form field gaps) |
| lg | 24px | Section padding (page header to content gap, `space-y-6` root wrapper) |
| xl | 32px | Layout gaps (between major page sections) |
| 2xl | 48px | Major section breaks (rare — empty state vertical centering) |
| 3xl | 64px | Page-level spacing (not typically needed at this page's scale) |

Exceptions: none. Root page wrapper uses `space-y-6` (24px) matching `processos/page.tsx` exactly.

## Typography

Matches the existing convention observed directly in `processos/page.tsx` (`text-3xl font-bold ... tracking-tight` for H1) — Tailwind's default type scale, no custom tokens declared for this app.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label | 12px (text-xs) | 500 (medium) | 1.4 |
| Heading (page H1) | 30px (text-3xl) | 700 (bold) | 1.2 |
| Section title (CardTitle) | 18px (text-lg) | 600 (semibold) | 1.3 |

Weights used: 400 (body/table cells), 700 (page H1) — CardTitle at 600 is an existing sub-heading convention (`CardTitle` component default), counted as the "2 weights max" contract's semibold tier alongside bold. Do not introduce a third distinct weight.

## Color

Matches the neutral/slate palette + existing badge color variants already defined in `web/src/components/ui/badge.tsx`. No new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / `dark:bg-neutral-950`-equivalent page background | Page background, table/card surfaces |
| Secondary (30%) | `slate-50`/`neutral-100` (light) — `slate-900`/`neutral-800` (dark) | Cards, table header row, sidebar/nav, filter bar background |
| Accent (10%) | `blue-100`/`blue-700` (badge "blue" variant) | Reserved for: **status badge for `EM_ELABORACAO`** and primary "view detail" link/button hover state only |
| Destructive | `red-100`/`red-700` (badge "red" variant) | Reserved for: **error toast text, `AlertCircle` error banners, and any future destructive-action confirmation (not used in this read-only phase, but declared for consistency with Phase 68)** |

Accent reserved for: status badge color-coding (one hex family per status value, see mapping below) and link/interactive-row hover highlight — never applied to static body text or decorative elements.

### Status badge color mapping (Claude's Discretion resolved)

| `status` value | Badge variant | Rationale |
|---|---|---|
| `PENDENTE` | `gray` | Neutral/not-yet-started state, matches Processos' convention for pre-active states |
| `EM_ELABORACAO` | `blue` | Active-in-progress work, matches Processos' "ativo" blue convention |
| `EM_REVISAO` | `amber` | Awaiting a decision/gate, matches Financeiro's "pendente" amber convention |
| `CONCLUIDO` | `green` | Terminal success state, matches Processos' "concluído" green convention |
