<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → same-origin /api/v1 (proxied to backend) | List/detail/versão/anexo data crosses here; auth via httpOnly cookies |
| URL param `/pareceres/[id]` → backend | User-supplied solicitação id; IDOR surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-03 | Information Disclosure / IDOR | /pareceres/[id] detail page | mitigate | Backend `getSolicitacao`/`listVersoes` return 404 for another tenant's id (tenant-scoped via getTenantId()). Frontend must render the isError branch WITHOUT metadata/timeline on failure — Task 2 explicitly forbids rendering data blocks in the error branch, so a manipulated id yields the error state, not leaked/partial data. |
| T-65-04 | Elevation of Privilege | Both pages | mitigate | Page render gated by `permissions.can.view("pareceres")` → AccessDeniedState (page not rendered, not merely hidden). Mirrors backend `@PreAuthorize('pareceres:view')` on every consumed endpoint. |
| T-65-05 | Spoofing / Tampering | Client-side filters | accept | Status/advogado/cliente filters map to backend query params; the backend re-applies tenant scoping regardless of client filter values, so a tampered filter cannot widen the result set beyond the caller's tenant. No client-side tenant filter is introduced. |
| T-65-06 | Information Disclosure | Anexo presigned URL | accept | Download uses the backend presigned-URL endpoint (`pareceres:view`, tenant + solicitação-ownership checked server-side); URL is short-lived (expiresIn 3600). Frontend only opens the returned URL. |
| T-65-SC | Tampering | npm installs | mitigate | No new dependencies introduced in this plan; no install task; no legitimacy checkpoint required. |
</threat_model>
