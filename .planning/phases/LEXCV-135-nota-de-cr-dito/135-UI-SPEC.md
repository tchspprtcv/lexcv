# Phase 135 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope (4 surfaces, NO new visual language: every token, class, badge variant, notice block and error pattern is inherited verbatim from `134-UI-SPEC.md`, including its "Checker clarifications" and the revised idempotency-key lifecycle):

1. "Emitir Nota de Crédito" button + two-step dialog on `web/src/app/(dashboard)/financeiro/documentos-fiscais/[id]/page.tsx` (FR only).
2. Same detail page: NC list and remaining creditable on a FR; link to the original FR on an NC.
3. Honorário payments list in `web/src/app/(dashboard)/financeiro/[id]/page.tsx`: estorno row.
4. Documents list `financeiro/documentos-fiscais/page.tsx` (+ `columns.tsx`): Tipo filter FR/NC, NC rows.

Hooks: extend `web/src/hooks/use-faturacao.ts` with `usePreVisualizacaoNotaCredito(documentoId)` and `useEmitirNotaCredito(documentoId)` (mutations). Types in the existing faturacao types file: `NotaCreditoResumo`, `PreVisualizacaoNotaCredito`, `valorCreditavelRestante`, `documentoOrigem`, `notasCredito[]`, `estorno` on the pagamento DTO. Reuse `web/src/lib/idempotencia.ts` and `web/src/lib/erros-emissao.ts`. Sources: 135-CONTEXT.md (locked), 134-UI-SPEC.md, REQUIREMENTS NCRD-01..03.

Principle ("frontend burro", unchanged): the frontend NEVER computes base, IVA, retenção, total, valor creditável restante or any NC amount. It renders only values returned by the NC pre-visualização endpoint and the document endpoints. Allowed client logic: formatting (Intl pt-CV, CVE), and a non-authoritative check that the typed valor parcial is a number > 0 (the ceiling is enforced by the backend, never compared client-side).

## Surface 1 — "Emitir Nota de Crédito" button and dialog

### Visibility (exact permission, both layers)
Trigger rendered only when ALL hold: `hasScopedPermission(perms, "financeiro", "manage")` is exactly true (manage, not the weaker chain), `documento.tipo === "FR"`, `documento.valorCreditavelRestante > 0` (value from backend), and faturação is not known to be off. Otherwise it is NOT rendered (no disabled button, no tooltip). A FR fully credited shows instead the line `text-xs text-slate-500` in the header area: "Esta fatura-recibo já foi totalmente creditada." Users with only `financeiro:view` see the page without the trigger and without any message about it.

Trigger: `Button variant="outline"` with lucide `FilePlus2` 16px, label "Emitir Nota de Crédito" (capitalisation as specified by the product decision; elsewhere copy is sentence case).

### Dialog (`Dialog`, data-bearing, same reasoning as 134), two steps in the same dialog

Title step 1: "Emitir Nota de Crédito". Description (`text-sm text-slate-500`): "Corrija esta fatura-recibo emitindo uma nota de crédito. O documento original não é alterado."
Close "X" `sr-only`: "Fechar emissão de nota de crédito" (step 2: "Fechar pré-visualização da nota de crédito").

Step 1 content, in order (`space-y-4`):
1. Context block (`bg-slate-50`): "Fatura-recibo" número (`font-mono`), "Total da fatura" and "Valor ainda creditável" (semibold) as returned by backend. Helper `text-xs text-slate-500`: "O valor total das notas de crédito não pode exceder o total da fatura."
2. Tipo de crédito: `RadioGroup`, two options with Label: "Total" (hint `text-xs`: "Credita todo o valor ainda creditável.") and "Parcial". Default "Total". Legend label (600): "Tipo de crédito".
3. Valor a creditar (only when "Parcial"): `Input` inputMode decimal, label "Valor a creditar (CVE) *". Helper `text-xs text-slate-500`: "Valor com IVA incluído." Client validation: required, number > 0; error "Indique um valor superior a 0." The ceiling is NOT validated client-side.
4. Motivo: `native-select`, label "Motivo *", placeholder option "Escolha o motivo", options in this order: "Anulação total", "Correção de valor", "Erro nos dados do cliente", "Outro". Error "Escolha o motivo da nota de crédito."
5. Descrição do motivo: `Textarea` (3 rows), label "Descrição do motivo *", mandatory, trimmed non-empty, max 200 characters (counter `text-xs text-slate-500` "{n}/200"). Error "Descreva o motivo da nota de crédito." Helper: "Fica registada no documento."
6. Banner area (`role="alert"`) for inline errors (see Errors).

Footer step 1: "Cancelar" (outline; becomes "Fechar" after an inline definitive error) + "Pré-visualizar nota de crédito" (primary). Pending: button "A calcular..." and disabled. If the preview is refused (409/422) the dialog stays on step 1 and shows the inline error; focus moves to the offending field or banner.

Step 2 (pré-visualização, all values from backend):
1. Simulation notice (neutral notice classes): "Documento simulado: não tem validade fiscal. Continue a emitir os seus documentos válidos no software de faturação homologado."
2. Adquirente block (`bg-slate-50`): Nome, NIF (`font-mono`), Morada — those of the original FR (read-only).
3. Referência: "Corrige a fatura-recibo {número original}" (`font-mono` número).
4. Motivo: "{rótulo do motivo} — {descrição}" (read-only line).
5. Valores `dl` (labels 400 left, values right `tabular-nums`; values shown as returned, credit amounts displayed with the formatter's minus where the backend returns them negative):
   - "Base tributável"
   - "IVA ({taxa}%)" (taxa of the ORIGINAL FR, as returned) — OR for isento: "IVA" = "Isento" + row "Motivo de isenção" `{código} — {rótulo}`
   - "Retenção na fonte ({taxa}%)" only if the original FR had retenção
   - Separator
   - "Total a creditar" (600) — focal row
   - "Valor creditável restante" (600) — focal row, value after this NC
   - helper `text-xs text-slate-500`: "O valor creditado sai do total pago do honorário, que volta a ficar por pagar na parte creditada. Será registado um estorno nos pagamentos."
6. Banner area for inline errors.

Footer step 2: "Voltar e editar" (outline, returns to step 1 keeping values; first in tab order) + "Emitir nota de crédito" (primary, not destructive). While emitting: both disabled, label "A emitir...", Escape/overlay close blocked. Opening step 2 focuses the dialog title; confirm is not auto-focused (avoid accidental Enter emission).

Success: dialog closes, queries for the document, documents list and honorário (payments, totals) are invalidated, toast "Nota de crédito {número} emitida." and focus returns to the "Emitir Nota de Crédito" trigger (or, if it disappears because the FR is fully credited, to the page `h1`).

### Idempotency key (identical to 134 revised lifecycle, CR-02)
`chaveIdempotencia` belongs to the request content (documento origem + tipo total/parcial + valor + motivo + descrição), not to the dialog. It is generated by `lib/idempotencia.ts` on first emission attempt and survives closing/reopening after an ambiguous failure (network, 5xx, 401/403/408/429), being reused for the same payload. It is discarded only after success, a definitive backend 4xx, or any change of the payload. The key is never displayed. Network-failure retry in the open dialog reuses the same key.

### Inline errors (dialog banner `role="alert"`, `text-sm text-red-600`; field-level `text-xs text-red-600` under the field). Mapping via `ApiError {message, code, campo}`, `lib/erros-emissao.ts`, and `semToastParaStatus` (409/422/503 inline, no toast; 401/403 keep `apiFetch` behaviour)

| Code / status | Behavior | Copy |
|---------------|----------|------|
| 409/422 `NC_EXCEDE_ORIGINAL` | banner on the step where it occurs; step returns to 1 if from emit; refreshes the context block (valor ainda creditável) from the server | "O valor indicado excede o que ainda pode ser creditado nesta fatura-recibo. Reduza o valor ou escolha crédito total." |
| 409/422 `NC_SOBRE_NC` | banner; "Cancelar" becomes "Fechar" | "Não é possível creditar uma nota de crédito. Emita a nota de crédito sobre a fatura-recibo original." |
| 409/422 `FATURACAO_DESLIGADA` | banner; "Cancelar" becomes "Fechar" | "A faturação está desligada. Ative a faturação nas definições para emitir notas de crédito." |
| 422 data (`DATA_EMISSAO_INVALIDA` or equivalent `code` on date) | banner | "A nota de crédito só pode ser emitida com a data de hoje. Atualize a página e tente de novo." |
| 422 adquirente/valor/motivo inválido with `campo` | field error on the field named in `campo`; else banner | backend `message`, fallback "Verifique os campos assinalados." |
| 409 `CHAVE_REUTILIZADA` | dialog returns to step 1, banner, key discarded (new key on next attempt) | "Este pedido já foi usado com valores diferentes. Reveja os dados e emita a nota de crédito de novo." |
| 503 (serviço indisponível / lock) | banner; dialog stays open on step 2; retry allowed with the SAME key | "O serviço de faturação está temporariamente indisponível. Aguarde um momento e tente novamente." |
| Network failure / other 5xx | banner; dialog stays open on step 2; retry reuses same key | "Não foi possível emitir a nota de crédito. Verifique a ligação e tente novamente." |
| 404 (document not found / other tenant) | dialog closes, page shows the not-found Empty state | see Surface 2 |

Preview-step failure (step 1 → 2 request) uses the same table; network failure copy there: "Não foi possível calcular a nota de crédito. Verifique a ligação e tente novamente."

## Accessibility and Responsive

- All controls have a `Label`; the radio group has a legend; errors linked via `aria-describedby`, inputs `aria-invalid`; banners `role="alert"`; dialog is Radix (focus trap, Esc closes unless emitting, focus returns to the trigger).
- Valor a creditar appears/disappears with Total/Parcial; when switching to Total the typed value is discarded and the key regenerated (payload changed).
- Double-click safety: confirm disabled on first click plus idempotency key.
- Touch targets >= 40px; tables in `overflow-x-auto`; dialog fields single column; header row wraps below 640px.
- Negative amounts are conveyed by the minus sign, not by colour alone.
- Dark mode: all classes paired with `dark:` variants.

## Decisions Made Without CONTEXT.md (defaults, consistent with codebase and 134)

- Dialog is two steps inside one `Dialog` (form, then backend preview) instead of the 134 pattern of form-on-page plus separate dialog, because the NC inputs live only in the dialog.
- Trigger is an outline button (irreversible action on a read-only page; filled accent stays reserved for the in-dialog primary actions).
- Estorno amounts are red with explicit minus sign in the payments list only; documents list stays uncoloured.
- Motivo description max 200 chars (default; backend is the authority and its `message` wins on a 422).
- Mapping of the four motivo options to XSD codes is backend-owned (confirmed in Phase 136); UI shows only the Portuguese labels.
- No prazo-máximo message (deferred pending contabilista).
- Filters remain synced to URL params; default page size 10.
