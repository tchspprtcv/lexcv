    - TOTAL with no prior -> exactly the FR columns
    - PARCIAL equal to the remaining total -> same result as TOTAL (column remainders, no recompute)
    - PARCIAL 100 000.01 after the 20 000 NC -> 409 NC_EXCEDE_ORIGINAL campo valor; TOTAL when remaining is 0 -> 409 NC_EXCEDE_ORIGINAL with the "totalmente creditada" message
    - origem tipo NC -> 422 NC_SOBRE_NC (checked first, before any request validation)
    - ISENTO FR (taxaIva 0, motivo isenção) PARCIAL 500.00 -> base 500.00, IVA 0.00, taxaIva 0
    - FR without retention (taxaRetencao null) -> retention 0.00 on every NC, taxaRetencao null
    - Rounding clamp: a sequence of many small PARCIAL NCs (e.g. FR 100.00 credited 0.01 at a time for a sampled set, plus a property-style loop over 1..N partials summing to the FR total) never produces cumulative base > FR base, cumulative IVA > FR IVA, or cumulative retention > FR retention, and the final total-remaining NC closes every column to exactly the FR value
    - Uses the FR snapshot taxaIva, never a parameter/current rate (no ParametroFiscalService anywhere in the class)
    - dataEmissao == hoje; descricaoLinha == "Crédito sobre a fatura-recibo " + origem numeroFormatado
  </behavior>

Remainders: sum totalBase/totalIva/totalRetencao/totalDocumento over notasAnteriores (filter tipo NC defensively) and subtract from the FR columns. If remTotal <= 0 -> NC_EXCEDE_ORIGINAL ("totalmente creditada"); if PARCIAL valor > remTotal -> NC_EXCEDE_ORIGINAL. TOTAL, or PARCIAL with valor == remTotal: calculo = remainders (taxaIva = origem.getTaxaIva(), taxaRetencao = origem.getTaxaRetencao(), liquido = remTotal - remRet). PARCIAL below remTotal: c = CalculoFiscal.calcular(valor, origem.getEmitenteRegimeIva(), origem.getTaxaIva(), origem.getTaxaRetencao()); base = min(c.base, remBase); iva = valor - base; if iva > remIva then iva = remIva and base = valor - iva; retencao = min(c.retencao, remRet); liquido = valor - retencao; build a new CalculoFiscal.ResultadoCalculo with these values. NC amounts are POSITIVE magnitudes (the negative sign lives only in the estorno Pagamento, plan 06). Class javadoc: pure, no Spring/DB/clock, shared by preview and emission (CONTEXT "frontend burro"), P-13 clamp rationale.</implementation>
