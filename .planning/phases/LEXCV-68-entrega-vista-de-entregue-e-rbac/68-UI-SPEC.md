## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual component library, not shadcn CLI — `components.json` does not exist in `web/`) |
| Preset | not applicable |
| Component library | Radix primitives wrapped manually in `web/src/components/ui/` — reuse existing `card.tsx`, `button.tsx`, `badge.tsx`, `alert-dialog.tsx` verbatim. **No new UI primitives are introduced this phase.** `AlertDialog`/`AlertDialogTrigger`/`AlertDialogContent`/`AlertDialogHeader`/`AlertDialogTitle`/`AlertDialogDescription`/`AlertDialogFooter`/`AlertDialogCancel`/`AlertDialogAction` are the confirmed pattern (already used in `web/src/app/(dashboard)/agenda/[id]/page.tsx:166-215` for event deletion) — copy that structure for the "Entregar Parecer" dialog. |

## Typography

Matches Phase 65/66/67's contract verbatim — same module, same page. Only two weights: 400 (regular) and 700 (bold).

**MANDATORY CROSS-CUTTING FIX — not new-component guidance, a required fix task for this phase's plan:**

Phase 66's UI-REVIEW and Phase 67's UI-REVIEW both independently found that `CardTitle` elements render without the `text-lg font-bold` override, defaulting to the base component's unstyled `font-semibold h3` (confirmed in `web/src/components/ui/card.tsx:28-34`). This is now a **3rd recurrence** of the identical defect class across three consecutive phases touching the same page family:

- Phase 65: not flagged as a fix at the time (spec pre-dated the mandate), but is the origin of the inconsistency.
- Phase 66: "Dados da Solicitação" CardTitle shipped without the override (66-UI-REVIEW.md).
- Phase 67: "Dados" and "Versões" CardTitles on `pareceres/[id]/page.tsx` shipped without the override, while only the new "Nova Versão" CardTitle got it correctly (67-UI-REVIEW.md, Top Priority Fix #2).

**Because this phase touches `pareceres/[id]/page.tsx` again, closing this gap here — across every `CardTitle` on every page in the `/pareceres` module — is mandatory, not optional discretion.** The plan MUST include an explicit task (not bundled silently into other work) to:

1. Audit every `<CardTitle>` usage under `web/src/app/(dashboard)/pareceres/**` (list page, detail page, `novo/page.tsx`, and this phase's new "Entregar Parecer"/"Parecer Entregue" cards).
2. Apply `className="text-lg font-bold"` to every single one, with zero exceptions, including the pre-existing "Dados" and "Versões" titles on the detail page that Phases 66/67 left unfixed.
3. This is a verifiable, gradeable fix — the executor must NOT scope the fix narrowly to "just this phase's new cards" the way Phase 66/67's specs were (mis)read; the instruction here is explicit and total-module in scope.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / Label | 14px (text-sm) / 12px (text-xs) | 400 (regular) | 1.5 (body) / 1.4 (label) |
| Heading (page H1) | 30px (text-3xl, list) / 24px (text-2xl, sub-pages) | 700 (bold) | 1.2 |
| Section title (ALL CardTitle instances, module-wide) | 18px (`text-lg`, **explicit class mandatory on every instance**) | 700 (bold, **explicit `font-bold` class mandatory on every instance**) | 1.3 |
| Dialog title (`AlertDialogTitle`, "Entregar Parecer") | 18px (component default, matches `agenda/[id]/page.tsx`'s existing `AlertDialogTitle` rendering — do not override) | 600 (component default `font-semibold`) — **exception, see note below** | 1.3 |

**Note on `AlertDialogTitle` weight:** the shared `alert-dialog.tsx` component renders `AlertDialogTitle` at `font-semibold` (600) by default, matching the existing "Apagar evento" dialog in Agenda verbatim (no override applied there either). This phase reuses that primitive unmodified for consistency with the one other existing irreversible-action dialog in the app — do not introduce a third weight tier by forcing `font-bold` here; treat this exact, pre-existing, shared-component value as an accepted exception scoped only to `AlertDialogTitle`, not a precedent to relax the CardTitle mandate above.

Weights used in new/touched code: 400, 600 (shared `AlertDialogTitle` only, unmodified), and 700. Do not introduce any additional weight beyond these three, and do not apply 600 anywhere except the untouched shared dialog primitive.

## Color

Matches Phase 65/66/67's neutral/slate palette and the 60/30/10 split verbatim — same module, same page family. No new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / `dark:bg-neutral-950`-equivalent | Page background, card surfaces |
| Secondary (30%) | `slate-50`/`neutral-100` (light) — `slate-900`/`neutral-800` (dark) | Cards, section backgrounds, "Parecer Entregue" summary card surface |
| Accent (10%) | `blue-600` (`hover:bg-blue-700`) | Reserved for: **primary CTA buttons only** ("Nova Versão"/"Nova Solicitação" on other pages) — on THIS page, the accent budget is **not** spent on the entrega action (see Destructive below); accent may still appear on the version-timeline "view detail"/link-style elements if any remain from Phase 65, but nowhere else |
| Destructive (irreversible-action semantic) | `red-600` / `bg-destructive text-destructive-foreground hover:bg-destructive/90` | Reserved for: **the "Entregar" `AlertDialogAction` confirm button** (irreversibility carries destructive-equivalent visual weight per CONTEXT.md's explicit decision, even though "entregar" is not a delete), **validation error text**, and **submit-failure banner/toast** |

**Explicit re-declaration of the accent-reservation rule (per this phase's requirement to reconfirm it):** Accent blue (`blue-600`/`blue-700`) is reserved **exclusively** for primary call-to-action buttons and the upload progress-bar fill. It must never appear on decorative markers, static/at-rest text, or any element that is not the single primary action or an active progress indicator. This rule has been violated twice already in this module and both violations are explicitly in scope to fix in this phase:

### Mandatory fixes carried into this phase (from 67-UI-REVIEW.md, Priority Fixes #1)

1. **Timeline dot marker leak** — `pareceres/[id]/page.tsx:221` currently renders `<span className="h-2.5 w-2.5 rounded-full shrink-0 bg-blue-600" />` for every version entry regardless of status. This is a decorative element and must NOT carry the accent color. **Fix required this phase:** change to a neutral, non-accent color — `bg-slate-400 dark:bg-slate-500` — for all timeline dots. Do not color-code dots by status; the existing status badge already carries that signal (per Phase 65's Color section).
2. **`FileDropZone` trigger text leak** — `web/src/components/shared/file-drop-zone.tsx:76` renders "Clique para selecionar" with `text-blue-600 dark:text-blue-400` — static, at-rest text carrying accent color, which the spec's own rule forbids. **Fix required this phase:** since `FileDropZone` is a shared component reused verbatim across Documentos, Pareceres-versão-upload (Phase 67), this phase does NOT change this component in isolation for cosmetic reasons that could regress other modules — however, if this phase touches any file-upload UI at all (it does not add a new one; entrega has no attachment step), leave `file-drop-zone.tsx` untouched. **This leak remains open and is explicitly flagged as a known, unresolved cross-phase gap** — recorded here for visibility, not remediated in this phase's scope (no file upload exists in the entrega flow), and should be picked up as a dedicated shared-component fix in a future phase or as a non-blocking follow-up in STATE.md.

Both leaks above are called out explicitly so the executor and checker do not silently re-approve them; item 1 is a required fix, item 2 is a required acknowledgment (not a required code change, since this phase does not touch that component).

### Focal points

- **Detail page, pre-entrega:** the "Entregar Parecer" trigger button (or its equivalent affordance) is the primary focal point when visible — but per the Destructive convention above, it is styled with the same visual weight as a destructive action (not `blue-600`), since irreversibility is the dominant signal here, not "this is a nice thing to do." Use `variant="destructive"` (or equivalent `bg-destructive` styling) on the trigger button itself, matching the confirm action's own styling for consistency — the whole affordance should read as "serious, one-way action," not as a cheerful primary CTA.
- **Detail page, post-entrega:** the "Parecer Entregue" summary block is the primary focal point, replacing the trigger button. Use the `green` badge variant (already established in Phase 65's status badge mapping for `CONCLUIDO`) as the only color accent in this block — everything else in the block is neutral text on the secondary (30%) card surface. No new accent color is introduced for "delivered" state; reuse the existing green semantic from the status badge system.

## Copywriting Contract

Portuguese, direct tone, sentence case, no exclamation marks — consistent with Phases 65/66/67.

| Element | Copy |
|---------|------|
| Entrega trigger button | "Entregar Parecer" |
| Dialog title | "Entregar Parecer" |
| Dialog body (irreversibility statement, mandatory) | "Esta ação é irreversível. Depois de entregue, o parecer não pode receber novas versões nem ser reaberto." |
| Dialog body (version selection prompt) | "Selecione a versão a entregar como final:" — followed by a list/select of existing versões (numeroVersao + data), defaulting to the most recent version pre-selected but requiring explicit confirmation of the choice, not a silent default |
| Dialog confirm button | "Confirmar Entrega" — pending state: "A entregar..." |
| Dialog cancel button | "Cancelar" (matches `AlertDialogCancel` convention from Agenda's delete dialog) |
| Entrega success toast | "Parecer entregue com sucesso." |
| Entrega error (inline banner + toast, dual-channel per Phase 66/67 pattern) | "Não foi possível entregar o parecer. Verifique a ligação e tente novamente." |
| "Parecer Entregue" block heading | "Parecer Entregue" |
| "Parecer Entregue" block — version reference | "Versão {numeroVersao}" (do not fabricate a separate "entregue por/em" line — see field-availability note below) |
| "Parecer Entregue" block — author/date (derived from final version's own fields, not a nonexistent "entrega" timestamp) | "Elaborado por {autor} em {data}" — sourced from the matched version's `criadoPorId`/`createdAt`, NOT from a fabricated entrega-specific field (the backend has no separate entregue-por/entregue-em field; do not imply one exists) |
| "Parecer Entregue" block — anexo link | "Descarregar anexo" / "Sem anexo" (reuses Phase 65's `AnexoLink` copy convention exactly) |
| Read-only enforcement (CONCLUIDO, no entrega button visible) | No separate banner needed beyond the "Parecer Entregue" block itself — the block's presence IS the read-only signal; do not duplicate with a second "este parecer é apenas de leitura" message |
| RBAC — entrega button hidden (not responsável/ADMIN) | No passive banner — button/section omitted entirely, matching the established "no dead buttons" principle from Phases 66/67 |
| Access denied (no `pareceres:view`) | Unchanged from Phase 65: "Não tem permissão para consultar o módulo de pareceres." |

Destructive confirmation: **applies to this phase.** "Entregar Parecer" — confirmation via `AlertDialog` per the Design System section above, with copy specified in this table. This is the phase's one and only destructive-weight action.
