<objective>
Resolve TEST-03: make an explicit, recorded decision about whether CI runs the backend tests / SpotBugs, and implement the affirmative decision by adding a gating CI job.

Context: this repo's CI (`.github/workflows/deploy.yml`) has never run `mvn test`, `mvn verify`, or `mvn spotbugs:check` — it goes straight to `docker/build-push-action`, and the backend Dockerfile builds with `-DskipTests`. So the two new Testcontainers tests (91-01, 91-02) and the Phase 90 SpotBugs config would silently rot without a CI step (PITFALLS.md Pitfall 7). `ubuntu-latest` runners ship a Docker daemon, so Testcontainers needs no extra CI service once a step exists.

Purpose: Tests and SAST that only run locally protect nothing. Gating image build/push on a test job converts this milestone's investment into ongoing regression protection.
Output: A new `test` job in deploy.yml gating `build-and-push`, plus the decision recorded in PROJECT.md and STATE.md.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → Docker daemon | The test job starts Testcontainers (postgres:16-alpine) on the runner's Docker |
| CI workflow → GHCR (image registry) | Only build-and-push writes images; the test job must not have registry write |
| Push event → deployment pipeline | The test/SAST job is the quality gate before any image ships |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-91-04 | Tampering | New `test` CI job (dep resolution + Docker image pull on runner) | mitigate | Pinned action versions (checkout@v4, setup-java@v4); Maven cache keyed on pom hash; no new secrets introduced; deps BOM-managed from 91-01 |
| T-91-05 | Elevation of privilege | Quality-gate bypass | mitigate | `build-and-push` declares `needs: test`; a failing test or SpotBugs finding blocks image build/push — verify a red test blocks the push job |
| T-91-06 | Information disclosure | CI job permissions / logs | mitigate | test job `permissions: contents: read` only (no packages:write); tests use ephemeral container credentials via @ServiceConnection, no prod secrets referenced in the test job |
| T-91-SC | Tampering | postgres:16-alpine pulled in CI | accept | Official Postgres image, same tag as prod/dev; ephemeral per-run; not an npm/pip/cargo install |
</threat_model>
