<known_traps>
1. **`@Builder.Default` é obrigatório em qualquer campo com valor por omissão em Java.** `Tenant.java:40-49` documenta exactamente esta armadilha: sem ele, todo o `Permission.builder()...build()` que não fixe o campo recebe `null`, não o default. O default de `reservadaPlataforma` só protege se estiver marcado.
2. **`columnDefinition` é o que povoa linhas já existentes.** `t_permission` tem linhas reais com atribuições reais. Uma coluna `NOT NULL` sem `default` no `columnDefinition` faz o `ALTER TABLE` de `ddl-auto: update` falhar no arranque. As colunas descritivas nascem por isso **nullable** (o seeder povoa-as no mesmo arranque) e só `reservada_plataforma` é `NOT NULL` — com `default true`.
3. **`@EqualsAndHashCode(of = "nome")` não pode ser tocado.** `Role.permissions` é um `Set<Permission>`; mudar a base de igualdade para incluir os campos novos alteraria a semântica de `addAll` em `upsertRolePermissions` e podia duplicar entradas no set.
4. **`nome` na entidade ≠ `nome` no DTO.** Em `RbacResponse.PermissionDefDto`, `key` = nome técnico (`Permission.nome`) e `nome` = rótulo legível (`Permission.rotulo`). O campo novo chama-se `rotulo` precisamente para não colidir. Nunca renomear `Permission.nome`.
5. **A coluna `nome` nunca é escrita num upsert de linha existente.** É a identidade referenciada por `t_role_permission`/`t_user_permission`. Actualizar só os campos descritivos é seguro; tocar em `nome` não é.
6. **`grep -c` conta comentários.** Qualquer verificação por contagem sobre `.java`/`.sql` tem de filtrar primeiro (`grep -v '^\s*\*' | grep -v '^\s*//'` / `grep -v '^--'`), senão os comentários que este plano manda escrever invalidam o próprio gate.
7. **`mvn` é o binário do sistema — não existe wrapper** (`./mvnw` não está commitado). Correr sempre a partir de `backend/`.
</known_traps>
