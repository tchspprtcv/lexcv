Root cause: the "create new" branch builds `Documento.builder().id(documentoId)....versao(1).build()`, explicitly setting BOTH an explicit ID and a non-null `@Version` field on a never-persisted entity; Spring Data JPA's `save()` uses "is version null?" to decide insert-vs-merge for `@Version`-annotated entities, so a non-null version on a brand-new entity routes to `merge()`, which then fails to find a matching existing row. Confirmed via `git log` that `ResourceController.java` was last touched by an unrelated Phase 97 commit (`f0c62ff`, 2026-07-14) — this predates and is unrelated to any Phase 107 (or any shadcn/ui migration) work; zero backend files were touched by any of this phase's 6 plans. | **Not fixed** — backend Java bug, entirely outside this phase's frontend-only scope (Progress/Select/NativeSelect/Combobox migration).
