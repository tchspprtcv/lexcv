Modificar `page.tsx` para adicionar filtros client-side. Todas as alterações ficam dentro do componente `FinanceiroContent`.

1. Adicionar `import * as React from "react"` no topo do ficheiro (ainda não existe).

2. Dentro de `FinanceiroContent`, logo após as declarações dos hooks existentes (`honorarios`, `processos`, `clientes`, `processoById`, `clienteNomeById`, `isLoading`, `isError`), adicionar estado de filtros:

```
const [filtroProcesso, setFiltroProcesso] = React.useState("");
const [filtroStatus, setFiltroStatus] = React.useState<"" | "Pendente" | "Parcialmente Pago" | "Pago">("");
const [filtroDataDe, setFiltroDataDe] = React.useState("");
const [filtroDataAte, setFiltroDataAte] = React.useState("");
```

3. Calcular `filteredList` após os estados (antes de `kpiFaturado` etc.):
- Começar com `honorarios.data ?? []`
- Se `filtroProcesso` não vazio: `.filter(h => h.processoId === filtroProcesso)`
- Se `filtroStatus` não vazio: `.filter(h => calcHonorarioStatus(h.totalPago, h.valorTotal) === filtroStatus)`
- Se `filtroDataDe` não vazio: `.filter(h => h.dataAcordo != null && h.dataAcordo >= filtroDataDe)`
- Se `filtroDataAte` não vazio: `.filter(h => h.dataAcordo != null && h.dataAcordo <= filtroDataAte)`
- Guardar resultado em `const filteredList`

4. Manter `const list = honorarios.data ?? []` (usado nos KPIs do topo — os KPIs NÃO são filtrados).

5. Na renderização, adicionar barra de filtros imediatamente antes do `<Card>` da tabela de honorários (depois dos cards de KPIs). A barra deve ser um `<div className="flex flex-wrap items-end gap-4">` com:

   a. Select de processo (FIN-11):
   - `<label>` com texto "Processo"
   - `<select>` nativo com `value={filtroProcesso}` e `onChange={e => setFiltroProcesso(e.target.value)}`
   - Opção vazia: `<option value="">Todos</option>`
   - Mapear `processos.data ?? []` para `<option key={p.id} value={p.id}>{p.numero ?? p.titulo ?? p.id}</option>`
   - Classes: `rounded-md border border-neutral-200 bg-white px-3 py-2 text-sm dark:border-neutral-800 dark:bg-neutral-950`

   b. Select de status (FIN-12):
   - `<label>` com texto "Estado"
   - `<select>` com `value={filtroStatus}` e `onChange`
   - Opções: `""` → "Todos", `"Pendente"` → "Pendente", `"Parcialmente Pago"` → "Parcialmente Pago", `"Pago"` → "Pago"
   - Mesmas classes do select anterior

   c. Inputs de data (FIN-13):
   - Dois `<input type="date">` com labels "Data de" e "Data até"
   - `value={filtroDataDe}` / `value={filtroDataAte}`, `onChange` respetivo
   - Classes: `rounded-md border border-neutral-200 bg-white px-3 py-2 text-sm dark:border-neutral-800 dark:bg-neutral-950`

   d. Botão Limpar — mostrar apenas quando `filtroProcesso || filtroStatus || filtroDataDe || filtroDataAte`:
   - `<Button variant="outline" onClick={() => { setFiltroProcesso(""); setFiltroStatus(""); setFiltroDataDe(""); setFiltroDataAte(""); }}>Limpar filtros</Button>`

6. Substituir `honorarios.data.map(...)` (na tabela) por `filteredList.map(...)`. A condição de "sem honorários" deve verificar `!honorarios.data?.length` (a mensagem de vazio quando a lista original está vazia) e adicionar, dentro da condição de dados existentes mas `filteredList` vazio, a mensagem "Nenhum honorário corresponde aos filtros aplicados."

   Estrutura para a renderização da tabela:
   - `!honorarios.data?.length` → "Nenhum honorário encontrado."
   - `honorarios.data.length > 0 && filteredList.length === 0` → "Nenhum honorário corresponde aos filtros aplicados."
   - caso contrário → tabela com `filteredList.map(...)`
