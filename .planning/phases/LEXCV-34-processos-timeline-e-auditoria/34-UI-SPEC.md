## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps inside timeline dots, inline chip padding |
| sm | 8px | Gap between timeline dot and content block, chip row gap |
| md | 16px | Default card padding, filter bar element spacing |
| lg | 24px | Card section padding (CardContent), between timeline entries |
| xl | 32px | Between major card groups on the detail page |
| 2xl | 48px | Empty-state vertical centering padding |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions:
- Timeline connector line: 2px width (not a spacing token — structural)
- Timeline dot: 10px diameter circle anchored at left edge of the feed
- Touch targets for filter chips and toggle buttons: minimum 36px height (existing app pattern — buttons use `h-9` = 36px)

Source: existing detail page uses `space-y-4`, `gap-4`, `px-8`, `py-4`, `gap-2` consistently. 8-point scale confirmed throughout.

## Layout: Tab System Extension

The existing tab system in `ProcessoDetailContent` uses `type TabKey = "partes" | "fases" | "movimentacoes"`.

Phase 34 change:
- Remove `"movimentacoes"` from TabKey
- Add `"timeline"` and `"auditoria"` to TabKey
- New tab order: **Timeline | Partes | Fases**
- `"auditoria"` tab renders only when `canManageProcessos === true`; the button is not rendered at all for users without `processos:manage`

Tab button pattern (existing convention preserved):
```
variant={tab === "timeline" ? "secondary" : "outline"}
```
No `rounded-none` on tab buttons — existing tabs use default Button border-radius.

## Timeline Feed Visual Spec

The Timeline tab renders a vertical dot-and-line feed. Anchor side: left.

### Structure per entry

```
[dot]─────[connector line going down]
  │
  └── [icon 16x16] [titulo — text-sm font-medium]
                   [timestamp — text-xs text-slate-500]
                   [descricao — text-sm text-slate-600 dark:text-slate-400 (optional)]
                   [autor_nome — text-xs text-slate-400 italic (optional)]
```

### Dot

- Size: 10px × 10px circle (`h-2.5 w-2.5 rounded-full`)
- Color: one of the five event-type colors above
- Left-aligned, vertically centered with the first line of the entry title
- Connector: `border-l-2 border-slate-200 dark:border-slate-700` running from dot bottom to next dot top, `ml-[5px]` offset (centers the 2px line under the 10px dot)

### Entry spacing

- Between entries: `py-4` each entry, connector line fills the gap
- Icon: `h-4 w-4` lucide icon, same color as dot, placed 8px right of dot
- Content block: starts 12px right of icon

### Icon mapping per tipo

| tipo | Icon | Dot color |
|------|------|-----------|
| `movimentacao` | `FileText` | `bg-emerald-500` |
| `transicao` | `GitBranch` or `ArrowRightLeft` | `bg-blue-600` |
| `evento` | `Calendar` | `bg-amber-500` |
| `documento` | `Paperclip` | `bg-slate-400` |
| `decisao` | `ShieldCheck` | `bg-purple-500` |

All icons from `lucide-react`.

### Loading state

Skeleton: 3 placeholder entries, each a `bg-slate-100 dark:bg-slate-800 rounded animate-pulse` block — `h-4` for title line, `h-3` for meta line, 24px vertical gap between them. No spinner.

### Empty state

Heading: "Sem entradas na timeline"
Body: "As movimentações, eventos e documentos do processo aparecem aqui assim que forem registados."
Layout: centered column, `py-12 text-center`, heading at `text-sm font-medium text-slate-500`, body at `text-xs text-slate-400`, no illustration.

### Error state

"Não foi possível carregar a timeline. Verifique a ligação e tente novamente."
Color: `text-red-600`. No retry button (user refreshes page or re-selects tab).

## Timeline Filter Bar Spec

Filters are applied client-side over already-loaded data (no re-fetch per filter change). State is local React state — no URL params.

### Filter 1: Type multiselect (chips)

Five toggle chips, one per event type: "Movimentações" | "Transições" | "Eventos" | "Documentos" | "Decisões"

Chip visual:
- Inactive: `variant="outline"` Button, `h-8 px-3 text-xs rounded-none`
- Active: `bg-slate-900 text-white dark:bg-slate-100 dark:text-slate-900 rounded-none h-8 px-3 text-xs` (inverse of background — reuses existing secondary pattern)
- Default: all types selected (show all)

### Filter 2: Date range

Two `Input` fields side by side — `type="date"`, `h-8 text-xs rounded-none border-slate-300 dark:border-slate-700`
Labels: "De" / "Até" — `text-xs text-slate-500 mb-1`
Default: empty (no date filter applied)

### Filter bar layout

```
[Filtrar por tipo: chip chip chip chip chip]   [De: input] [Até: input]   [Limpar filtros — ghost button]
```

Horizontal flex row, `gap-2 flex-wrap items-end`. Responsive: wraps naturally at narrow widths.

## Auditoria Tab Spec

Only visible to `canManageProcessos === true`. Tab button absent for others.

### Entry structure (table-like, not dot-and-line)

Rendered as a plain list inside a Card. Each entry row:

```
[timestamp — text-xs text-slate-500 w-36 shrink-0]  [acao badge]  [entidade_tipo — text-xs text-slate-500]  [entidade_id truncated — text-xs text-slate-400 font-mono]  [autor_nome — text-xs text-slate-600 dark:text-slate-300]
```

Row layout: `flex items-center gap-3 py-2 border-b border-slate-100 dark:border-slate-800`

### Acao badge variants

| acao value | Badge variant |
|------------|---------------|
| `transicao_estado` | `blue` |
| `conflict_check_decisao` | `purple` |
| `documento_download` | `secondary` |
| `documento_eliminacao` | `red` |

All use `rounded-none font-bold tracking-wide text-[11px]` to match existing badge overrides in the app.

### Loading state

"A carregar auditoria..." — `text-sm text-slate-500 dark:text-slate-400 py-4`

### Empty state

Heading: "Sem registos de auditoria"
Body: "Os eventos sensíveis do processo (transições, decisões, downloads e eliminações) ficam registados aqui."
Layout: same pattern as Timeline empty state.

### Error state

"Erro ao carregar a auditoria. Tente novamente."
Color: `text-red-600 text-sm py-4`

## Accessibility Contract

- Timeline dot + icon: each entry must have `aria-label` on the icon wrapper identifying event type and timestamp (e.g. `aria-label="Movimentação em 12/06/2026"`)
- Filter chips: use `role="button"` or `<button>` (not `<div>`); active state indicated by both color and `aria-pressed={true}`
- Date inputs: linked to labels via `htmlFor`/`id`
- Auditoria tab button: hidden from DOM (not just visually hidden) when user lacks `processos:manage` — no `aria-hidden` needed since element is absent
