<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → /processos/{id}/timeline | processoId in path; tenant-scoped user making a view request |
| Client → /processos/{id}/audit | processoId in path; only processos:manage users reach this endpoint |
| Internal → audit save calls | Author identity resolved from UserPrincipal (server-side), never from request payload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Information Disclosure | GET /processos/{id}/audit | mitigate | @PreAuthorize("hasAuthority('processos:manage')") at method level; frontend tab visibility is UX-only |
| T-34-02 | Information Disclosure / IDOR | GET /processos/{id}/timeline and /audit | mitigate | processo.getTenantId().equals(getTenantId()) tenant guard before any data is returned — same pattern as all processo sub-resource endpoints |
| T-34-03 | Repudiation | Audit records for downloadDocumento/deleteDocumento | mitigate | auditLogRepository.save() placed before the response return or repository.delete() so the record is written even if a downstream exception occurs |
| T-34-04 | Tampering | autor_id on Movimentacao | mitigate | autorId resolved exclusively from UserPrincipal (SecurityContext) — never accepted from request payload; client cannot forge authorship |
| T-34-05 | Information Disclosure | Timeline endpoint returning AuditLog entries | mitigate | getTimeline() only aggregates Movimentacao, Evento, Documento, ConflictCheckDecisao — it never queries auditLogRepository; audit data is exclusively in /audit |
| T-34-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase; zero supply-chain risk |
</threat_model>
