# Phase 134 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope (5 surfaces, no new visual language, same conventions as `133-UI-SPEC.md`):

1. Payment form in `web/src/app/(dashboard)/financeiro/[id]/page.tsx`: retention + mandatory método (only when faturação is active), confirmation dialog with backend-computed preview, inline 409/422 errors.
2. Column "Documento fiscal" in the honorário payments list.
3. New list page `web/src/app/(dashboard)/financeiro/documentos-fiscais/page.tsx` (+ `columns.tsx`), using the shared `DataTable`.
4. New detail page `web/src/app/(dashboard)/financeiro/documentos-fiscais/[id]/page.tsx`.
5. 409 delete-guard messages (pagamento, cliente, processo, honorário).

Hooks: extend `web/src/hooks/use-faturacao.ts` (`usePreVisualizacaoFaturacao`, `useDocumentosFiscais`, `useDocumentoFiscal`); `useCreatePagamento` gains `retencaoPercentagem`, `chaveIdempotencia`. Types in `web/src/types/financeiro.ts` (or `faturacao.ts`). Sources: 134-CONTEXT.md (locked), 133-UI-SPEC.md, REQUIREMENTS EMIS-01..12, existing `financeiro/[id]/page.tsx` and `financeiro/page.tsx`.

Principle ("frontend burro"): the frontend NEVER computes base, IVA, retenção, total or líquido. It only renders values returned by `POST /api/v1/faturacao/pre-visualizacao` and by the document endpoints. Money formatting only (Intl pt-CV, CVE).

## Surface 1 — Payment form (`financeiro/[id]/page.tsx`)

Faturação state comes from the existing config hook (`useConfiguracaoFiscal`, Phase 133). Loading state of that query: treat as faturação off visually but keep the submit button disabled until resolved (avoids wrong path).

Faturação OFF: form, button label "Registar pagamento" (existing label stays verbatim), toast and behavior unchanged (CFG-03). No retention field, método stays optional as today.

Faturação ON, additions inside the existing form grid (`grid gap-4 sm:grid-cols-2`):

| Field | Control | Rules |
|-------|---------|-------|
| Valor pago | existing | unchanged; helper `text-xs text-slate-500`: "Valor com IVA incluído." |
| Data do pagamento | existing `DatePickerField`, default today (Cape Verde), helper: "Com a faturação ativa, a data tem de ser a de hoje." | omitted value is allowed (backend assumes hoje); picking another date shows inline 422 on submit, not client block |
| Método de pagamento | existing select; label gains " *" ; required | zod: required only when faturação active; error "Escolha o método de pagamento." |
| Retenção | `Checkbox` + Label "Aplicar retenção na fonte" (`sm:col-span-2`) | default unchecked |
| Taxa de retenção (%) | `Input` inputMode decimal, w-full, visible only when checkbox checked, prefilled with `RETENCAO_SUGERIDA` (20) from fiscal parameters | 0 < taxa <= 100; error "A taxa de retenção deve ser superior a 0 e não superior a 100."; helper `text-xs`: "Calculada sobre o valor sem IVA." |

Submit: button "Registar pagamento" runs zod validation, then (faturação ON) calls the pre-visualização endpoint and opens the preview dialog. Button shows "A calcular..." and is disabled while the preview request is pending. If preview returns a refusal (422), no dialog opens: inline error is shown (see Errors) and focus moves to the offending field or the error banner.

`chaveIdempotencia`: generated with `crypto.randomUUID()` when the dialog opens; regenerated whenever the dialog is closed and reopened or the form values change; kept stable across retries within the same open dialog (network failure retry reuses the same key).

### Preview dialog (`Dialog`, not AlertDialog; contains a real form action, 133 used AlertDialog for pure confirmations)

Title: "Confirmar fatura-recibo". Description (`text-sm text-slate-500`): "Confira os dados do documento antes de emitir. Depois de emitido, não pode ser alterado nem apagado."

Order of content:
1. Simulation notice (neutral notice classes): "Documento simulado: não tem validade fiscal. Continue a emitir as suas faturas válidas no software de faturação homologado."
2. Adquirente block (`bg-slate-50`): Nome, NIF (`font-mono`), Morada (read from backend preview).
3. Linha: descrição controlada returned by backend ("Honorários por serviços jurídicos — Processo n.º {numero}").
4. Valores `dl` (labels left 400, values right `tabular-nums`):
   - "Base tributável"
   - "IVA ({taxa}%)" — OR, if regime isento: "IVA" value "Isento" and one row "Motivo de isenção" with `{código} — {rótulo}` returned by backend
   - "Retenção na fonte ({taxa}%)" row only if retenção applied (shown as returned, e.g. "- 20 869,57 CVE" formatted with minus by formatter only)
   - Separator
   - "Total" (600) — focal row
   - "Líquido recebido" (600) — focal row
   - helper `text-xs text-slate-500` under totals: "A conta corrente do cliente é creditada do total."
5. Método de pagamento and Data (read-only line).

Footer: "Voltar e editar" (outline, closes dialog, keeps form values) + "Emitir fatura-recibo" (primary). While emitting: both disabled, confirm label "A emitir...", Escape/overlay close blocked. Success: dialog closes, form resets, toast "Pagamento registado e fatura-recibo {número} emitida." Dialog stays open on network failure with banner "Não foi possível emitir a fatura-recibo. Verifique a ligação e tente novamente." (retry reuses same chave). Dismiss labels are contextual: the close "X" has `sr-only` "Fechar pré-visualização".

Loading preview: Skeleton rows are not needed (dialog opens only after response). Preview error: inline banner in the form Card.

### Inline errors (form Card banner `role="alert"`, `text-sm text-red-600`, above the footer; field-level ones `text-xs text-red-600` under the field)

| Code / status | Behavior | Copy |
|---------------|----------|------|
| 422 `DATA_PAGAMENTO_RETROATIVA` | field error under Data do pagamento + focus | "Com a faturação ativa, a data do pagamento tem de ser a de hoje. Escolha a data de hoje ou deixe o campo vazio." |
| 422 adquirente incompleto, `campo`=nif | banner with link to cliente | "O cliente não tem um NIF válido. Corrija o NIF do cliente (9 dígitos, começa por 1 a 9) e tente de novo." |
| 422 `campo`=nome | idem | "O nome do cliente deve ter entre 3 e 150 caracteres. Corrija o cliente e tente de novo." |
| 422 `campo`=morada | idem | "A morada do cliente é obrigatória e não pode ter mais de 100 caracteres. Corrija o cliente e tente de novo." |
| 409 `CHAVE_REUTILIZADA` | dialog closes, banner, new key will be generated | "Este pedido já foi usado com valores diferentes. Reveja os dados e registe o pagamento de novo." |
| 422 retenção/método inválidos | field error on the field named in `campo` | message from backend `message`, fallback "Verifique os campos assinalados." |

Banner for adquirente errors includes a link "Abrir cliente" (`/clientes/{id}`, accent link style, text-sm). 401/403 and other errors: existing `apiFetch` toast behavior (no duplicate inline). Mapping uses `ApiError` `{message, code, campo}` and `semToastParaStatus` (409/422 handled inline, no toast, same as 133).

## Accessibility and Responsive

- All controls have a `Label`; errors linked with `aria-describedby`, inputs `aria-invalid`; banners `role="alert"`; dialogs are Radix (focus trap, Esc closes unless emitting, focus returns to "Registar pagamento").
- Opening the preview dialog focuses the dialog title; confirm button is not auto-focused (avoid accidental Enter emission); "Voltar e editar" is first in tab order.
- Double-click safety: confirm disabled immediately on first click (plus idempotency key).
- Touch targets >= 40px; tables in `overflow-x-auto`; filters collapse to one column below 640px; preview dialog scrolls (`max-h-[85vh] overflow-y-auto`).
- Dark mode: all classes paired with `dark:` variants.

## Checker clarifications (2026-10-04, applied by orchestrator)

- Surface 2: for a faturado payment the delete button is HIDDEN (not rendered) and replaced by the explanatory text line; there is no disabled button.
- Surface 2: the "Documento fiscal" column is kept at all widths; the table wrapper scrolls horizontally.
- Detail page: the "Pendente" badge uses helper text (no tooltip) — no new component needed.
- List page: the "Ambiente" column is hidden below `md` via view-options defaults; the detail page badge row is always visible.
- Idempotency key lifecycle (revised after code review CR-02, supersedes earlier wording): the key belongs to the request content, not the dialog. It survives closing/reopening after an ambiguous failure (network, 5xx, 401/403/408/429) and is reused for the same payload; it is discarded only after success, a definitive backend 4xx, or a change in the payload.
