# Phase 137 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope (NO new visual language: every token, class, badge rule, notice block, dialog pattern, inline-error convention and exact-permission gate is inherited verbatim from `136-UI-SPEC.md`, including its "Checker clarifications", which in turn inherit 134/135):

1. Document detail (`web/src/app/(dashboard)/financeiro/documentos-fiscais/[id]/page.tsx`): "Descarregar PDF" / "Descarregar XML" buttons and new Card "Entrega por email" (six states, attempts, last error, exact-`financeiro:edit` resend + confirm dialog).
2. Documents list (`.../documentos-fiscais/page.tsx` + `columns.tsx`): new "Email" state column and per-row PDF/XML download actions.
3. Client page (`web/src/app/(dashboard)/clientes/[id]/page.tsx`): new tab "Documentos fiscais", read/download only.
4. Financeiro (`web/src/app/(dashboard)/financeiro/page.tsx`): "Exportar mês" button + month dialog producing the accountant CSV.
5. In-app notification `EMAIL_FISCAL_FALHOU` (non-silenceable).
6. Server-rendered artefacts: the A4 PDF template (OpenHTMLtoPDF) and the email subject/body.
7. Settings copy touch-up (`web/src/app/(dashboard)/settings/faturacao-email-card.tsx`): the "envio real ... numa versão futura" helper becomes false in this phase and is replaced.

Sources: 137-CONTEXT.md (locked), 136-UI-SPEC.md (precedent), REQUIREMENTS ENTR-01..07, RELF-01, DFE-06; codebase scan (existing `ComunicacaoEstadoBadge`, `ModoSimuladoBanner`, `comunicacao-fiscal-card.tsx`, `reprocessar-comunicacao.tsx`, `lib/comunicacao-fiscal.ts`, `lib/notificacao-categoria.ts`, `use-faturacao.ts` exact gates).

Principle ("frontend burro", unchanged): the frontend NEVER derives the delivery state, recipient, attempts, resend eligibility, file names or CSV content. It renders backend values. Allowed client logic: formatting (Intl pt-CV, `dd/MM/yyyy HH:mm`, `Atlantic/Cape_Verde`), mapping `estado` -> label/variant/icon/long description through ONE module-level `Record<EstadoEntregaEmail, ...>` in a new `web/src/lib/entrega-email.ts` (mirror of `lib/comunicacao-fiscal.ts`), the exact-permission gates, and triggering browser downloads.

Types/hooks (planner may rename, shape is the contract):
- `EstadoEntregaEmail = "NAO_CONFIGURADO" | "DESLIGADO" | "SEM_EMAIL" | "PENDENTE" | "ENVIADO" | "FALHOU"`.
- On `DocumentoFiscalDetalhe`: `entregaEmail: { estado, destinatario, emailDestinatario, tentativas, ultimaTentativaEm, proximaTentativaEm, enviadoEm, ultimoErro, reenviavel } | null`. `emailDestinatario` = client's current record email (used by the SEM_EMAIL send dialog; null when none). `reenviavel` is computed by the backend (true only when estado ∈ {FALHOU, ENVIADO, SEM_EMAIL} AND SMTP is configured AND the automatic toggle is on AND the communication is `ACEITE_SIMULADO`); `DESLIGADO`, `NAO_CONFIGURADO` and `PENDENTE` are never resendable.
- On `DocumentoFiscalResumo` (mandatory field, backend must add it): `estadoEntregaEmail: EstadoEntregaEmail | null` (null only when no delivery record exists).
- Hooks in `use-faturacao.ts`: `useReenviarEmail(documentoId)` (POST), `useDescarregarPdf()`, `useDescarregarXml()`, `useExportarMesCsv()`; gate helper `podeReenviarEmail(permissions)` = exact `hasPermission(perms, "financeiro:edit")` (NEVER `hasScopedPermission`), with a unit test mirroring `podeReprocessarComunicacao`. All read/download/export gates use the existing exact `podeLerDocumentosFiscais` (`financeiro:view`).

## Surface 1 — Document detail

### 1a. Download buttons (ENTR-02)
- Location: the header action group (right of the número/badges block, `flex flex-wrap gap-2`, wraps below the title on < 640px). Order: "Descarregar PDF", "Descarregar XML", then the existing "Emitir Nota de Crédito" (unchanged, when shown).
- Rendered for every FR and NC whenever `podeLerDocumentosFiscais` is true (the page is already gated on it). No disabled state for "not generated yet": the backend generates on demand.
- Buttons: `Button variant="outline"`, lucide `FileDown` (PDF) / `FileCode` (XML) 16px `aria-hidden`, labels "Descarregar PDF" / "Descarregar XML".
- Mechanism:
  - PDF: `apiFetch` GET (e.g. `/faturacao/documentos/{id}/pdf`) returns `{ url, nomeFicheiro }` (presigned MinIO URL, generated on demand if missing); the frontend then calls `window.location.assign(url)`. The frontend never builds the MinIO URL.
  - XML: `apiFetch` GET (e.g. `/faturacao/documentos/{id}/xml`) returns the file; trigger the download through a Blob + object URL (same technique as the honorários CSV), file name from `Content-Disposition` (backend: série/número, e.g. `FR-2026-A-000123.xml`), fallback `{numeroFormatado}.xml` with `/` and spaces replaced by `-`.
- Pending: the clicked button shows `Loader2` spinning 16px + "A preparar PDF..." / "A preparar XML..." and is disabled; the other download button stays enabled. Double-click safe (disabled on first click).
- Errors (no dialog here, so toasts; call with `semToastParaStatus` for these statuses to avoid the generic `apiFetch` toast duplicating):

| Status | Copy (toast.error) |
|--------|--------------------|
| 404 | Documento fiscal não encontrado. |
| 503 (storage/PDF generation unavailable) | Não foi possível preparar o ficheiro neste momento. Aguarde um momento e tente novamente. |
| Network / other 5xx | Não foi possível descarregar o ficheiro. Verifique a ligação e tente novamente. |
| 401/403 | existing `apiFetch` behaviour |

No success toast (the browser download is the feedback).

### 1b. Card "Entrega por email" (ENTR-03..06)
Placed immediately after "Comunicação fiscal" and before "Ligações". Rendered for every FR and NC. Same structure/classes as `comunicacao-fiscal-card.tsx`: CardHeader row = CardTitle "Entrega por email" (`text-xl font-semibold`, `tabIndex={-1}` ref for focus return) + right-aligned trigger when allowed (wraps below on mobile).

Content `dl` (`grid grid-cols-1 gap-2 text-sm sm:grid-cols-[1fr_auto]`, values `sm:text-right`):

| Row | Shown when | Value |
|-----|------------|-------|
| "Estado" | always | `EntregaEmailBadge` + long description below (`text-xs text-slate-500 dark:text-slate-400`) |
| "Destinatário" | `destinatario` present | email, `text-sm break-all` |
| "Tentativas" | estado ∈ {PENDENTE, ENVIADO, FALHOU} | `{n}` `tabular-nums`; helper `text-xs`: "O envio é tentado automaticamente até 5 vezes." |
| "Enviado em" | estado = ENVIADO and `enviadoEm` | `dd/MM/yyyy HH:mm` |
| "Última tentativa" | estado ∈ {PENDENTE, FALHOU} | `dd/MM/yyyy HH:mm` or "Ainda sem tentativas" |
| "Próxima tentativa" | estado = PENDENTE and `proximaTentativaEm` | `dd/MM/yyyy HH:mm` |

For `NAO_CONFIGURADO`, `DESLIGADO` and `SEM_EMAIL` only "Estado" (+ "Destinatário" if the backend sends it, never for SEM_EMAIL) is shown: no attempts rows (no attempts exist).

Last-error block (only when `ultimoErro` present and estado ∈ {FALHOU, PENDENTE}): identical to 136 — neutral notice classes, `role="status"`, lead "Última falha" (600), backend-sanitised text as plain text, `break-words whitespace-pre-line line-clamp-3`. Never HTML, never SMTP transcripts, never red.

`entregaEmail` null (document issued before this phase, or not yet registered): `text-sm text-slate-500 dark:text-slate-400` "O envio por email deste documento ainda não foi registado." and no trigger.

Loading: Skeleton Card (inside the existing `CarregandoDocumento`, add one more Card skeleton). Polling: extend the 136 rule — `refetchInterval: 15000` while `comunicacao.estado === "PENDENTE"` OR `entregaEmail.estado === "PENDENTE"`, `refetchIntervalInBackground: false`; no toast/announcement on automatic changes.

### 1c. Resend trigger (exact gate, both layers)
Rendered only when `podeReenviarEmail(permissions)` (exact `financeiro:edit`) AND `entregaEmail.reenviavel === true`. Otherwise NOT rendered (no disabled button, no tooltip). Backend: `@PreAuthorize("hasAuthority('financeiro:edit')")`, audited, resets attempts and opens a new failure episode.

Trigger: `Button variant="outline"`, lucide `Send` 16px `aria-hidden`. Label via a `Record` in `lib/entrega-email.ts`: FALHOU / ENVIADO -> "Reenviar email"; SEM_EMAIL -> "Enviar email".

### 1d. Resend confirm dialog (`Dialog`, single step, same pattern as `reprocessar-comunicacao.tsx`)
- Title: "Reenviar email" (or "Enviar email" for SEM_EMAIL).
- Description (`text-sm text-slate-500`): "O documento será enviado ao cliente com o PDF e o XML em anexo. O envio é feito em segundo plano e o documento não é alterado."
- Context block (`bg-slate-50 dark:bg-slate-900 rounded-md p-4`, `dl`): "Documento" número (`font-mono`), "Destinatário" (`entregaEmail.destinatario`, `break-all`; for SEM_EMAIL the backend returns the client's CURRENT record email in `entregaEmail.emailDestinatario` and the row shows it, or `text-sm text-slate-600 dark:text-slate-400` "O cliente não tem email na ficha" when absent), "Estado atual" `EntregaEmailBadge`, "Tentativas" count.
- Helpers (`text-xs text-slate-600 dark:text-slate-400`): "O contador de tentativas volta a zero." For ENVIADO add: "Este documento já foi enviado. O cliente vai receber um novo email." For SEM_EMAIL add: "Será usado o email registado agora na ficha do cliente." (SEM_EMAIL is only `reenviavel` when `emailDestinatario` is present — the backend sets `reenviavel = false` while the client still has no email, so this dialog never opens in that state)
- Error banner area `role="alert"`, `text-sm text-red-600 dark:text-red-400`.
- Footer: "Fechar sem reenviar" (outline; becomes "Fechar" after a definitive inline error) + primary "Reenviar email"/"Enviar email". Pending: "A reenviar..." / "A enviar...", both buttons disabled, Esc/overlay blocked. Close X `sr-only`: "Fechar reenvio do email". On open focus goes to the dialog title (confirm not auto-focused).
- Success: close, invalidate document + list + client-tab queries, toast "Email colocado na fila de envio.", focus returns to the Card "Entrega por email" heading (keep the 136 IN-06 fix: dialog state lifted so the component does not unmount mid-close).

Inline errors (`ApiError {message, code, campo}`; 409/422/503 inline without toast):

| Code / status | Behavior | Copy |
|---------------|----------|------|
| 409 `ENTREGA_ESTADO_INVALIDO` (already pending/resent elsewhere) | banner; "Fechar"; document refetched | Este email já está a ser enviado. Atualizámos o estado; verifique antes de tentar de novo. |
| 422 `SEM_EMAIL_CLIENTE` | banner; "Fechar" | O cliente continua sem email registado. Adicione um email na ficha do cliente e tente de novo. |
| 422 `SMTP_NAO_CONFIGURADO` | banner; "Fechar"; document refetched | O servidor de email não está configurado nesta instalação. Peça ao administrador da instalação para configurar o servidor de email. |
| 422 `ENVIO_EMAIL_DESLIGADO` | banner; "Fechar"; document refetched | O envio automático por email está desligado nas definições de faturação. |
| 422 `COMUNICACAO_NAO_ACEITE` | banner; "Fechar" | O documento só pode ser enviado depois de aceite na comunicação. |
| 403 | existing `apiFetch` behaviour; dialog closes | existing copy |
| 404 | dialog closes; page shows existing not-found Empty | Documento fiscal não encontrado |
| 503 | banner; stays open; retry allowed | O serviço está temporariamente indisponível. Aguarde um momento e tente novamente. |
| Network / other 5xx | banner; stays open; retry allowed | Não foi possível reenviar o email. Verifique a ligação e tente novamente. |

## Surface 6 — Server-rendered artefacts

### 6a. PDF template (OpenHTMLtoPDF, ENTR-01, DFE-06)
Rendered only from the stored document snapshot. No external resources (no remote fonts/images/CSS; resolver refuses non-classpath URIs). No logo in this phase. No QR code and no barcode (a QR on a simulated document could read as fiscally valid).

Page and type tokens (print):

| Token | Value |
|-------|-------|
| Page | A4 portrait, `@page { size: A4; margin: 28mm 16mm 16mm 16mm; }` (28mm top holds the header band: 2mm grid exception justified by the running band height ~20mm + 8mm gap) |
| Small | 7.5pt regular / 1.4, `#4b5563` — labels, footer, notes, band line 2, IUD note; table header row uses 7.5pt bold |
| Body | 9pt regular / 1.4, `#111827` — block content, table cells |
| Heading | 11pt bold / 1.2 — section headings (sentence case), band line 1, emitente firma, totals block lines label "Total do documento"/"Total a crédito" and its value |
| Title | 16pt bold / 1.2 — document type ("Fatura-Recibo" / "Nota de Crédito") |
| Weights | 2 only: regular (400) and bold (700) |
| Watermark | 44pt bold is a decorative graphic, not part of the text scale |
| Codes (NIF, série/número, IUD) | DejaVu Sans Mono at the size of their role (9pt Body); IUD `word-break: break-all` |
| Spacing (2mm grid: 2/4/8mm) | 8mm between major blocks, 4mm between related blocks and as box padding, 2mm inside blocks and as table cell padding (`2mm` all sides). Rationale: a 2mm grid is the print analogue of the web 4px scale and keeps blocks aligned across pages |
| Lines/borders | 0.5pt `#d1d5db`; zebra rows none |
| Colour | greyscale only (prints cleanly on B/W); no blue, green or red anywhere |

Repeated on every page:
- Header band (running element in the top margin, full content width, `background: #e5e7eb; border: 0.75pt solid #6b7280; padding: 2mm 4mm; text-align: center`): line 1, Heading 11pt bold `#111827`: "SIMULAÇÃO — SEM VALIDADE FISCAL"; line 2, Small 7.5pt: "Documento emitido em ambiente de teste e comunicado a um serviço de simulação, não à administração fiscal (DNRE)."
- Diagonal watermark (`position: fixed`, centred on the page, `transform: rotate(-35deg)`, DejaVu Sans bold 44pt, `color: #9ca3af; opacity: 0.18`, behind content via `z-index: -1`): "SIMULAÇÃO — SEM VALIDADE FISCAL" (one line; if the renderer cannot fit it, break after the dash into two lines).
- Footer (bottom margin, 7.5pt `#4b5563`, `border-top: 0.5pt solid #d1d5db`): left "{tipo} {série}/{número} · Documento simulado, sem validade fiscal"; right "Página {counter(page)} de {counter(pages)}".

Body order:
1. Top row, two columns (60/40):
   - Left "Emitente": firma (Heading 11pt bold), NIF (mono), morada, localidade; "Regime de IVA: Normal | Isento".
   - Right document box (`border 0.75pt #6b7280; padding 4mm`): title "Fatura-Recibo" or "Nota de Crédito" (16pt bold); "Série" + "Número" (mono, e.g. `FR 2026A/000123` as stored in `numeroFormatado`); "Data de emissão" dd/mm/aaaa; "IUD" (mono, wrapping) with 7.5pt note below "Ambiente de teste — sem validade fiscal".
2. "Adquirente" block: nome; "NIF" (mono) or the text "Consumidor final" when the snapshot has no NIF; morada when present.
3. NC only, "Documento de origem" block: "Corrige a Fatura-Recibo {número da FR}" + "de {data da FR}"; "Motivo: {motivoRotulo}"; "Descrição: {motivoTexto}" when present.
4. Lines table (full width; header row `background #f3f4f6`, Small 7.5pt bold): "Descrição" (left) | "Base" | "Taxa IVA" | "IVA" | "Total" (numeric columns right-aligned, `white-space: nowrap`). Exempt line: "Taxa IVA" shows "Isento", "IVA" shows "{código}". `thead` repeats on page break; rows never split (`page-break-inside: avoid`).
5. Totals block (right-aligned, 45% width): "Base tributável"; "IVA ({taxa}%)" OR "IVA: isento"; "Retenção na fonte ({taxa}%)" as "- {valor}" only when > 0; separator; "Total do documento" Heading 11pt bold (other total lines Body 9pt). NC: same lines, title of the final line "Total a crédito"; amounts printed as stored (positive) — the document type conveys the credit.
6. Exemption statement (when isento, 7.5pt): "Motivo de isenção: {código} — {descrição}."
7. Closing note (7.5pt): "Processado por computador. Documento simulado para testes, sem validade fiscal; não substitui o documento emitido no software de faturação homologado."

Formats: money pt-CV, 2 decimals, decimal comma, narrow no-break space thousands separator, suffix " CVE" (e.g. `12 345,00 CVE`); dates dd/mm/aaaa; all text from the snapshot is HTML-escaped (no raw HTML injection from cliente/descrição fields). ## Accessibility and Responsive

- States conveyed by visible label + icon, never colour; badges have `title`; background polling not announced; notices `role="status"`, dialog banners `role="alert"`.
- Icon-only table buttons have explicit `aria-label` including the número, plus a Tooltip; spinner state keeps the `aria-label` and sets `aria-busy="true"`.
- Dialogs: Radix focus trap, Esc closes unless pending, focus return as specified, confirm not auto-focused; month input labelled and error linked via `aria-describedby`.
- Helpers on `bg-slate-50` use `text-slate-600 dark:text-slate-400`.
- Header action group and Card header wrap below 640px; `dl` stacks; tables in `overflow-x-auto`; emails/IUD `break-all`. Tab list already scrolls/wraps with the existing triggers.
- Dark mode: all web classes paired with `dark:`. PDF/email are light-only by design.
- PDF: embedded fonts so PT accents (ç, ã, õ, é, ê, —) render; the PDF has a document title metadata "{tipo} {número} — Simulação sem validade fiscal" and `lang="pt-CV"` on the HTML root.
